# 前端重设计 demo

针对《现代高质感 SaaS 与企业级界面 UI/UX 设计趋势与架构范式研究报告》做的一次完整重新设计。

**这是一个独立静态原型，不改动 `web/` 下任何一行现有代码。**

```bash
python3 -m http.server 4187 --directory demo
```

然后打开 <http://localhost:4187/index.html>。无构建、无依赖、无后端。

## 1. 两套视觉主张，为什么并排而不是二选一

报告推荐 Dark-First + Bento + 玻璃拟物 + 环境光晕。现有 `DESIGN.md` 写的是"克制即工程"
"无彩底色""交互只改颜色"。这两者不是同一套审美的深浅差别，而是两种不同的产品立场。
与其替你们选，不如把两条路都做出来放在一起看。

两个维度是**正交**的，在语义令牌层分岔，原语层与组件层完全共用：

```
data-theme = light | dark
data-skin  = restrained | expressive
```

| | A · 克制版 | B · 高质感版 |
|---|---|---|
| 基底 | 中性黑 `#0b0b0c` / 纯白 | 冷调黑 `#08090c` / `#fafafb` |
| 强调色 | 主操作近黑/近白，蓝色仅表示"可交互" | 靛青 `#4f46e5` / `#818cf8` |
| 圆角 | 控件 6 / 卡片 8 | 控件 8 / 卡片 12 |
| 深度 | 环形阴影，几乎不可见 | 环形 + 递进投影 |
| 光晕 | 无 | 极弱，仅 Hero 单元格右上角与焦点环 |
| 字距 | −0.01 / −0.03em | −0.015 / −0.035em |

**换风格不需要改一行组件代码**——这是三层令牌结构的实际收益，也是这套 demo 想证明的
第一件事。

## 2. 对报告的逐条取舍

### 2.1 采纳的九项

| 报告主张 | demo 里的落点 |
|---|---|
| Bento 按空间权重传达优先级（§2.1） | `home.html` 的 12 栏网格；Hero 6×2，Feature 4，Metric 3，Accent 2 |
| ⌘K 作为操作枢纽，含动态操作执行器（§2.2） | `app.js` 的命令面板：跳转 / 操作 / 实体三类条目并存，筛选命令直接改当前页状态而不跳转 |
| 键盘优先与清晰焦点（§2.2） | g 前缀序列、`↑↓↵Esc`、面板内 Tab 拦截、**双环焦点**（修掉了现有系统单环在深色面板上不可见的问题） |
| 暗色分层与物理深度（§2.3） | 非纯黑基底 + 四级表面叠层 + 1px 半透明发丝边 |

| 角色导向情境化分层（§5.2A） | `home.html` 的三种角色布局，同一批瓦片按责任重排空间权重 |
| 乐观 UI 消解阻断感（§2.2） | 行内编辑与任务操作先落界面、后台确认，同步中用左侧竖条标记未确认 |

### 2.2 拒绝或改写的四项

**① 玻璃拟物（Glassmorphism）不用于数据卡片。**
`backdrop-filter` 让背后内容的高频细节透过来，正好落在数字最需要清晰边缘的地方；
它还是移动端最常见的合成层性能陷阱。demo 里只在**命令面板与抽屉遮罩**上用——
它们是短暂浮层，不承载需要精读的数值。

**② 品牌色弥散光晕不覆盖任何数值区域。**
报告把光晕当质感手段，这在营销页成立。在这个产品里，彩色是**信息**：红色意味着异常，
黄色意味着证据不足。如果背景本身就在发紫光，红色异常点的语义强度就被稀释了。
`expressive` 皮肤保留了光晕，但限制在 Hero 单元格右上角的空白区与焦点环，
`--hero-accent-wash` 在 `restrained` 下直接是 `transparent`。

**③ Dark-First 作为默认，改为明暗等权、跟随系统。**
报告的 Dark-First 结论来自开发者工具的用户画像。本产品的高频用户里有相当一部分是
会计与审计——他们在明亮办公室工作、要打印、要对着纸质凭证核对。
深色被做成**一等公民**（这是相对现状的净增量，现有系统完全没有暗色模式），
但不做默认。

**④ Tremor / Recharts 这类图表库不用。**
两个具体原因，都不是"不想用库"：

- Tremor 的默认配色是一条多彩序列，直接违反本产品"多序列优先用灰度深浅 + 形状区分，
  确需多色不超过 3 色"的规则。要改配色就得覆盖它的内部类名——那正是现有
  `globals.css` 里 91 处 `.ant-` 覆盖的成因，等于把同一个坑再挖一遍。
- 多数图表库默认 `connectNulls`，或把 `null` 当 0 处理。这两种行为在本产品里都是错的：
  0 和"没有数据"是两件事。`charts.js` 的折线遇到缺口**断开并画出底纹区间**
  （见 `pulse.html` 的 08-12 / 08-13）。

自建的图形只有四种（折线 / 横向条 / 贡献桥 / 分位条），成本低于驯服一个库的成本。

### 2.3 报告的盲区：数据可信度

**这是本次重设计里最重要的一条，也是报告完全没有覆盖的一条。**

报告默认"界面呈现的就是事实"，因此它的全部篇幅都在讨论如何把事实呈现得更好看、更快、
更易操作。这个默认在通用 SaaS 里成立，在这个产品里不成立：

- 数据分成 `production` 与 `simulated`，模拟数据永远不能冒充正式数据；
- 事实有版本，重述会加版本而不是覆盖；
- 覆盖率不足时，指标仍然可看，但**必须**被标记为不足以支撑决策；
- 多来源冲突时拒绝猜测，而不是取一个平均值；
- 权限拒绝要如实显示，不能软化成"暂无数据"。

所以 demo 把 `DataTrustBar` 提到了**每一个经营数据页的第一屏、标题正下方**，
并且遵守三条硬规则：

1. `decision_ready = false` 时**整条降级变色**，且所有 KPI 加统一角标——
   这个判定不能藏在第五个 span 里。
2. 覆盖不足**显示 `—` 并说明原因**，不用 0 补齐。
3. 被抑制的门店单独成表，明写"证据不足，不是表现正常"。抑制永远不是静默的。

同一条原则也贯穿别处：`store360.html` 的贡献桥保留 +8,000 的**未配平残差**，
而不是加一个配平项把它抹平——配平项会让下一个人误以为分解是精确的。

> 一个看起来很高级、但没说清覆盖率只有 88% 的仪表盘，比一个朴素、但标了
> "不足以支撑决策"的仪表盘危险得多。

## 3. 相对现有前端的结构性差异

现有 `web/` 的已知债务（数字取自 `DESIGN.md` §14）：

| 项 | 现状 | demo |
|---|---|---|
| `globals.css` 行数 | 3666 | 三个文件合计约 1400，且分层明确 |
| `!important` | 142 处 | **4 处**，全部在 `prefers-reduced-motion` 块内（该场景必须用） |
| `.ant-` 覆盖 | 91 处 | 0（不依赖组件库，因此没有要覆盖的对象） |
| 内联 `style={{}}` | 906 处 | 仅动态值（进度条宽度、图表容器高度） |
| 字重 > 600 | 13 处 | 0（字重只有 400/500/600 三档） |
| `border: 1px solid` | 11 处 | 0（统一环形阴影） |
| 暗色模式 | 无 | 双主题，且是令牌层原生支持 |
| 焦点环 | 单环，深色面板上不可见 | 双环，任意底色可见 |

这些不是"写得更整齐"，而是同一件事的两面：**当颜色、间距、深度全部只能从语义令牌取值时，
"加一条 `!important` 把它压下去"这个动作就没有对象了。**

`web/` 的整改路径与本 demo 的关系：`assets/tokens.css` 的 L2 语义层可以整体移植回
`web/app/design-system/tokens.ts` + `globals.css` 的 `:root`，两边名字一一对应。
Bento、命令面板、可信度条三个组件可以独立移植，不依赖本 demo 的其余部分。

## 4. 已知边界

这是一个**设计原型**，不是可交付的实现。明确不在范围内的：

- 没有接后端。全部数据来自 `assets/data.js`，且全部标注为 `simulated`。
- 没有国际化。真实实现必须走 `t()` 并同时提供 `zh-CN` / `zh-HK` / `en`。
- 没有真实鉴权。角色切换只改布局，不改数据可见性。
- 高级筛选抽屉里的条件行是静态的，只演示交互形态。
- 自定义保存视图落库、命令面板的服务端搜索、AI 抽屉的真实流式输出均未实现。
- 可访问性做到了键盘可达、双环焦点、`aria` 标注、状态不单靠颜色；
  但没有跑过屏幕阅读器实测。

响应式已在 1440×900、1280×720、720 三档验证过；`prefers-reduced-motion` 全局生效。
