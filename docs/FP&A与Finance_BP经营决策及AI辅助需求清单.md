## 1. 文档目的

本清单用于把产品支撑做到**线下零售门店经营分析**所需的深度：以门店 store-day 经营事实为核心，把销售、毛利、客流、人工、占用成本与承租合同连接起来，服务零售 Finance BP 与集团 FP&A 的日常决策。

IFRS 16 计量与月结控制作为**已成熟的合规模块**继续维护，是入口与差异化数据来源，不是产品定位。

产品不以替代完整 ERP、POS 或集团 EPM 为目标，而是利用可信经营事实、租赁事实和确定性计算引擎，帮助 FP&A 与 Finance BP 完成以下闭环：

```text
发现偏差 → 核实数据 → 解释业务驱动 → 模拟可选动作
→ 形成建议 → 人工审批/业务确认 → 跟踪行动及收益兑现
```

## 2. 状态与优先级

### 2.1 状态

- `[x]`：当前系统已具备可用能力。
- `[~]`：已有部分能力或技术基础，但业务闭环不完整。
- `[ ]`：待设计或待实现。

### 2.2 优先级

- `P0`：可信性、权限、数据基础或经营闭环的必要能力。
- `P1`：最小可行 FP&A / Finance BP 产品能力。
- `P2`：零售行业深化能力。（原「零售与制造」中的制造部分已移出范围，见文首范围更新）
- `P3`：预测优化、自动监控和外部集成深化。

## 3. 产品边界与强制原则

### 3.1 产品定位

- [x] 将产品定位为“**线下零售门店经营分析工作站**”，而不是通用总账、通用 BI 或完整企业预算系统。IFRS 16 计量是其中的合规模块。
- [ ] 所有经营分析必须能下钻至合同、门店/资产、付款计划、事件、经营指标和数据版本。
- [ ] 所有建议必须最终落到可执行行动、责任人、截止日期和预期财务影响。
- [ ] 经营指标作为独立事实层接入，不直接污染或覆盖 IFRS 16 正式子账。

### 3.2 会计与内控原则

- [x] 会计引擎与业务录入分离，重大合同变化通过事件驱动重算。
- [x] Working 与 Official 数据和报表严格区分。
- [x] AI 运行在 Assist Mode，不能直接写入正式台账、正式预测、正式事件或正式分录。
- [x] 折现率缺失时必须人工确认，AI 不得猜测。
- [ ] AI 生成的解释、假设和建议必须标识为“AI 推断/建议”，不得冒充系统事实。
- [ ] 所有计算金额由确定性规则、版本化模型或受控分析服务产生；LLM 只负责理解问题、编排工具和组织语言。
- [ ] 对正式数据的每次查询、导出、解释确认和行动变更保留审计记录。

## 6. 统一经营驾驶舱

### FPA-001 本月经营结果总览（P1）

- [ ] 同时显示 Actual、Budget、Latest Forecast、Prior Year 和 Scenario。
- [ ] 支持法人、业务板块、品牌、区域、门店、工厂、资产类型和币种筛选。
- [ ] 显示利润、现金流、租赁成本、租赁承诺和关键经营指标的差异。
- [ ] 首页默认突出影响金额最大的异常，而不是只展示合同数量和审批状态。
- [ ] 每个指标显示来源、数据日期、版本、覆盖率、币种和 Working/Official 状态。
- [ ] 支持从集团汇总下钻至门店/工厂、合同、事件和原始证据。

验收标准：

- 用户能在三次点击内从集团红色指标定位到主要责任单位和支持证据。
- 汇总金额必须与明细勾稽；跨币种合并必须显示汇率版本。
- 数据覆盖不完整时不得显示为正常或零值，必须明确显示缺口。

### FPA-002 经营异常与行动中心（P0）

- [ ] 将月结异常、预算差异、租售比异常、关键日期、数据质量问题统一进入行动中心。
- [ ] 按影响金额、会计/经营风险、截止日期、重复发生率和可修复性排序。
- [ ] 支持责任人、协作人、截止日期、状态、根因、计划动作和预期收益。
- [ ] 支持批量分派、批量确认、批量导出和逾期升级。
- [ ] 区分系统确定性发现、AI 信号、人工结论和正式控制异常。
- [ ] 保存行动的基线值、目标值、实际兑现值和验证期间。

验收标准：

- 每个异常均能追溯到检测规则、数据版本和原始记录。
- AI Signal 不得自动变成 Control Conclusion。
- 已完成行动必须通过后续 Actual 验证，不能仅靠用户手工标记“完成”。

### FPA-003 管理层差异桥（P1）

- [~] 保留现有租赁成本 Budget / Forecast / Actual 差异桥。
- [ ] 扩展为经营驱动桥：销量、价格、组合、毛利率、租金、人工、材料、能源、效率和汇率。
- [ ] 支持集团、零售、制造三种原因字典，并保留无法自动归因的残差。
- [ ] 提供 Waterfall 数据、Top Contributors、解释覆盖率和待行动金额。
- [ ] 人工解释与自动归因分开存储，不允许人工覆盖确定性金额。

验收标准：

- 桥接总额始终勾稽至 Actual - Comparison Basis。
- 未解释差异必须可见，不得由 AI 编造归因。
- 原因字典和物料性阈值必须版本化。

## 7. 驱动式计划、预测与情景

### FPA-010 统一假设库（P1）

- [ ] 建立假设名称、适用范围、期间、数值、单位、来源、责任人和有效版本。
- [ ] 支持销售、毛利、租金、通胀、汇率、利率、人工、材料、能源、产能和 CAPEX 假设。
- [ ] 区分合同事实、系统政策、管理层假设和 AI 建议。
- [ ] 重大假设变更进入审核流程，不允许静默覆盖。
- [ ] 提供假设变化对 P&L、资产负债表、现金流及 KPI 的影响范围。

### FPA-011 滚动预测（P1）

- [~] 保留现有 Budget / Forecast / Scenario 版本生命周期。
- [ ] 支持月度或季度滚动 Forecast，保留原版本而不是覆盖。
- [ ] 支持 Actual 自动替换已发生期间，未来期间仍保留 Forecast。
- [ ] 支持业务负责人提交假设、Finance BP 复核、FP&A 固化版本。
- [ ] 追踪 Forecast Accuracy、Bias 和主要误差驱动。

### FPA-012 情景工作台（P1）

- [ ] 支持 Baseline、Upside、Downside 和用户自定义情景。
- [ ] 支持自然语言生成情景草稿，但必须展示结构化假设供人工确认。
- [ ] 同时输出 P&L、资产负债表、现金流、净负债和经营 KPI。
- [ ] 支持情景间比较、敏感性、盈亏平衡点及关键假设排序。
- [ ] 情景不得冒充 Budget、Forecast 或 Actual。

验收标准：

- 每个情景保存不可变输入快照、模型版本和运行时间。
- 相同输入和模型版本必须产生相同结果。
- 缺少关键假设时必须停止计算或明确排除，不得由 AI 猜测。

## 8. 零售 Finance BP 功能

### RTL-001 门店经营事实层（P1）

- [ ] 建立 `store × period` 经营事实，至少包含营收、毛利、交易数、客流、面积、人工和其他店铺费用。
- [ ] 支持 POS / ERP / BI 的 CSV、XLSX 导入和 API 接入。
- [ ] 支持门店别名映射、品牌/区域归属、财月口径、币种和数据版本治理。
- [ ] 显示数据来源、刷新时间、覆盖率和与总账/销售系统的对账状态。
- [ ] 经营事实更正保留版本和审计轨迹，不直接修改租赁合同。

### RTL-002 四墙损益（P1）

- [ ] 按门店展示营收、毛利、人工、固定租金、变量租金、非租赁费用和其他可控成本。
- [ ] 计算 Four-wall EBITDA、贡献利润、租售比、占用成本率、坪效和盈亏平衡销售额。
- [ ] 支持 Actual / Budget / Forecast / Prior Year 比较。
- [ ] 支持同店、新店爬坡、关闭门店和店龄 Cohort 分析。
- [ ] 提供门店排名、异常阈值、趋势和区域/品牌基准。

### RTL-003 续租、关店与搬店决策（P1）

- [x] 支持续租、重谈和终止的租赁现金流及会计影响比较。
- [ ] 加入销售、毛利、人工、搬迁 CAPEX、装修补贴、蚕食影响和停业损失。
- [ ] 支持续租、降租、缩店、搬店、关店至少五类情景。
- [ ] 计算 NPV、回收期、退出成本、盈亏平衡租金和目标谈判区间。
- [ ] 自动显示 break option、通知期限、续租窗口和需要业务确认的关键假设。
- [ ] 决策结果以草稿卡保存，经业务、Finance BP 和审批人确认后才创建正式租赁事件。

### RTL-004 促销与租金联动分析（P2）

- [ ] 支持促销增量销售、毛利侵蚀、供应商投入和促销 ROI。
- [ ] 对 turnover rent 单独显示销售增长带来的变量租金影响。
- [ ] 评估销售增长是否足以覆盖租金、人工和其他门店固定成本。
- [ ] 不将 sales-based variable rent 错误资本化进入租赁负债。

## 9. 制造 Finance BP 功能（⚠️ 不在当前范围，保留供将来评估）

### MFG-001 工厂与设备主数据关联（P2）

- [ ] 建立租赁合同与工厂、产线、设备、成本中心和资产编号的映射。
- [ ] 支持一份合同覆盖多台设备以及一台设备关联多个服务/租赁成分。
- [ ] 记录设备状态、额定产能、启用日期、使用地点、责任部门和关键维护周期。
- [ ] 设备迁移、停用、替换和范围变化必须通过事件或受控业务事件留痕。

### MFG-002 制造经营事实层（P2）

- [ ] 建立 `plant / line / equipment × period` 事实，包含产量、良率、废品、停机、OEE、人工、能耗和利用率。
- [ ] 接入标准成本、实际成本、采购价格、材料耗用和制造费用吸收数据。
- [ ] 支持 ERP / MES / WMS / 维护系统的文件导入和 API 接入。
- [ ] 数据缺失时保留“未知”，不得按零处理。

### MFG-003 制造成本差异桥（P2）

- [ ] 展示采购价格差异、材料耗用差异、人工效率、良率/废品、能源和制造费用吸收差异。
- [ ] 识别产能下降导致的租赁刚性成本吸收不足。
- [ ] 支持按工厂、产线、产品和设备下钻。
- [ ] 将合同租金调整与生产经营差异分开归因。

### MFG-004 设备 Buy / Lease / Replace / Outsource 决策（P2）

- [ ] 比较购买、租赁、续租、替换和外包方案。
- [ ] 计入采购价、租金、维护、能源、残值、税务、停机、安装和退出成本。
- [ ] 计入产能、良率、效率和交付风险影响。
- [ ] 输出 NPV、IRR、回收期、单位产能成本、现金流和 IFRS 16 影响。
- [ ] 识别闲置、低利用率或临近到期的租赁设备，并生成重谈/退出候选清单。

验收标准：

- 经营结论和 IFRS 16 会计结论必须分别显示。
- 设备使用率或产能数据不完整时，不得自动给出“应终止租赁”的确定性结论。
- AI 只能提出候选方案，正式资产处置、合同变更和会计事件必须经人工审批。

## 11. AI Copilot 需求

### AI-001 每日经营简报（P1）

- [ ] 按用户权限和关注范围生成每日/每周简报。
- [ ] 内容包括重大偏差、现金流风险、租约关键日期、数据问题、逾期行动和待确认事项。
- [ ] 按影响金额和时效排序，并说明“为什么值得关注”。
- [ ] 每条结论附系统来源、数据日期和 Working/Official 状态。
- [ ] 无重大变化时明确说明，不制造虚假告警。

### AI-002 差异调查 Copilot（P0）

- [ ] 将现有预算差异、租售比、组合分析、现金流和事件查询开放为受控 Agent Read Tools。
- [ ] AI 能把用户问题拆成数据校验、差异桥、贡献者下钻和证据核实步骤。
- [ ] AI 生成管理层解释草稿，但金额和原因桥必须来自确定性服务。
- [ ] 对无法解释的金额输出“残差/证据不足”，不得自行补全原因。
- [ ] 用户确认解释后才保存为正式人工解释，并记录确认人和时间。

### AI-003 对话式情景建模（P1）

- [ ] AI 将自然语言转成结构化情景假设草稿。
- [ ] 在运行前展示假设、单位、范围、来源和缺失字段。
- [ ] 对折现率、汇率、销售增长、产能等重大假设执行 Human-in-the-loop。
- [ ] 调用确定性情景引擎，返回多方案对比和敏感性。
- [ ] 支持将结果保存为 Scenario 草稿；不得直接覆盖 Forecast 或 Budget。

示例问题：

- “华东区域本月租赁成本为什么比 Forecast 高？”
- “哪些门店未来六个月到期，但没有续租决定？”
- “如果销售下降 8%、租金上调 5%，哪些门店会跌破盈亏平衡？”
- “比较这两份房东报价，并给出目标谈判租金。”
- “如果两台设备由续租改为购买，未来三年现金和 EBITDA 如何变化？”

### AI-004 决策材料生成（P1）

- [ ] 基于已运行的确定性情景生成一页决策摘要。
- [ ] 自动列出最敏感假设、数据缺口、反对理由和需要业务确认的问题。
- [ ] 支持生成续租谈判提纲、关店说明、设备投资备忘录和管理层摘要。
- [ ] 不允许 AI 在没有对应模型结果时生成具体财务金额。

### AI-005 会议与行动辅助（P2）

- [ ] 基于系统数据生成 WBR / MBR / S&OP 会前材料和提问清单。
- [ ] 将会议纪要解析为行动草稿，提取责任人、期限、目标和预期影响。
- [ ] 创建或发送行动前必须由用户确认。
- [ ] 后续期间自动匹配 Actual，评估行动是否兑现。

### AI-006 主动监控（P2）

- [ ] 定期发现月结阻塞、数据质量下降、重大经营偏差和临近决策窗口。
- [ ] 将检测结果保存为 Agent Signal，不直接创建正式控制结论。
- [ ] 相同问题去重，保留首次发现、最近发现和重复次数。
- [ ] 支持阈值、静默期和升级规则，避免告警疲劳。

### AI-007 可解释性与安全控制（P0）

- [ ] 每次 AI 回答展示使用的工具、数据来源、查询范围和证据引用。
- [ ] 显示系统事实、确定性计算、人工输入和 AI 推断四类信息。
- [ ] 遵守法人、门店、区域、品牌和角色权限，不允许通过自然语言绕过数据范围。
- [ ] 写入类工具必须使用草稿、幂等键、Review Gate 和审计日志。
- [ ] 对 Prompt Injection、伪造文件指令和越权工具调用实施拒绝策略。
- [ ] 记录工具调用成功率、拒绝率、延迟、人工采纳率和错误原因。

## 12. Agent 工具需求

> ⚠️ **本节原有的勾选清单已于 2026-08-18 移除。**
>
> 那张表把大量**已经实现**的工具标成未实现（`lease.portfolio.summary`、`lease.cashflow.scenario`、`lease.predeal.simulate`、`lease.store.scenario.simulate`、各类 Draft 工具等在 `internal/agenttools/tools/` 中均已注册），是本仓库最典型的误导源之一——AI 协作者读到它会去重复实现已有能力。
>
> **工具的实现状态以代码为准**：`core-service/internal/agenttools/tools/` 是唯一事实来源，注册点见 `internal/aiagent/agent.go`。缺口的现行判断见 [AI 文档索引与现行决策](AI_文档索引与现行决策.md) §3。
>
> 本节保留下面的**分类与约束**，那部分仍然有效。

### 12.1 工具分级

| 级别 | 用途 | 约束 |
|---|---|---|
| **Read** | 读取权限范围内的事实：合同、计量、事件、分录、经营组合、门店表现、租售比、设备表现、关账准备度、预算差异 | 只读，不产生副作用 |
| **Simulation** | 签约报价比较、签约前经济性、续租方案、现金流情景、门店/设备经营方案 | **必须是无副作用的确定性计算**；结果为 Scenario，不改写 Forecast、合同或会计记录 |
| **Draft / Action** | 合同、付款计划、事件、差异解释、经营行动、Scenario、决策备忘录 | **必须经过 Review Gate**，带幂等键与审计留痕 |

### 12.2 不变的硬约束

- Simulation 类工具永远不写库；Draft 类工具永远只产草稿。
- 工具的权限、租户范围、幂等、复核、配额判定统一走中间件链，不散落在各工具实现里——见 [ADR-0019 Addendum A](adr/0019-agent-tool-runtime-policy-and-threat-model.md)。
- IFRS 16 计量类度量不得由沙箱等非确定性路径产生——见 [ADR-0025](adr/0025-separate-certified-engine-output-from-exploratory-analysis.md)。

## 13. 数据集成与语义层

### DATA-001 经营数据接入（P0/P1）

- [ ] 提供标准 CSV/XLSX 模板及字段校验报告。
- [ ] 建立 Source System、Import Batch、As-of Time、Version 和 Reconciliation Status。
- [ ] 支持错误行隔离、重试、重复检测和幂等导入。
- [ ] 原始文件、解析结果、人工修正和最终确认值均可追溯。

### DATA-002 主数据映射（P0）

- [ ] 建立法人、成本中心、门店、工厂、产线、设备、合同和 ERP 编码映射。
- [ ] 支持别名、有效日期和一对多关系。
- [ ] 未映射记录进入异常工作台，不静默丢弃。

### DATA-003 指标语义与治理（P0）

- [ ] 为租售比、占用成本率、Four-wall EBITDA、OEE、利用率等指标建立版本化定义。
- [ ] 指标定义包含公式、粒度、币种、期间、排除规则、责任人和生效时间。
- [ ] 前端和 AI 使用同一指标服务，不允许各自重复计算产生不同答案。

## 14. 权限、审批与审计

- [ ] 在现有六种角色基础上定义 FP&A、Retail BP、Manufacturing BP 的权限组合或数据范围。
- [ ] 数据权限扩展至工厂、产线和设备，同时保留法人、门店、区域和品牌范围。
- [ ] Budget、Forecast、Scenario、人工解释、行动和决策卡分别定义创建、复核、批准权限。
- [ ] Official Forecast 或决策结论固化后不可原地修改；变更必须创建新版本。
- [ ] 跨法人汇总允许查看汇总但不得泄露无权限明细。
- [ ] 所有导出保留用户、时间、数据版本、范围和用途标记。

## 15. 非功能需求

### 15.1 性能与可用性

- [ ] 驾驶舱常用查询在正常数据规模下目标响应时间不超过 3 秒。
- [ ] 长时间情景运行采用异步 Run，可查询进度、取消和恢复。
- [ ] 报告生成失败不得留下看似完整的 Official Artifact。

### 15.2 数据质量

- [ ] 所有核心经营事实提供完整率、及时率、对账状态和异常数量。
- [ ] 对零值、缺失值和不适用值使用不同状态。
- [ ] 跨币种、跨财月和跨组织范围比较必须经过显式口径校验。

### 15.3 可复演性

- [ ] 任一管理层数字能以相同数据版本、假设和模型版本重新生成。
- [ ] 任一 AI 结论能追溯到工具调用、输入、输出和引用来源。
- [ ] 模型或指标定义变更后，历史 Official 结果保持不变。

## 16. 产品指标

### 16.1 North Star Metric

- [ ] 从提出财务问题到获得“有证据、可解释、可执行结论”的中位时间。

### 16.2 效率与质量指标

- [ ] 月结周期和 Close Readiness 阻塞解决时间。
- [ ] 预算差异自动归因率和未解释差异金额占比。
- [ ] Forecast Accuracy、Forecast Bias 和版本提交及时率。
- [ ] AI 建议采纳率、人工修改率、无证据回答率和工具调用失败率。
- [ ] 续租/关店/设备决策周期及决策卡覆盖率。
- [ ] 行动按期完成率、预计收益和实际兑现收益。
- [ ] FP&A / Finance BP 周活、报告导出和下钻使用率。

## 17. 推荐实施顺序

### 第一阶段：连接已有能力，形成最小行动闭环（P0）

- [ ] 将预算差异、租售比、组合、现金流、Close Readiness 和续租决策开放为 Agent Read Tools。
- [ ] 建设统一经营异常与行动中心。
- [ ] 建立 AI 证据引用、事实/推断分层和经营指标语义治理。
- [ ] 复用现有差异责任人、截止日期和行动状态，避免重复任务模型。

### 第二阶段：零售 Finance BP 产品化（P1）

- [ ] 接入门店营收、毛利、面积、人工及其他费用。
- [ ] 建设四墙损益和门店经营驾驶舱。
- [ ] 完善续租、关店、搬店和房东报价决策工作流。
- [ ] 上线每日经营简报、差异调查和对话式情景建模。

### 第三阶段：制造 Finance BP 产品化（P2）

- [ ] 接入工厂、设备、产量、成本、OEE 和利用率数据。
- [ ] 建设制造成本桥和设备经济性工作台。
- [ ] 上线 Buy / Lease / Replace / Outsource 决策卡。

### 第四阶段：智能预测与主动监控（P3）

- [ ] 在数据覆盖、主数据和对账稳定后引入统计/机器学习预测。
- [ ] 上线异常主动发现、Forecast 风险预测和收益兑现验证。
- [ ] 完成真实 ERP、POS、MES 或 BI 系统联调。

## 18. 明确非目标

- [ ] 不在本阶段建设完整集团总账、供应链执行系统或全科目 EPM。
- [ ] 不让 LLM 直接计算会计金额、修改正式合同或自动过账。
- [ ] 不以无证据的“智能建议”替代业务负责人、Finance BP 或审批人的判断。
- [ ] 不在经营数据不完整时输出确定性的关店、续租或设备处置结论。
- [ ] 不因新增经营分析而削弱现有事件驱动、Working/Official、锁账和审计控制。

## 19. 外部依赖

- [ ] 第三方会计师完成 IFRS 16 回归标准答案复核和签字。
- [ ] 客户确认续租、关店、减值、CAM 拆分、turnover rent 和折现率政策。
- [ ] 选择真实 ERP 完成凭证及主数据映射联调。
- [ ] 选择真实 POS / BI 完成门店经营数据接入。
- [ ] 选择真实制造 ERP / MES 完成工厂和设备经营数据接入。
