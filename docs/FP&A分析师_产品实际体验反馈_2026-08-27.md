# FP&A Analyst 产品实际体验反馈（2026-08-27）

> 角色视角：线下连锁零售 FP&A。体验方式：真实浏览器走 UI（admin_user / password123，模拟数据集 SIM-2853D953-007，as-of 2026-06-05，14 天窗口）。未运行任何代码修复，只做了环境迁移补齐（见 §1）。

## 0. 一句话结论

**「经营分析」这半边（脉搏 / 门店 360 / 租金谈判 / AI 助手）已经像一个成熟产品，可以直接支撑 FP&A 的日常晨检与归因工作；「法人级 FP&A」这半边（单店利润表、三表模型、预算对比）在当前环境不可用或缺数据，尚不能承担月度预算/预测职责。**

## 1. 环境前提（很重要）

- 本轮从 `docker compose up -d` 冷启动本地环境。发现既有 DB 卷的 schema 停在迁移 059，而 HEAD 已到 064：`/ai-chat` 所有会话运行一律 500（`ERROR: column "data_classification" does not exist`，062 未应用）。
- 执行 `make migrate`（060–064 五个增量，事务式、仅补列/表、不动既有数据）后，AI 会话恢复。
- **教训：既有开发卷上 `docker compose up` 不会自动更新 schema，必须 `make migrate`。** 否则「打开即 500/页面异常」会被误判成产品缺陷。建议把 `make migrate` 纳入 `make up` 或 compose 的 healthcheck 前置。

## 3. 当前不可用 / 不满足（P0 类）

1. **`/store-pnl`（单店利润表）在模拟数据环境完全无法打开** —— 对 FP&A 这是核心交付物。
   - 门店下拉调 `operating-facts/stores`（`web/app/store-pnl/page.tsx:95`），后端查的是旧表 `store_operating_facts`（本环境 0 行），而演示数据在 `retail_store_day_facts`（60 店 × 181 天 = 10,860 行）。
   - 即使有门店，`getPnl`（`web/app/lib/api.ts:2097`）不传 `data_classification`/`dataset_version`，而后端默认 production（`core-service/internal/handlers/store_pnl.go:114`），返回 `retail store is not visible`。
   - 修复方向：门店列表走 `retail/store-options`，PnL 查询透传当前数据环境参数（与脉搏页一致）。
2. **`/financial-model`（三表模型）开箱不可运行** —— 无任何预置定义/模板/运行记录（`fin_model_*` 全 0）；页面如实标注「后端列表尚未开放」「期初自动取数尚未开放」「上传尚未开放」，当前只能手动粘贴定义 ID + 手填期初余额。对月度预算编制价值尚未兑现，且缺少「从空到有」的引导流程。
3. **`/reports` 预算对比、`/promotions`、版本对比/准确率** —— 均为空态：无合同（台账空）、无促销活动、BUDGET 版本只有表头（`fpna_plan_lines` 0 行）。功能界面在，链路缺数据。

## 4. 体验细节问题（P1/P2）

- AI Chat 首页（无页面上下文）直接问「哪些门店需要关注」会得到「请提供 as_of、window_days、data_classification…」——诚实但陡峭。普通用户不知道从「交给 AI 分析」按钮进入才能带上下文。建议：无上下文时尝试默认取最近一期演示/生产数据集，或给出引导文案。
- 经营脉搏「人时产出」「单均人时」的标签渲染成「人时产出 部分· 算这个指标要用的字段缺了…」——文案拼接怪异，疑似缺单位（元/人时）。门店 360 同样存在「销售人效/单均工时 — 同群样本不足」堆叠问题但更清晰。
- 经营脉搏页与经营驾驶舱的同一指标口径不同（页面自己标注「两页的数取自不同的后端」）——对单一数字有双源的用户是真实的混淆风险，建议标注更显眼或统一入口。
- 门店 360 页「返回经营脉搏」按钮实际链路 OK，但「情景分析」入口跳到 `scenario-workbench`？体验一致。

## 6. 专项研究：AI Chat 能否生成 FP&A 工作台的预算 draft（2026-08-27）

**结论：不能。** 三层证据如下。

1. **工具层无此能力。** 全部 Agent Tool 中没有任何一个写入 `fpna_plan_versions` / `fpna_plan_lines`。`fpna_copilot` 技能的写类工具仅 6 类（均落草稿层）：`fpna.actions.draft.create`、`fpna.explanations.draft.create`、`fpna.meeting_actions.draft.create`、`fpna.memos.decision.draft.create`、`fpna.scenarios.draft.create`、`fpna.coa.suggest_template`；另有 `fpna.assumptions.suggest[_batch]`（写 `fpna_assumption_versions`，`source=ai_suggestion`）——是模型运行的**假设输入**，不是预算草稿。
   预算草稿的人工路径：`POST /performance/plan-versions`（创建版本，`fpna_governance.go:233`，权限 `fpna_actions:write`）、`CreatePlanVersionWithLines`（仓库层，`fpna_governance.go:307`，目前仅被 `finmodel/persist/publish.go` 使用）、`POST /fpna/plan-versions/import`（Excel 导入，权限 `master_data:manage`）。这三条都没有 agent tool 包装。

2. **运行时实测（带 fpna-workbench 页面上下文提问）。** Agent 自动匹配 `fpna_copilot` skill，先执行读类工具：2026-08 门店经营事实 0 条、门店四墙空、设备空、关账准备度 population=0；合同仅 CT-LE001/CT-LE002 两条且**均未映射门店**。随后如实回答：**「我未获得任何可调用 FP&A 工作台生成预算草稿的工具凭证，无法执行该操作」**，并列出前置条件（编制范围/科目/币种口径、补齐 baseline 事实、合同-门店映射、工具权限）。未编造任何预算数字——这是 assist mode 的正确行为，但结果就是「无法完成」。

3. **数据层也不具备条件。** 当前演示数据集只到 2026-06-05（as-of），2026-08 无任何 store-day 事实；现有 BUDGET 版本只有表头（`fpna_plan_lines` 0 行）；无合同-门店映射。即使补上工具，也做不到「计划行与门店经营事实对齐」。

**扩版路径建议：** 新增 `fpna.plan_version.draft.create`（按现行命名规则二级段表达，不开新根），`Level=Draft` + `ReviewPolicy{Required, AllowedRoles:[reviewer/approver], ConfirmAction}` + 幂等，写入 `fpna_plan_versions(status=draft)` + `fpna_plan_lines`，并带 `source=ai_suggestion` 标记（AI 可提议、不可自我批准）；校验复用 `CreatePlanVersionWithLines` 与导入 handler 的同一条规则；工具前置守卫应要求「存在授权范围事实或用户指定基线版本」，否则返回具名 Gap。当前最接近的绕行方案：AI 只能产出假设建议 + 情景草稿 + 数据缺口清单，预算行仍须人工建版本/导入，AI 事后协助核对勾稽。

### 7.4 「未落地 / 未接线」汇总（给工程的按 P0 排序）

1. **`/store-pnl` 页面数据链路断裂（P0，PRD-2 S1）**：列表走旧表 `operating-facts/stores`、`getPnl` 缺 `data_classification/dataset_version`（后端默认 production 拒绝模拟店）。后端（带参数的 API + aggregate）全通，只缺页面接线——与附录 E「✅」冲突，属「代码态与产品态不一致」。
2. **三表模型产品级演示缺口（P0，S2）**：无任何预置定义/默认模板/示例运行，「运行模型/校验期初/导出」全部没有触发点；附录 E 的验收（Golden/勾稽反向测试）是工程态，产品级验收（PRD 要求的「可演示路径」）不存在。
3. **脉搏/门店 360 无 Actual vs Budget 列（P1，P2-23）**：BP 每天大头的预算对比，在主力页面不可见。
4. **P4 续租/终止/闭店决策卡整体未落地（P1）**：PRD-1 自身也标注依赖 renewal-termination-decision-card spec，实测全站无入口。
5. **P1-16/17 日历期（月/季）UI 未接（P1）**：后端 period 已支持，前端三页只有滚动窗口。
6. **P1-15 跨店/区域汇总视图只做了按钮没做视图（P2）**：按区域后无分组表、无信号，用户看到的是「No data」。
7. **SSSG 有后端无前端卡（P2，F2）**：sssg 对象已在脉搏响应里（全部 undecidable 属正确的诚实降级），但 UI 不显示。
8. **AI 一致性小瑕疵（P3）**：同一会话对「有无合同」两次表述不同；无引用时未显式标注「无引用」；三表问题未命中 finmodel skill（无该快捷入口）。
9. **P0-2 残留**：情景台「决策就绪」徽标区分「数据就绪 vs 情景已评估」。
10. **F4/F7/F8 数据模型在、模拟数据集不含品类/库存/SKU** → 演示路径断，需要补 seed 才能展示。
11. **AI Chat 写草稿路径被意图路由遮蔽（新证据，2026-08-27 补齐）**：实测 4 次写类请求（3 次「生成经营行动草稿」+1 次「提交假设建议草稿」），**全部命中 `retail_operations`（Priority 70，仅 3 个只读工具）**，无一命中唯一带写工具的 `fpna_copilot`（Priority 45）——只要问句含零售关键词（门店/经营利润/毛利/人工成本率），高优先级零售技能就压住 FP&A 技能，「行动草稿/假设建议」等写工具在自然语言下实际不可达；此前唯一一次命中 fpna_copilot 的是纯 FP&A 语境（「在 FP&A 工作台生成预算草稿」，无零售词）。另观察到写类工具走 `retail_operations` 时会被要求补 horizon_months（情景参数）后拒绝——诚实但打不通。**修法建议**：技能选择显式化（页面「交给 AI 分析」按当前页绑定技能；fpna-workbench 绑定 fpna_copilot）或匹配权重去遮蔽；补 `fpna.plan_version.draft.create` 才是预算 draft 的正路（§6）。
