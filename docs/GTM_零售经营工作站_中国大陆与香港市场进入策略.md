## 0. Executive Summary

- **当前不是获客阶段，是 design partner 阶段。** 运行库经营域 0 条真实数据、0 次客户访谈。此时建漏斗会得到一批愿意看 demo 但永远不上数据的"伪线索"。第一目标是 **3 家 design partner**，不是 30 条线索。

- **这个产品做不了 PLG，应尽早放弃自助增长幻想。** 数据敏感度高、价值滞后于集成、买家（CFO/COO）与用户（BP/区域经理）分离、客单价门槛高。结论是销售驱动 + 咨询式交付，接受 6–12 个月周期。

- **核心打法是「合规楔子 → 经营扩张」。** 用 IFRS 16 / CAS 21 租赁会计做入口（成熟度 4.5、合规刚需、预算好批、owner 明确），落地后租约/面积/门店/关键日期已进系统，再向上扩张占用成本、四墙利润、行动闭环（成熟度 2.0–2.8、未验证）。这条路径与产品当前的能力分布完全吻合。

- **香港做 beachhead，大陆做主战场。** 香港的价值不是市场规模（TAM 小），而是**验证速度**：HKFRS 16 强制、租金痛点极端、决策链短、SaaS 接受度高、可产出对大陆有背书价值的 case study。大陆的销售周期、私有化要求和"项目制"付费模式必须提前在交付形态上设计，不能事后补。

- **第一渠道是会计师事务所的租赁会计 / IFRS 服务团队，不是直销。** 他们已经握有客户信任、已在财务部门内部、且自身正被"每个客户重做一遍 Excel 计量"所困。渠道杠杆远高于陌拜。

- **本文档存在一个未解前提：团队现有关系网。** 见 §8。这决定下一步是"找客户"还是"先建圈层"，两者资源分配完全不同。

## 1. 阶段定义：先分清 Design Partner 与 增长获客

把这两件事混为一谈是早期 B2B 最常见的失败模式。它们的目标、数量、定价和成功指标全部相反。

| 维度 | Phase 0：Design Partner（现在） | Phase 2：增长获客（约 12–18 个月后） |
|---|---|---|
| 目标 | 拿到真实数据 + 验证付费意愿 | 建立可重复的销售路径 |
| 目标数量 | 3 家 | 30 家 |
| 定价 | 免费 / 极低价，换数据授权与深度参与 | 标准报价单 |
| 客户来源 | 创始人关系网、专业圈层、事务所转介 | 渠道 + 内容 + 销售团队 |
| 交付方式 | 创始人亲自实施，接受大量定制 | 标准实施手册 + 实施伙伴 |
| 成功指标 | 用了 6 个月还在用，且愿意付第二年 | CAC / LTV / 回收期 |
| 失败信号 | 数据一直不上传；只看看板不建行动 | CAC 回收期 > 24 个月 |

**中间的 Phase 1（约 6–12 个月）**：把 3 家的定制交付沉淀为可复制的实施方法论、连接器清单和标准指标口径。这一阶段不扩销售团队。

> **纪律要求**：在 Phase 0 完成前，不得对外宣称产品市场匹配、客户采用数或真实 ROI；不得把内部模拟验证结果表述为客户证据。此条沿用可行性报告的约束。

## 2. 为什么这个产品不能 PLG

以下四条是结构性的，不是执行力问题，不要试图用增长技巧绕过。

| 障碍 | 具体表现 | 后果 |
|---|---|---|
| 数据敏感度极高 | 门店销售明细 + 租约商务条款，属于企业最核心的两类数据 | 没有 CFO 签字和 DPA，没人会上传，自助注册转化率趋近于 0 |
| 价值滞后于集成 | 不接 POS/ERP、不导租约台账，产品就是空壳 | 免费试用期内客户永远走不到"看到价值"那一步，试用即流失 |
| 买家 ≠ 用户 | 决策人是 CFO/COO/财务总监，日常用户是 BP、区域经理、租赁会计 | 用户自下而上的喜爱无法自动转化为采购，必须有自上而下的销售动作 |
| 客单价门槛 | 交付含数据集成、口径对齐、口径评审 | 年 ARR 低于 20–30 万时单位经济模型不成立，低价客户是负毛利 |

**因此明确不做的事**（写下来是为了以后不反复讨论）：

- ❌ 自助注册 / 免费试用 / freemium
- ❌ 信息流广告、SEM 投放、增长黑客式裂变
- ❌ 一开始就做"通用零售 BI"的内容营销（打不过存量厂商，且吸引到的是错误画像）
- ❌ 低价走量以求 logo 数量

## 3. 核心策略：合规楔子 → 经营扩张

### 3.1 策略图

```text
入口（成熟 4.5 / 合规刚需 / 预算好批）        扩张（差异化 / 高价值 / 未验证 2.0–2.8）
────────────────────────────────────      ────────────────────────────────────────
IFRS 16 / HKFRS 16 / CAS 21 租赁计量   →   占用成本口径
合同台账 / 关键日期 / 选择权管理        →   门店四墙利润 / 租售比
月结 / 披露 / 审计包                   →   续租-终止决策卡 / 租金谈判测算
                                       →   行动闭环与收益兑现
                                       →   受控经营 Agent
```

### 3.2 为什么用租赁会计做入口

| 理由 | 说明 |
|---|---|
| 合规刚需 | 不是 "nice to have"。审计师会催、董事会会问、有明确截止日 |
| 痛点具体可量化 | 典型现状："我们用 47 个 Excel 做计量，月结要 5 天，去年被提了 2 个审计调整" |
| Owner 明确 | 财务经理 / 租赁会计 / Financial Controller，找得到人 |
| 预算容易批 | 可挂在审计、合规或内控科目下，不需要论证"分析的 ROI" |
| 产品最成熟 | 可行性报告评分：财务与占用成本差异化 4.5，零售经营指标仅 2.8，数据接入仅 2.0 |
| 数据量小 | 几十到几百份合同，无需 POS/ERP 联调即可上线，**这是唯一能在 4 周内产生价值的模块** |

### 3.3 为什么它能自然扩张

落地后，**租约条款、面积、门店主数据、关键日期、递增条款、选择权已经在系统里**。这正是可行性报告（该报告已归档）所述、也是与"客户自建 Doris + BI"竞争时最硬的一条差异：**这些数据不在客户的湖仓里，任何 BI 都分析不了不存在的数据**。

此时向上销售占用成本率、四墙 EBITDA、续租决策分析，客户的边际阻力极低——**不需要再做一次数据集成**，只需要再接销售/客流/人工事实。这是 land-and-expand 最理想的结构。

### 3.4 中国大陆的合规红利（需核实）

CAS 21《租赁》与 IFRS 16 趋同，境内执行企业会计准则的企业已须按新准则处理承租人租赁。市面上仍有大量企业以 Excel 完成计量。这构成一个**真实存在、有明确合规驱动的入口**，销售叙事强度远高于"我们有 AI 零售分析"。

> **待验证**：CAS 21 的具体适用范围、执行时点与豁免条款，以及"仍在用 Excel"的比例，均需由具备资质的会计专业人士核实后方可写入对外材料。本文档不作为准则依据。

## 4. 市场选择：香港 Beachhead，大陆主战场

### 4.1 为什么先香港

选香港的理由**不是市场规模，是验证速度**。

| 优势 | 说明 |
|---|---|
| 合规压力最直接 | HKFRS 16 与 IFRS 16 一致，港交所上市公司强制适用与披露 |
| 租金痛点极端 | 香港连锁零售的租金/占用成本占营收比处于全球最高区间，"占用成本率"是董事会级议题，**不需要市场教育** |
| 决策链极短 | 家族式管理的连锁集团居多，老板/CFO 一句话即可定，不必等 IT 部门半年排期 |
| ICP 密度高 | 50–500 店的餐饮、药妆、便利、珠宝、时装连锁在香港高度集中 |
| SaaS 接受度高 | 可直接销售云端订阅，避免首单即私有化 |
| 背书可迁移 | 产出英文/繁中 case study，对大陆的港资、外资及出海连锁具备说服力 |
| 专业圈层紧密 | HKICPA、四大与中型所的圈子小、信息流动快，一个成功案例传播极快 |

**香港的限制**：符合 ICP 的公司总数可能仅 100–200 家量级（**需核实**）。因此香港是**验证场与背书来源，不是终局市场**。不要按香港的 TAM 做公司融资叙事。

### 4.2 大陆的现实约束（必须提前设计）

这四条如果事后才处理，会导致产品架构返工或大单流失。

| 约束 | 影响 | 现在就要做的动作 |
|---|---|---|
| **私有化部署几乎是必答题** | 大型零售集团的销售数据不会放公有云 | 现在就把交付形态设计成「SaaS + 私有化」双轨；docker-compose 已是好起点，需补齐离线安装、License 校验、版本升级路径 |
| **付费模式偏"项目"而非"订阅"** | 首年多为「实施费 + 授权费」，而非 ARR | 续费要靠**嵌入月结流程**来保（租赁计量是每月必跑的，天然黏性）；定价结构要能同时表达两种形态 |
| **销售周期 6–12 个月** | 现金流压力 | 财务预期按此设定；不要按 SaaS 的 3 个月周期做规划 |
| **国产化 / 信创** | 影响国企、部分上市公司客户 | 记录为已知约束，暂不投入。待出现具体商机再评估 |

### 4.3 两地打法对照

| 维度 | 香港 | 中国大陆 |
|---|---|---|
| 阶段定位 | Beachhead / 验证场 | 主战场 / 规模来源 |
| 目标客户 | 港交所上市连锁、家族连锁集团 | 上市连锁、大型连锁集团、外资/港资在陆业务 |
| 主渠道 | 四大 + 中型所租赁服务团队、HKICPA 圈层 | 事务所转介、CCFA 等行业协会、财务专业内容 |
| 交付形态 | 云端订阅优先 | SaaS + 私有化双轨，大客户以私有化为主 |
| 语言 | 繁中 + 英文（英文为主的专业材料） | 简中 |
| 内容平台 | LinkedIn、英文白皮书、行业活动 | 公众号、知乎、视频号、行业协会刊物 |
| 定价形态 | 年度订阅 | 首年「实施 + 授权」，后续年度维护/订阅 |
| 关键风险 | TAM 天花板 | 销售周期长、私有化交付成本高 |

> **定价区间刻意留空。** 在完成至少 10 场客户访谈与 3 家竞品报价调研前，任何价格数字都是编造的。定价假设应在 Phase 0 结束时单独成文。

## 5. 渠道策略

### 5.1 第一优先级：会计师事务所的租赁会计 / IFRS 服务团队

**为什么优先于直销：** 他们已经拥有信任关系、已经在客户的财务部门内部、已经知道谁在痛。一位事务所租赁服务合伙人的转介质量，抵得上半年陌拜。

**他们自身的痛（这是合作的真正基础）：**
- 每个客户的 IFRS 16 计量都要重做一遍 Excel 模型，人力密集、不可复用
- 模型易错，复核成本高，是执业风险来源
- 交付周期长，占用高级别人力，项目毛利被压

**价值主张（给合伙人的一句话）：**
> "你们的顾问用我们的产品交付租赁计量，交付周期从 6 周压到 2 周，复核有系统留痕；你们赚咨询费，我们收授权费。"

**合作形式（按承诺度递增，从左往右谈）：**

| 形式 | 我方投入 | 对方承诺 | 适用阶段 |
|---|---|---|---|
| 转介绍分成 | 低 | 低 | 首次接触，先建立关系 |
| 联合交付 | 中（二线支持 + 培训） | 中（指定项目使用） | 有 1–2 个成功案例后 |
| 白标 / 联合品牌 | 高（品牌与产品让渡） | 高（纳入标准服务包） | 需谨慎，可能丧失终端客户关系 |

**风险提示：** 白标会切断我们与终端客户的直接关系，使 §3.3 的"向上扩张经营分析"路径受阻。**建议前期只做转介绍与联合交付，保留终端客户接触权**，并把这一条写进合作协议。

### 5.2 次级渠道

| 渠道 | 说明 | 优先级 |
|---|---|---|
| 中国连锁经营协会（CCFA）及各地连锁协会 | 行业会议、白皮书、案例分享。是接触零售 COO/CFO 的高密度场景 | 中 |
| HKICPA / 香港零售管理协会圈层 | 香港专业圈层小而紧密，活动出席即接触 | 中（香港侧为高） |
| 商业地产 / 购物中心运营方的租户网络 | 可触达大量连锁租户，但注意产品边界不含房东侧 | 中低 |
| 用友 / 金蝶 / SAP 生态 | 既是渠道也是潜在竞争者，合作前需评估其自身租赁模块的路线图 | 低，谨慎 |
| 零售 ERP / POS 厂商 | 互补性强（他们有数据，我们有租约与决策层） | 低（需产品更成熟后） |

### 5.3 内容与信任建设

**已有弹药（目前躺在 repo 里未被利用）：**
- [IFRS16_计量方法与准则映射白皮书.md](IFRS16_计量方法与准则映射白皮书.md)
- 计量回归对数报告（不入库，`make ifrs16-regression` 生成 22 用例 / 148 断言的逐条对数）

这两份可直接改写为对外引流资产。**注意口径**：回归的标准答案仍是 `pending_third_party_review`，对外材料不得表述为审计背书。

**内容选题原则：写财务人真实会搜索的长尾问题，不写"AI 零售分析"。**

大陆（公众号 / 知乎）候选选题：
- 变量租金（turnover rent）在 CAS 21 下的处理与常见误区
- 续租选择权"合理确定"的判断实务与证据留存
- 售后回租的计量陷阱
- 租赁负债重估的触发条件与操作步骤
- 短期租赁与低价值资产豁免的边界

香港（LinkedIn / 英文白皮书）：同一组主题的 HKFRS 16 版本，措辞更技术化，附可下载的计算示例。

**为什么这类内容有效：** 转化率不高但信任度极高，且能建立"这家公司懂准则"的定位——这正是对抗客户自建 Doris + BI 的领域深度护城河（该报告已归档）的对外表达。

> **合规提醒**：所有准则解读类内容必须经具备资质的会计专业人士复核后发布，并附免责声明（不构成专业意见）。

## 6. ICP 打分卡

用于快速判断一个潜在客户是否值得投入。**≥ 70 分进入 design partner 候选池；< 50 分明确放弃**，不要因为"是个大 logo"而破例。

| # | 维度 | 权重 | 满分条件 | 分值 |
|---|---|---:|---|---:|
| 1 | 门店数量 | 15 | 50–500 家直营门店 | 0–15 |
| 2 | 占用成本占比 | 20 | 租金 + 服务费占营收 ≥ 10%，且是管理层关注议题 | 0–20 |
| 3 | 合规压力 | 15 | 上市公司或需出具 IFRS 16 / HKFRS 16 / CAS 21 披露 | 0–15 |
| 4 | 现状痛感 | 15 | 租赁计量仍靠 Excel，且月结曾因此延迟或被审计提出问题 | 0–15 |
| 5 | 数据可得性 | 10 | 已有 POS/ERP 且能导出 store-day 粒度销售数据 | 0–10 |
| 6 | 组织现状 | 10 | 财务、运营、租赁会计对同一门店使用**不同口径**（这是痛点信号，不是减分项） | 0–10 |
| 7 | 决策链长度 | 10 | 能直接接触 CFO / COO，采购不需 IT 部门主导 | 0–10 |
| 8 | 数据团队成熟度 | 5 | **反向计分**：客户已有成熟数据团队 + 语义层（dbt/Cube/Looker）则**扣分**，我方价值被压薄 | -5–5 |

**自动淘汰条件（一票否决）：**
- 门店 < 20 家（价值主张不成立）
- 加盟为主、总部无门店层级经营数据（数据供给缺失）
- 采购已由 IT 部门主导且已立项自建数据平台（我们进入的是错误的战场）
- 租约数据已在某成熟租赁管理系统中且完全满足需求（护城河 1 失效）

## 7. Phase 0 执行计划：招募 3 家 Design Partner

### 7.1 Design Partner 的定义与对价

**我们给什么：**
- 首年免费或象征性收费（具体额度按客户情况定）
- 创始人 / 核心团队亲自实施与陪跑
- 优先响应的需求通道：他们的痛点直接进入 roadmap
- 首年结束后按早期客户价格续约的锁定权

**我们要什么（必须书面约定，缺一不可）：**
- **真实数据授权**：≥ 6 个月历史的 store-day 粒度经营数据 + 完整租约台账
- **用户参与**：至少 2 名 BP / 分析师 + 1 名租赁会计的常规使用
- **双周复盘**：每两周 45 分钟的产品反馈会，持续 6 个月
- **可引用性**：6 个月后若结果满意，同意作为具名或匿名案例
- **付费意愿测试**：第 7 个月起进入付费谈判（**这是最关键的验证，不能省略**）

> 不签书面协议的"愿意试试"不算 design partner。免费+无承诺 = 必然不用。

### 7.2 招募话术（冷启动，事务所转介版）

> **开场（给财务总监 / Financial Controller）：**
>
> "我们在做一个针对连锁零售承租方的产品。想先问一个问题：**贵司现在的 IFRS 16 租赁计量是怎么做的？月结那几天要花多少人天？**"
>
> —（听对方描述 Excel 现状，不要打断，记录具体数字）—
>
> "这和我们看到的情况一致。我们做的第一件事，是把租赁计量从 Excel 搬进系统：合同、事件、现金流、重估、披露包，都有版本和审计留痕，月结可以复演。这部分产品已经比较成熟。
>
> 但我们真正想解决的是下一步——**把租金和门店的销售、毛利、客流、人工连起来，算出每家店真实的四墙利润和占用成本率，再把结论变成有责任人、有截止日期、能验证收益的行动。** 这部分我们还在做，所以想找 3 家公司深度共建。
>
> 具体是：首年不收费，我们亲自帮你们把租赁计量上线，作为交换，希望能拿到你们的门店经营数据来把经营分析这部分做对，并且每两周聊 45 分钟。半年后如果你们觉得有用，我们再谈付费。
>
> **想先确认一件事：如果真的有一个系统，能告诉你哪些门店在扣除租金后其实是亏的、以及续租还是关店哪个更划算——这个问题今天在贵司是谁在负责回答？**"

**话术设计说明：**
- 用**合规痛点**开场（易共鸣、易量化），而不是"AI 分析"
- 明确区分"已成熟"与"在共建"，**不夸大未验证能力**（符合可行性报告纪律）
- 结尾问句用于**定位真正的经济买家**，同时测试这个问题是否真的存在

### 7.3 客户访谈脚本

目标：每场 45 分钟，Phase 0 内完成 **≥ 30 场**。访谈的首要目的是**证伪**，不是推销。

**A. 现状与痛点（15 分钟）**
1. 贵司现在有多少家门店？直营 vs 加盟比例？
2. 租金 + 服务费占营收大概多少？这个数字管理层多久看一次？
3. IFRS 16 / CAS 21 的计量现在怎么做？谁做？花多长时间？
4. 上一次因为租赁数据出问题（月结延迟 / 审计调整 / 口径打架）是什么时候？具体发生了什么？
5. 门店经营数据（销售、毛利、客流、人工）现在在哪些系统里？谁能拿到？
6. 财务算的门店租金成本，和运营算的，是同一个数吗？（**若不是，追问差异如何解决**）

**B. 决策流程（10 分钟）**
7. 一家门店表现不好，从发现到决定采取行动，中间经过哪些人、多长时间？
8. 上季度门店改善的行动，有几条按期完成了？收益兑现了多少？**你现在能在哪个系统里看到这个数字？**
9. 续租 / 关店的决策，依据是什么？谁拍板？有没有统一的测算模板？

**C. 护城河失效条件验证（15 分钟）— 本节必须问，不得跳过**

这四组问题直接对应产品差异化的四条护城河（该报告已归档）。若答案全部指向"已解决"，则我方价值主张对该客户不成立，应记录并放弃。

| 护城河 | 验证问题 | 失效信号 |
|---|---|---|
| 1. 租约数据不在湖仓里 | "租约的商务条款——面积、递增、turnover rent 规则、选择权、关键日期——现在存在哪里？是结构化的吗？能查询吗？" | 已有成熟租赁管理系统且开放 API |
| 2. 三套口径的领域深度 | "财务报告口径的租金（折旧+利息）和门店经营口径的租金（实付+变量租金），贵司是怎么区分的？谁维护这个映射？" | 已有明确的双口径定义与维护机制 |
| 3. 状态化决策工件 | "预算版本、场景测算、决策纪要、行动跟踪现在跑在什么工具上？够用吗？" | 已在飞书/钉钉/Jira 上跑顺且满意 |
| 4. 受控 AI | "如果有个 AI 助手能直接改预算版本或建行动，你们会担心什么？" | 完全不关心治理 = 该价值主张卖不动 |

**D. 数据团队现状（5 分钟）**
10. 有没有独立的数据团队？多少人？
11. 有没有数据仓库 / 湖仓（Doris、ClickHouse、Snowflake、Fabric）？谁在用？
12. 有没有语义层 / 指标平台（dbt、Cube、Looker）？口径统一问题解决了吗？

> **访谈纪律**：不 demo、不报价、不承诺功能。全程记录**客户的原话**而非我方的总结。每场访谈后 24 小时内归档至 `docs/research/`。

## 8. 未解前提：团队现有关系网（阻塞项）

上述打法有一个本文档无法判断的前提。**这是执行前必须先回答的问题**，它决定资源分配：

| 现状 | 下一步优先级 | 预期首签时间 |
|---|---|---|
| 有零售集团 CFO / 财务总监的直接关系 | 直接走 design partner 招募，跳过建圈层 | 约 3 个月 |
| 有四大 / 中型所租赁服务团队的关系 | 优先做渠道合作，杠杆最大 | 约 4–6 个月 |
| 有零售行业协会 / 商业地产圈层关系 | 从行业活动切入，先建立专业声誉 | 约 6–9 个月 |
| 以上均无 | **第一优先级是花 3 个月做 30 场访谈建立圈层，而不是继续写代码** | 约 9–12 个月 |

第四种情况下，最大的风险不是产品不够好，而是**在没有客户反馈的情况下继续投入研发**，这会放大可行性报告已经指出的核心风险（"只能证明平台能承接，不能证明客户会持续使用"）。

## 9. 成功与失败指标

### 9.1 Phase 0 的四个核心指标

**不看 MRR、注册数、DAU。** 这些在本阶段全是虚荣指标。

| # | 指标 | 目标 | 说明 |
|---|---|---|---|
| 1 | Design partner 签约数 | 3 家 | 必须是含数据授权的书面协议 |
| 2 | 真实经营数据接入 | ≥ 50 门店 × ≥ 6 个月 store-day 粒度 | 低于此规模无法验证同店、cohort 与日/周口径 |
| 3 | **行动闭环真实发生** | 被创建 → 认领 → 关闭 → 收益验证的行动 > 0 | **最关键的证伪指标，见下** |
| 4 | BP 角色周留存 | 周活跃 ≥ 2 天，连续 ≥ 8 周 | 低于此说明不是日常工具，只是月度报表 |

**为什么第 3 条最关键：** 如果客户拿完看板就走、从不创建行动，那么"从分析到可验证行动的闭环"这个核心差异化就是伪命题——产品退化为一个昂贵的 BI，而在那条赛道上我们打不过客户自建的 Doris + BI。**这条指标失败，整个产品定位需要重来，而不是继续加功能。**

### 9.2 停止条件（Kill Criteria）

出现以下任一情况，应停下来重新评估定位，而不是继续投入：

1. 30 场访谈中，**护城河 1（租约数据不在湖仓里）失效率 > 50%** → 差异化基础不成立
2. 12 周内**签不到 1 家 design partner** → ICP 定义或价值主张有根本问题
3. Design partner 上线 3 个月后**行动创建数仍为 0** → 决策闭环是伪需求
4. 第 7 个月付费谈判中**3 家全部拒绝付费** → 无独立付费意愿
5. 客户反复要求的是"更多图表 / 更快刷新"而非决策能力 → 我们被拖入了必输的赛道

## 10. 本文档的已知局限

沿用可行性报告的诚实基线，明确列出本文档**不能**支撑的结论：

- 没有客户访谈，因此 ICP 假设、痛点描述和话术全部未经验证
- 没有市场规模测算，香港与大陆的 TAM 数字均为估计，不可用于融资材料
- 没有竞品价格调研，因此本文档**刻意不给出任何定价数字**
- 没有渠道验证，事务所合作的意愿与分成结构均为假设
- CAS 21 / HKFRS 16 的适用范围与执行细节需由具备资质的会计专业人士核实
- 本文档描述的是**计划**，不是**结果**；任何对外材料不得引用其中内容作为已发生的事实
