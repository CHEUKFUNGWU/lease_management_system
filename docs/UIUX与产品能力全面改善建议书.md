## 0. 执行摘要：CFO 的核心诊断与战略定调

在过去的产品演进中，我们优先建设了 IFRS 16 租赁会计引擎，并逐步搭建了 store-day 事实层与 `retail-kpi-v1` 指标语义。但从集团财务总监视角，立足于**集团、大区、单店**三层下属（财务 BP、FP&A 分析师、经营分析师）的实际日常工作流进行全方位走查后，当前工作站存在**四大结构性脱节**：

```
┌──────────────────────────────────────────────────────────────────────────────────────────┐
│                               四大结构性脱节 (Core Structural Gaps)                       │
├──────────────────────────────────────────────────────────────────────────────────────────┤
│ 1. 业务重心脱节：全站 31 个页面中超 15 个服务于租赁与 IFRS 16，零售经营核心（人/货/场）严重缺位 │
│ 2. 页面架构重叠：经营脉搏、驾驶舱、门店360多处重合；甚至残留工业制造设备代码与软件销售ROI玩具     │
│ 3. 财务模型僵化：三表模型死锁在单法人，科目树与驱动公式不可自定义，无法在集团/大区/单店泛化     │
│ 4. 角色作业断层：日常高频工作（滚动预测、开闭店测算、单店对账、杜邦归因、活动复盘）仍靠 Excel   │
└──────────────────────────────────────────────────────────────────────────────────────────┘
```

本建议书旨在系统性地给出改进方案，彻底清理历史包袱，补齐零售核心分析与财务模型能力，重塑高密度、现代化的 UI/UX 体验。

### C. 本文漏掉的、比它列出的任何一项都严重的缺陷

`web/app/performance/page.tsx:164-169` 的同群对标表：

- 列标题硬编码中文「同群平均坪效达成率」，渲染的值是 `row.fact.oee_pct || row.fact.utilization_pct`，也就是设备综合效率，取不到就退到产能利用率。这两个数与坪效没有任何关系。
- 门店副标题 `row.fact.plant_code || "核心商圈"`、`row.fact.production_line_code || "标杆同群"`。工厂代码为空时兜底显示一个听起来合理的商圈词。

本文把设备代码残留定性为「专业性硬伤」。它不是硬伤，是**界面在说假话**：使用者读到的是一个看起来完全合理的零售指标。这违反的是本仓最硬的一条纪律，也是唯一一条与产品信任直接相关的纪律。Spec 把它列为第一优先级。

### D. 术语更正

§5.2 称「杜邦五因素异动归因」。杜邦分析是净资产收益率的三因子分解（利润率 × 周转率 × 权益乘数），是资本回报的分解方法。§5.2 描述的是门店利润差异的因子分解，那是连环替代法的差异分析。两者不是一回事。另外标题说「五因素」，其下公式列了六项加残差。

界面文案统一叫「利润差异归因」，Spec 按七因子 + 残差定义，并要求替代顺序回显（连环替代法的结果依赖顺序，不声明顺序的归因数字无法被复核）。

### E. 排期不可用

§7 按 2026-Q3 起算「阶段 0 一周」，但复核日已是 2026-08-22，Q3 剩不到六周。且团队是一位人类 + AI 协作者（`docs/AI_文档索引与现行决策.md` §6），没有可并行的第二条人力线。Spec 不给日期，只给依赖顺序。

### F. 仍然成立、且已被 Spec 全额采纳的部分

清单本身有错，方向判断没错。以下几条我复核后认为完全成立：

- 产品重心确实过度偏向租赁合规，导航与功能入口需要按零售经营工作流重组（§4.2）；
- 保留并增强门店利润流向桑基图（§2.4）。不过「不得删除既有功能」已经覆盖了这条，不需要单列为纪律；
- 缺失数据显示「—」不用 0 填补、`pp` 与 `%` 严格区分、状态用 8px 圆点不用彩色 Tag 轰炸、AI 用当前页 Drawer 不跳页（§6.1~6.3）。这几条与 `DESIGN.md` 一致，Spec 已做成 CI 可强制的守卫；
- 促销投前保本测算、新店全生命周期业务测算、滚动预测自动滚入、公式可视化编辑器四项确实缺失（§5.1/5.3/5.4、§3.2 第三点）。这四项进了 Spec 的能力补齐批次。

## 一、 角色工作流与痛点矩阵（集团 — 大区 — 单店）

为确保产品改动真正贴合业务实际，我们将整个工作站的使用者细分为 3 个层级、3 类核心角色，并对其日常工作断点进行精准对齐与剖析：

| 组织层级 | 角色定位 | 核心日常工作流 | 当前工作站痛点与断点 | 迫切改善诉求 |
| :--- | :--- | :--- | :--- | :--- |
| **集团层面 (Group)** | **集团 FP&A** | 集团月度滚动预测 (3+9 / 6+6 / 12+24)；集团三表模型合并与资金计划；多币种/跨法人折算；资本开支 (CAPEX) 配置与投资回报追踪。 | 现三表模型只支持单法人 (`legal_entity_id`)，无集团合并抵销与折算视图；科目树不可自定义；无法进行自上而下的目标分解 (Top-down Target Setting)。 | 集团级多法人三表合并视图；多币种折算看板；自定义科目树与驱动公式库。 |
| | **集团经营分析师** | 集团大盘经营监控；各大区/品牌经营业绩横向拉通；异常大区穿透；全集团促销 ROI 宏观复盘；全渠道/品类结构监控。 | 缺少集团宏观大盘；数据散落在多个不同颗粒度的页面；缺少跨大区、跨品牌的对比矩阵与多维切片分析 (Slice & Dice)。 | 集团大盘总览；品牌/大区对标象限矩阵；全渠道毛利与费用拆解模型。 |
| **大区层面 (Region)** | **大区财务 BP** | 大区月度损益汇总；新开店选址可行性测算 (Feasibility Study)；租金谈判测算与续约/关店决策；大区 CAPEX 进度与折旧分摊管控。 | `/pre-deal` 和 `/deal-compare` 只是租赁现金流折现，**完全没有新店业务经营测算**（无客流、客单价、装修CAPEX、回本期Payback、IRR模型）；无法出具大区汇总利润表。 | 新店全生命周期经营测算模型；大区单店利润表批量汇总；大区多店组合情景模拟。 |
| | **大区经营分析师** | 大区各店日/周达成追踪；同城竞对对标；大区促销活动效果监控与费用分摊；异常门店运营根因排查（人效、转化、缺货）。 | 缺少大区层面的“高租金-低坪效”危机门店分布图；`/promotions` 页面与门店损益脱节，无法衡量促销对大区净利润的真实拉动。 | 大区运营矩阵看板；活动增量毛利测算与追踪；异常门店预警与督导工单派发。 |

## 二、 经营类页面功能重叠与历史包袱清理

当前系统 31 个页面中，经营分析类页面存在严重的**功能重合、定位冲突与历史残留代码**。必须做坚决的下架、整合与归并：

```

┌──────────────────────────────────────────────┐                ┌──────────────────────────────────────────────┐

│ · /performance (驾驶舱: 混杂设备稼动率/OEE)    │ ─────────────► │    - 吸收原 performance 的四墙EBITDA排行与行动 │
│ · /store-360 (单店360诊断)                   │                │    - 彻底删除工业设备/OEE/工厂代码            │
├──────────────────────────────────────────────┤                ├──────────────────────────────────────────────┤
│ · /scenario-workbench (单店百分比情景微调)    │                │ 2. 门店 360 深度洞察 (/store-360)             │

                                                                 └──────────────────────────────────────────────┘
```

### 1. 彻底清除 `/performance` 中的工业制造遗留代码
- **现状缺陷**：代码中存在 `PeerBenchmarkItem`，包含 `equipment_id`、`plant_code`、`production_line_code`、`oee_pct`（设备综合效率）、`utilization_pct`（产能利用率）以及设备事实对账。这是早期工业资产租赁系统的残留，出现在零售经营工作站中是严重的专业性硬伤。
- **改善措施**：
  - **立即清理**：从数据库、后端 API (`performanceApi.equipmentPerformance`) 到前端全面剔除所有设备、产线、工厂相关字段。
  - **页面合并**：将 `/performance` 中的“四墙 EBITDA 排行”和“行动项管理 (Action Tracking)”直接合并并入 `/operating-pulse` 的「门店排行与行动建议」Tab 中，**废除独立的 `/performance` 路由**。

### 2. 坚决下架荒谬的 `/roi` 页面
- **现状缺陷**：导航中的 `/roi` 页面竟是“测算引入本租赁管理系统能节约多少合同录入工时、月结天数和审计工时”的**软件采购销售计算器**。这属于供应商向甲方演示的 Demo 页面，放在面向企业内部财务 BP 与分析师的工作站中不仅毫无业务价值，更严重损害产品的专业定位。
- **改善措施**：
  - **下架 `/roi` 页面**，将其从系统导航中彻底移除；
  - 将 `/promotions`（促销活动与促销 ROI）更名为更加明确的「促销与营销投资回报 (Promotion & Marketing ROI)」，承载真正面向零售业务的活动前测算与投后复盘。

### 3. 统一测算与情景工具链
- **现状缺陷**：
  - `/scenario-workbench`：只能对单店调整几个预设百分比（租金、营收、毛利率），功能过于单薄；
  - `/pre-deal` 与 `/deal-compare`：只算合同层面的现金流折现与会计影响，无业务端输入；
  - `/fpna-workbench`：停留在扁平的版本生命周期管理，未与模型测算深度结合。
- **改善措施**：
  - 将 `/pre-deal`（签约前评估）升级为「新店开业全生命周期测算 (New Store Feasibility Model)」，融合业务营收预测、CAPEX 投入、回本期与 IFRS 16 租金测算；
  - 将 `/deal-compare` 降级为租赁合同详情页中的「租约商务条件比选抽屉 (Drawer)」，无需占用一级导航菜单。

### 4. 核心资产保护纪律：坚决保留并强化「门店利润流向桑基图」
- **定调声明**：清理历史包袱（如 `/performance` 的工业设备代码与 `/roi` 的软件采购计算器）绝不等于盲目删减优秀图表。**`/store-360` 中的「门店三级利润流向桑基图 (`ProfitFlowPanel / SANKEY-001`)」是全站最具零售业务价值的明星资产，必须 100% 完整保留并持续升级**。
- **核心业务价值**：
  - 直观呈现门店单店营业额（Revenue）如何像水流一样流经进货成本（COGS）、人工薪酬（Labor）、固定/抽成租金（Occupancy Cost）、其他可控杂费，最终沉淀为门店贡献与四墙 EBITDA，是非财务专业店长与高管看懂损益的最佳载体；
  - 严守 `DESIGN.md §8.2` 的财务守恒纪律（常驻 `平衡状态 · 未归因金额 · 公式版本` 守恒说明行，真实反映数据完整度，不弄虚作假）；
  - 完全由后端契约驱动（`flow.nodes` 与 `flow.links`），自适应容器布局稳定。
- **未来三大增强规划**：
  1. **支持节点下钻**：点击人工节点展开全职/兼职构成，点击占用成本展开基本租金/抽成租金/物业费；
  2. **跨页面联动**：在 `/store-pnl`（单店利润表）顶部增加「一键图表/表格视图切换」，直接复用该桑基流向模型；
  3. **AI 异动诊断**：点击异常扩大的支流（如租金占比暴涨），直接唤起右侧 AI Drawer 进行多维根因归因。

### 1. 突破单法人限制，实现「四级多维穿透」
- **集团合并层**：支持勾选多个法人，自动生成集团管理口径的 Consolidated P&L / Balance Sheet / Cash Flow。结合已有的 `currencytranslation` 服务，提供原币分区（Currency Partition）与统一本位币折算（Group Reporting Currency）双视图。
- **大区汇总层**：支持按大区/事业部维度跨法人汇总其管辖范围内的所有门店损益与资产占用。
- **单店贡献与三表联动**：单店端以 `/store-pnl` 为基础，增加「单店自由现金流 (Store Free Cash Flow = EBITDA - 门店CAPEX - 营运资金变动NWC)」模块；法人三表的 Actual 营业收入、毛利、租金、人工成本必须能一键穿透反查到旗下所有门店的贡献明细。

### 2. 赋予 FP&A 真正可用的「自定义科目树与驱动公式」
- **科目树 (Chart of Accounts) 自定义**：
  - 允许企业根据自身 ERP 会计科目体系，配置 3~4 级科目树（如：一级`营业收入` → 二级`线下门店销售` / `外卖即时零售` / `私域社群销售`；一级`营业成本` → 二级`商品进货成本` / `物流履约费` / `盘亏损耗`）。
- **业务驱动型 (Driver-based) 预测引擎**：
  - 不应仅支持固定的比率假设。必须支持零售经典的驱动因子公式建模：
    $$\text{门店收入} = \text{商圈客流} \times \text{进店率} \times \text{转化率} \times \text{客单价} \times \text{营业天数}$$
    $$\text{商品毛利} = \sum (\text{品类收入}_i \times \text{品类综合毛利率}_i)$$
    $$\text{营运资金变动} = \Delta \text{应收} + \Delta \text{存货 (基于周转天数 DIO)} - \Delta \text{应付 (基于周转天数 DPO)}$$
- **可视化公式行编辑器 (DSL Editor)**：
  - 提供类似 Excel 的直观公式配置器（支持点击选择科目、引用滞后期 `lag(x, n)`、四则运算、`IF` 条件判断），模板保存时在后端进行语法解析与循环依赖检测，而非让财务人员手动去改 JSON。

### 3. 轻量化试算模式 (Lightweight Sandbox Mode)
- **痛点**：当前三表模型要求严格的期初 Balance Sheet（三道闸检验），否则 BS/CF 整体降级不可用。但在日常测算中，BP 经常只需要基于 P&L 和部分核心资产做快速沙盘推演。
- **改进**：增加「轻量化经营试算模式」——允许在未录入全量期初资产负债表的情况下，仅基于经营 P&L + CAPEX 投资计划 + 租金付款流，自动生成**经营性现金流预测 (Operating Cash Flow)** 与**投资回报分析**，满足敏捷决策需求。

## 五、 财务 BP、FP&A、经营分析师日常作业必须补齐的功能清单

为了让下属彻底摆脱对各自本地 Excel 文件的依赖，工作站必须补齐以下 5 项日常杀手级功能：

### 1. 滚动预测闭环 (Rolling Forecast 3+9, 6+6, 12+24)
- **业务场景**：每过一个季度或月份，Actual 历史期自动“冻结”，系统自动将已发生的真实数据与剩余预测期的假设拼接。
- **功能设计**：
  - **历史数据自动截断与滚入**：根据选定的 `actual_cutoff_period`，截止期前自动锁定并读取真实 store-day 事实，截止期后由驱动假设运算；
  - **三大版本同屏对比**：`Actual` vs `Latest Forecast` vs `Original Budget` vs `Prior Year`，自动生成差异额、达成率与差异百分点；
  - **版本谱系与锁定**：经审批的预测版本（如 `2026-Q2-Latest-Forecast`）一键打快照并归档，不可篡改。

### 2. 杜邦五因素异动归因分析 (DuPont Variance Attribution)
- **业务场景**：门店利润下滑 15 万元，财务总监需要下属在 5 分钟内解释清楚“到底是因为客流少了、客单价降了、综合毛利率滑坡了，还是人工/租金费用上升了”。
- **功能设计**：
  - 基于确定性因式分解算法，自动拆解利润差异的五个因子贡献金额：
    $$\Delta \text{门店利润} = \text{客流效应} + \text{转化率效应} + \text{客单价效应} + \text{毛利率效应} + \text{固定及变动费用效应} + \text{残差}$$
  - 以标准的**正负瀑布图 (Waterfall Chart)** 直观呈现，并在右侧一键唤起 AI 撰写基于事实归因的《经营异动解释备忘录》。

### 3. 新开店选址全生命周期商业测算 (New Store Feasibility Study)
- **业务场景**：业务部门物色了一个新铺位，大区财务 BP 需要在 2 天内出具一份《新店立项财务可行性分析报告》。
- **功能设计**：
  - **业务输入**：商圈预估客流、进店率、客单价、预估日均销售额、商品毛利率；
  - **投资与成本输入**：首次装修及设备 CAPEX、首批铺货资金、基本租金、抽成扣率、免租期、开业爬坡期 (Ramp-up Months)；
  - **自动化产出核心决策指标**：
    - 静态投资回收期 (Payback Period)、动态投资回收期；
    - 内部收益率 (IRR)、净现值 (NPV)；
    - 盈亏平衡点销售额 (`BEP`) 及达成难度评估；
    - IFRS 16 使用权资产 (`ROU`) 与负债入账对当期报表的影响。

### 4. 促销与营销活动投前投后全闭环 (Promotion Pre/Post Analytics)
- **业务场景**：大促前业务申请“满200减40”，财务 BP 需要测算“保本销售额需要增长多少”；大促后经营分析师需要复盘“这次活动到底赚了还是赔了”。
- **功能设计**：
  - **投前测算**：输入综合折扣率与营销推广费，系统自动计算**保本增量销售额 (Required Incremental Sales)**：
    $$\text{保本增量销售额} = \frac{\text{营销固定费用投入} + \text{原销售额} \times \text{毛利率损失}}{\text{活动期实际边际毛利率}}$$
  - **投后复盘**：对比基线期（同群无活动门店或活动前两周），计算活动的**真实增量毛利 (Incremental Gross Profit) = 增量营收 × 实际毛利率 - 营销支出**，彻底杜绝“虚假繁荣、增产不增收”的自嗨促销。

### 5. 一键生成管理层经营分析简报 (Executive Deck & Store P&L Deck Generator)
- **业务场景**：每月月结后，财务 BP 需要向大区总经理或门店店长进行月度经营复盘汇报。
- **功能设计**：
  - 基于系统已有的 WorkingPaper 底座与数据，一键将单店/大区的经营分析结果生成为带公式、全 Certified 单元格的 **XLSX 经营底稿** 或排版精美的 **PDF/PPT 经营简报**；
  - 自动包含：月度损益表、杜邦差异归因图、Top 关注问题、行动项跟进进度，省去财务人员每月耗费在手工排版和贴图上的大量低效劳动。

- 严禁在表格中大量使用大面积彩色背景的 AntD `<Tag color="red">` / `<Tag color="gold">`；
- 一律采用 **8px 状态圆点 (`<SeverityDot />`) + 常规字色**，仅在出现严重偏离时使用强调色，让真正的经营异常一目了然。

### 3. AI-Native 沉浸式交互：当前页 Drawer 代替跳页
- **严禁使用 `router.push('/ai-chat?...')` 或 `window.location.href` 跳出分析上下文**；
- 在 `/operating-pulse`、`/store-360`、`/scenario-workbench`、`/store-pnl` 等核心页面，点击「交给 AI 分析」一律在**右侧拉起沉浸式 `<RetailAIDrawer />`**；
- AI 的分析过程严格接入 `<ThinkingTrace>`（推理轨迹）、`<ToolChip>`（调用的数据工具）、`<SourceCitation>`（数据来源角标）、`<ApprovalCard>`（行动建议确认卡），确保 AI 输出百分之百可解释、可追溯、可干预。

### 4. 专业零售图表库扩展（四大招牌图表矩阵）
- **门店利润流向桑基图 (Sankey Flow Chart)**：**【核心资产·坚决保留】** 严格落实守恒纪律，作为门店与大区损益现金流的直观透视载体，后续扩展多级节点下钻与 AI 异常支流联动；
- **损益归因瀑布图 (Waterfall Chart)**：必须带守恒校验底线，直观呈现从营业收入到毛利、门店贡献、四墙 EBITDA 的层层扣减；
- **经营对标象限矩阵图 (Quadrant Matrix)**：提供「租售比 vs 坪效」、「毛利率 vs 周转率」双轴矩阵，快速框定“明星店”、“潜力店”、“亏损整改店”与“建议闭店店”；
- **同群置信安全带图 (Confidence Band Chart)**：展示单店指标在同品牌、同商圈同群中的 P25 ~ P75 置信区间，避免孤立看单店绝对值。

### 5. 门店 360 上半部分 UI/UX 架构定调与轻量微调清单
- **架构定调（保持稳定·无需大改）**：
  门店 360 的上半部分（筛选条 → DataTrustBar → 门店身份卡 → 6 大核心 KPI 网格 → 左右双翼图表）整体信息层级清晰、视线动线合理，已是全站最成熟的分析看板之一。主体架构坚决保持不变，仅执行以下 5 处精细化微调：
- **5 项轻量微调清单（Micro-Polishing）**：
  1. **筛选条小屏排版防折行**：将「核心必选（门店 + 时间窗口）」常驻，将「自定义天数输入框」与「数据源系统」收纳为紧凑控件，防止 13~14 寸屏幕下折成不规则两行；
  2. **门店身份标签去彩色杂音**：将生命周期与店型的 AntD 预设彩色 `<Tag color="purple">` / `<Tag color="cyan">` 替换为符合 `DESIGN.md §3.3` 的 Coastal Navy 冷调中性 `<StatusTag kind="neutral">`；
  3. **KPI 卡片基线与数值对齐**：确保所有数值锁定 `font-variant-numeric: tabular-nums`，对比基线（`对比: ¥xx`）严格对齐底部单行，卡片添加微弱悬停反馈（`--shadow-hover`）；
  4. **右侧图表卡片表头防挤压**：优化「瀑布图 ⇋ 桑基图」切换器 `Segmented` 的 padding 与 min-width，保证窗口缩放时标题文字不换行，左右双翼卡片表头高度严格等高；
  5. **顶栏操作按钮主次分层**：将「AI 深度分析」与「导出」设为主操作，「情景分析」与「返回脉搏」设为简洁描边次级操作，形成清晰的操作梯队。
