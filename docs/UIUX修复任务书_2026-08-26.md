## 总约束（每个任务都适用）

1. **梯子顺序**：① 这个修复需要存在吗？② 仓库里已有现成的吗（组件/seam/工具函数）？③ 都没有才写最少的新代码。禁止为单个 bug 建工厂、接口、配置项。
2. **只修根因**：改共享函数一处，不要在每个调用点打补丁。
3. **五条底线不动**（跨法人隔离、模拟标识、来源追溯、幂等、IFRS 16 正式表零写入）。任何修复不得绕过。
4. **替换类改动验收（GUARD-001）**：「把 A 换成 B」必须证明 B 真的生效——把 B 的规则删掉或改错，测试必须红。只证明 A 消失了不算数。
5. 改完跑：

```bash
cd core-service && GOCACHE=$(pwd)/.gocache go test ./... && go vet ./...
cd ../web && npm run type-check && npm run build && npm test && npm run lint
```

## T1 · 四个经营数据页面补可信度标识 【最高优先级】

**问题**：`/promotions`、`/portfolio`、`/performance`、`/retail-data-import` 展示经营/模拟数据但无任何 `data_classification` 标识（grep 0 命中）。这是底线 2 的展示面缺口，不是样式偏好。

**修法（最小 diff）**：
- 直接复用 `<DataTrustBar>`（`web/app/components/DataTrustBar.tsx`），照 `/operating-pulse` 的接法抄。
- 页面数据源没有 classification 字段的，先查后端响应里是否已带（大概率带了只是没渲染）；后端确实没有的，停下来在任务里注明，不要在前端编造标识。

**验收**：
- 四个页面在 simulated 数据下可见分类标识；
- 把 `<DataTrustBar>` 从任一页面摘除，相关断言测试变红（GUARD-001）。

**明确不做**：不给这四个页重做版式、不加新的信任组件变体。

> **2026-08-26 执行注记（T1 停下）：四个页面的后端数据源均不携带 `data_classification` / SourceEnvelope**，逐源核验：
> `/promotions` → `handlers/promotion.go`（0 命中）；`/portfolio` → `services/reporting` 投影（0 命中）；`/performance` → `handlers/operating_facts.go` 的 Overview / StorePerformance / EquipmentPerformance / actions（只有 `basis:"Working"` 与 `source` 元数据，无分类字段）；`/retail-data-import` → `handlers/retail_ingest.go` preview/commit（commit 的 envelope 只含 source_system / import_batch_id / as_of_at）。
> 按本任务约束，不在前端编造标识。**后续专项**：给这些端点接 `services/sourceenvelope.Build`（store-day 读路径已有现成实现可抄），并补上 legacy 读路径对 `data_classification` 的过滤（当前 `/reports/store-performance` 等不过滤，simulated 与 production 行混读——这是比缺标识更实质的底线 2 缺口）。详见《UIUX修复任务书_2026-08-26_执行报告》。

## T2 · 接口层两个小修

**问题 a**：6 处裸 `fetch()` 绕过 `apiRequest`，token 过期时 401 不触发自动刷新，用户看到一次莫名失败：
`web/app/ai-chat/page.tsx:254`、`:1666`、`retail-data-import/page.tsx:60`、`reports/page.tsx:439`、`lib/retail-export.ts:39`（`ai-chat/runtime/transport.ts:60` 是 SSE，豁免）。

**修法**：统一走 `apiRequest`；下载类的走同一个共享 download 缝（`apiRequest` 已有 blob 场景可扩展，或在 `lib/export.ts` 现有缝上加）——**一个缝收拢六处，不要六处各改各的**。

**问题 b**：后端 `errcontract` 的 `rate_limited` code 前端未映射，落到「请求失败」generic 文案。

**修法**：`api.ts` 的 `userMessage` switch 加一个 case + `i18n.ts` 补三语 key（zh-CN / zh-HK / en）。一行分支的事。

**验收**：手动把 token 改过期后调 artifact 导出，自动刷新成功不报错；mock 一个 `rate_limited` 响应，文案是具名的。

## T4 · scope_denied 可区分性复核（只审不改）

**问题**：13 个页面未走 `StateBlock`/`classifyDataState`，权限拒绝是否被软化为「无数据」未知。这触及「权限拒绝必须保持原因」红线。

**修法**：逐页人工核出一张表：`页面 × 权限拒绝时的实际呈现 × 是否可区分于空态`。**本轮只产报告**——发现违规先记下，批量迁移到 StateBlock 是下一个专项，不在这次做（13 页一起动 diff 太大，违反最小 diff 原则）。
