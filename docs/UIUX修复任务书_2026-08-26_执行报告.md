## T1 · 四个经营数据页面补可信度标识 —— **停下（后端无分类字段）**

逐源核验结果：四个页面的**全部**后端数据源都不返回 `data_classification` 或 SourceEnvelope，前端无从渲染，也不允许编造。

| 页面 | 数据源 | 后端证据 |
|---|---|---|
| `/promotions` | `/api/v1/retail/promotions*`（含 ROI / breakeven） | `handlers/promotion.go`、`services/promotionattribution/` 全文 0 命中 |
| `/portfolio` | `/reports/portfolio-summary`、`/reports/unit-price`、`/reports/rent-to-sales` | `handlers/reports.go` → `services/reporting` 投影 payload 无分类字段 |
| `/performance` | `/performance/overview`、`/reports/store-performance`、equipment、actions | `handlers/operating_facts.go` 只有 `basis:"Working"` + `source:{...}` 元数据，无分类 |
| `/retail-data-import` | ingest preview/commit、plan/TB import | commit 的 envelope 仅 `{source_system, import_batch_id, as_of_at}` |

**更实质的发现**：legacy 读路径（如 `/reports/store-performance` 的 `ListStores`）查询 `store_operating_facts` 时**不过滤 `data_classification`**——simulated 与 production 行混读。这比「页面缺标识」更直接地触及底线 2；补标识之前应先修这个。

**后续专项建议**：给上述端点接 `services/sourceenvelope.Build`（`handlers/retail_store_day_facts.go:430` 已有现成接法可抄），读路径加分类过滤，然后再回到本任务把 `<DataTrustBar>` 接进四个页面。

## T4 · scope_denied 可区分性复核 —— **只审不改，报告如下**

机制背景：`classifyDataState` 把 `scope_denied` 独立成第四态且**永不并入 empty**（红线有实现）；但只有走 `useRetailQuery` + `StateBlock` 的页面才吃到这层保护。

| 页面 | 权限拒绝时的实际呈现 | 可区分于空态？ |
|---|---|---|
| audit-logs | seam 第四态 `scope_denied`，但页面只检查 `failed` → **无 toast、无 StateBlock，空表** | ❌ 违规 |
| contracts | 同上（seam 页，连 failed 检查都没有）→ 空表静默 | ❌ 违规 |
| sensitivity | 直调 catch → toast 显示 ApiError 原文（具名文案）；正文保持旧/空 | ⚠️ 部分（toast 可区分，正文不可） |
| admin/users | seam 只查 failed → 空表静默；另有客户端 need_admin 前置拦截（permission_denied 场景已覆盖） | ❌ 违规 |
| todo | seam 只查 failed → 空表静默 | ❌ 违规 |
| ai-chat | 会话列表 hydration `.catch(() => undefined)` 全吞；会话内操作错误走 `apiErrorMessage` 具名呈现 | ❌ 列表层违规 / 操作层达标 |
| promotions | 直调 catch → `err?.message` toast 具名；正文空表 | ⚠️ 部分 |
| cashflow-forecast | 同 promotions（toast 具名） | ⚠️ 部分 |
| portfolio | seam 只查 failed ×2 → KPI 卡显示 0、表格空，**比空态更糟（零填充）** | ❌ 违规 |
| monthly-closing | 多处直调 catch → toast 具名 | ⚠️ 部分 |
| performance | cockpitState 只查 failed → 治理计数全 0、表格空 | ❌ 违规 |
| reports | ledgerState 只查 failed → 空表静默 | ❌ 违规 |
| standards | 直调 catch → toast 具名 | ⚠️ 部分 |

**可达性备注**：当前后端主要在 ai-chat runtime / agent gateway / store_pnl / store-day 写路径发 `scope_denied`；legacy 报表端点多半走 access 过滤静默返回空集或 403 `permission_denied`。所以表中 ❌ 是**结构性风险**（一旦后端把这些路径改成具名 scope_denied 即暴露），不是今天必现的用户可见 bug——这也是它适合单独立项而非顺手改的原因。

**下一个专项的现成修法**：六个 seam 页把 `state.kind === "scope_denied"` 渲染成 `<StateBlock>`（组件已存在、文案已有三语 key），diff 小、模式统一。
