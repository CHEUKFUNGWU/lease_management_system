## B. KPI-001 — 单一 KPI 引擎

### 收进 retail-kpi-v1 的语义（`retailkpi` 包）
- `ChangeRate` / `ChangeRateType`（周期变化率，零对比拒绝、missing 有原因）
- `MinimumPeerCount = 3` + `PercentileRank`（Peer Cohort 资格与分位数）
- `CoverageIncomplete` / `CoverageComplete`（唯一 Fact Coverage 判定）
- `EvaluateStorePeriod`（门店粒度评估入口，four-wall 月度视图经此消费同一语义层）

### K3 谓词收敛（8 处 → 1 处判定）
| 调用点 | 改动前 | 改动后 |
|---|---|---|
| retailkpi:179 | 内联 `Expected>0 && Observed<Expected` | `CoverageIncomplete` |
| retailpulse:606 | 内联（同语义） | `CoverageIncomplete` |
| **store360:242** | **`Observed != Expected`（超额覆盖误降级）** | **`CoverageIncomplete`（缺陷修复）** |
| **store360:252** | **`!=`（bridge 原因）** | **`CoverageIncomplete`** |
| scenario:330 | `len(current) != expected` | `CoverageIncomplete` |
| aiagent:888 | 内联 `Observed < Expected` | `CoverageIncomplete` |

K3 测试 `TestCoverageIncompleteSingleVerdict`：under/exact/**over-coverage**/unknown-expected 五种形态，钉住「observed > expected 不视为不完整」。

### fourwall 修复（K1/K2）
- `max(f.Revenue, 1)` 三处全部移除（K1 grep = 0），`max` 助手删除；
- `CalculateFourWall` 指标改由 `retailkpi.EvaluateStorePeriod` 计算：零营收贡献率 → `null`（K2 单测 `TestFourWallZeroRevenueYieldsNullRatios`）；缺 other_controllable_cost → EBITDA/贡献率 `null`（不再当 0）；租售比含变量租金；经营占用成本率含非租赁成本；break-even 仅在有营收时产出。

### K4 Peer Cohort 统一
`BenchmarkStores` 重写：同 brand+region+**currency**、成员 decision-ready、**排除目标门店自身**、最少 3 家同群否则不产出基准。`TestBenchmarkStoresCohortRules` 覆盖 5 家 CNY 群（各有 4 家同群 → 产出）、2 家 USD 对（各 1 家 → 不产出）、1 家独店（0 家 → 不产出）。store360 的 `MinimumPeerCount` 改为引用 `retailkpi.MinimumPeerCount`；`/performance` 的 `peer_definition` 文案与 `minimum_peer_count` 字段已更新。
