## A. FIX-002 折现率缺失不该报「服务暂时不可用」

### 根因

`SnapshotBuilder.Build` 在第一份缺折现率的合同处即返回 `fmt.Errorf("contract %s: %w", contract.ID, err)`（裸 UUID），而 `ReportHandler.buildSnapshot` 把**所有**快照构建错误一律映射 500。`writeProjectionError` 里既有的 `ErrDiscountRateRequired → 422` 分支只覆盖 projection 阶段，永远轮不到 snapshot 阶段。前端把无 code 的 500 按 `system_failure` 兜底，显示「服务暂时不可用，请稍后重试」+「请求未成功，请重试」。

引擎行为未动：`ResolveDiscountRateValues` 依旧拒绝在无政策、无人工确认时给率（AGENTS.md §Discount Rate 人机协同）。本票只修呈现。

### 改动

**后端**（core-service）：

- 新增 `reporting.DiscountRateMissingError`（`services/reporting/discount_rate_error.go`）：包装 `ErrDiscountRateRequired`（`Unwrap` 保持既有 `errors.Is` 判定全部有效），携带合同编号列表
- `SnapshotBuilder.Build`（`snapshot.go:148-175`）：不再首错即返，**收集全部**缺率合同编号后一次性返回 `DiscountRateMissingError`（编号排序去重前已按合同顺序，sort 保证稳定输出）
- `reporting.projectStandardComparison` / `projectSensitivity`（`projection.go:287,426`）：直接返回点从裸 sentinel 改为带该合同编号的 `DiscountRateMissingError`
- `handlers/reports.go`：`writeDiscountRateMissing` 单一 HTTP 适配器 —— **422** + `writeCodedError(errcontract.CodeDataUnavailable)` + `details: {discount_rate_missing: true, contracts: [...]}`；`buildSnapshot` 与 `writeProjectionError` 都走它

**code 选择理由**：13 个既有 code 里选 `data_unavailable` 而非 `business_failure`。仓库内先例（`handlers/retail_scenarios.go:215-226`）已把「证据/数据条件不满足导致无法产出结论」映射为 `data_unavailable` 422——折现率缺失正是同一语义：**数据条件不满足**，不是业务规则冲突，也不是服务故障。`business_failure` 在 Agent Tool 侧（`agenttools/errors.go`）用于「执行上下文缺失」类硬失败，语义更远。未新增 code。

**前端**（web）：

- `lib/api.ts`：`ApiError.userMessage` 新增 `data_unavailable` 分支（原在 generic fall-through 列表里）。当 `details.discount_rate_missing === true` 时，按 `details.contracts` 渲染合同专属文案；`data_unavailable` 其余形态（如 coverage 降级）保持原 generic 文案不变
- `lib/i18n.ts` 新增三语词条 `api.discount_rate_missing`（带 `{contracts}` 插值）与 `api.discount_rate_missing_no_contracts`（后端列表为空时的兜底）

## B. FIX-003 卡片固定尺寸与数值排版

### 改动

| 项 | 内容 |
|---|---|
| 卡片高度 | `.pulse-kpi-card` / `.store-360-kpi-card`：`min-height: 156px` → **`height: 156px` + `overflow: hidden`**；移动端断点同步 `height: 136px`。同排卡片由布局（等固定高度）保证等高，与内容无关 |
| 数值排版 | 选定方案：**单行不换行**。数值行统一走共享类 `.pulse-kpi-value`（常量 `margin: 12px 0 4px`、`tabular-nums`、`max-width: 100%`）；主数值与币种由统一 formatter（`formatKPIValue`/`displayMetric`）拼成一个字符串，永不拆行 —— 换行造成的高度跳变在物理上不再可能 |
| 超长降级 | `Typography.Title ellipsis={{ tooltip: display }}`：溢出省略号 + **Tooltip 展示完整数值**；change / comparison 两行同样 `nowrap + ellipsis`。三处使用点（pulse 网格、pulse 空态卡、store-360 网格）全部生效 |
| tabular-nums | 数值行类内置；change 行既有 `.pulse-change` 规则已含；本票未新增内联样式（数值行的 `style={{ margin, fontVariantNumeric }}` 内联被移除，改为类） |

金额继续走统一 formatter：`formatKPIValue` → `formatUnitValue`（`operating-pulse/logic.ts`），未在组件里新写 `toLocaleString`。

### 验收 B1–B5 的机械保证方式（任务书要求明示）

「六张卡等高」无法用眼睛确认，本票的机械保证链是：

1. **CSS 契约测试** `web/app/lib/kpi-card-height.test.ts`（5 用例）解析 `globals.css` 与两个页面源码，断言：
   - 两个卡片类都是 `height: 156px` + `overflow: hidden`，且**不含** `min-height`（B1 的样式前提）
   - 移动端断点内两个类都是 `height: 136px` 且无 `min-height`
   - 共享数值类含 `tabular-nums`、常量 margin、`max-width: 100%`（B3）
   - change/comparison 行含 `nowrap + hidden + ellipsis`（B2 的截断降级前提）
   - 两个页面的数值行都渲染 `className="pulse-kpi-value"` + `ellipsis={{ tooltip: display }}`，且旧的内联数值样式已不存在
2. **等高推理**：同一 `Row` 内的卡片高度全部为常量 156px（AntD Col 不改变子元素 height），高度相等由 CSS 盒模型保证——任何一张卡想变高只能改 `globals.css`，而契约测试会立刻失败。
3. **B2（不撑破）**：`overflow: hidden`（卡片级）+ `max-width: 100%` + ellipsis（数值行级）双保险；截断后完整值在 Tooltip。

**需要用户用眼睛确认的部分**：视觉效果（ellipsis 省略号观感、Tooltip 内容、移动端 136px 的呼吸感）与 1440×900 / 390×844 两档视口的整体协调——契约测试保证「等高且不破」，不保证「好看」。
