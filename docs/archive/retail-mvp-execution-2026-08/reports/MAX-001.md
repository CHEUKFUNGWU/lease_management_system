## 设计说明

- 数据版本与幂等：唯一键为 `store_id + business_date + version + source_system`；Repository 使用 `ON CONFLICT DO UPDATE ... RETURNING id`，同一业务键重放不会增加事实行。
- 多租户过滤：写入先通过 `stores` 关联按 `legal_entity_id` 和 `access.Scope` 校验；读取始终 `JOIN stores`，同时应用显式法人参数和门店/区域/品牌范围。
- 模拟来源传播：数据库只允许 `production` / `simulated`；`simulated` 必须有非空 `simulation_dataset_version`，`production` 必须为空。API 信封汇总为 `production`、`simulated`、`mixed` 或空结果 `none`，并始终返回 `simulation_dataset_versions`。
- 向后兼容：没有删除、改名、回填或修改 `store_operating_facts`；新路由和新 Repository 使用独立表，月度 API 未改动。
- 审计：每个 POST 成功写入后调用现有审计 Logger，审计对象固定为 `retail_store_day_facts`；全局管理员场景由审计 Repository 通过门店反查法人主体。
