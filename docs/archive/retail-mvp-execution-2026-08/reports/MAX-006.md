## API 与数据合同

- `GET /api/v1/retail/store-options` 复用 `RetailKPIRepository` 的 population 过滤（法人、active、classification/dataset、现有 region/brand/store scope），按 `store_code, store_id` 稳定排序，只返回门店元数据，不返回金额。
- `GET /api/v1/retail/stores/:store_id/diagnostics` 受 `reports:read`、JWT/TenantMiddleware 和现有数据范围保护；production 禁止 dataset，simulated 强制 dataset；参数错误 400、不可见门店 404、来源冲突 409、Repository 错误 500。
- Service 对 current+comparison 合并范围只调用一次 `RetailKPIRepository.QueryFacts`，内存中完成目标/同群/趋势/桥；集成 counting DB 固定为 population/facts 2 个 Query + source conflict 1 个 QueryRow，无 N+1。
- current=`as_of-(window-1)…as_of`，comparison 为此前等长且不重叠；peer 固定为目标之外、同 brand+region+currency、current `decision_ready=true`、当前授权范围内门店，最少 3 家。
- quantile 使用线性插值 `position=(n-1)*p`，p25/median/p75 为 0.25/0.50/0.75；percentile 为 `(less + 0.5*equal)/n*100`，输入先排序，ties 稳定。

三组桥固定业务顺序且由 API 计算：

1. `revenue_shapley_v1`：`footfall × conversion_rate(decimal) × average_transaction_value`，3! 顺序平均边际贡献；
2. `gross_profit_shapley_v1`：`revenue × gross_margin_rate(decimal)`，2! 顺序平均边际贡献；
3. `store_contribution_additive_v1`：`gross_profit - labor_cost - occupancy_cash_cost - other_controllable_cost`，成本项按对贡献的影响取负。

每组返回 current/comparison/total_change/items/rounding_residual/status/reason；缺失、partial、零分母或覆盖不足不补 0，桥降级为 unavailable。观察文案只说“变化贡献/观察信号/不作解释性判断”，不生成因果或根因断言。
