## B. SEC-003 值类型化

### B0. 关键决策

- **值类型的两态语义如何表达**：`internal/access.EntityFilter`（`global bool` + `id string`，字段私有）。`GlobalEntityFilter()` = 管理员跨法人（SQL 侧**不产出任何法人子句**）；`EntityFilterFor(id)` = 普通用户（拒绝空/空白串，trim 后存储）；`FromScope(Scope)` 由既有 `access.Scope` 构造（Global→global，否则必须有法人，否则报错）。SQL 片段构造器 `SQLClause(column, argIdx)`：scoped 产出 `X.legal_entity_id::text = $N`（**无 OR 分支**），global 返回空。命名贴合 CONTEXT.md 的 Legal Entity Access，未引入 `tenant permission` / `default scope` 等 Avoid 词。
- **零值为什么是安全的（附测试名）**：构造器保证「scoped 必有非空 id」，因此 `var f EntityFilter`（global=false, id=""）与任何合法构造值都不重合；`SQLClause` 与 `LegalEntityID()` 对零值返回错误（失败关闭，绝不退化为不过滤）。测试：`TestEntityFilterZeroValueFailsClosed`（internal/access/entity_filter_test.go）。
- **防回归检查放在哪、怎么跑**：`internal/repository/legal_entity_escape_hatch_regression_test.go`——`TestNoLegalEntityEscapeHatchInRepositorySQL` 扫描 `internal/repository/` 下非测试 .go 源，匹配逃生舱签名 `''\s*OR\s+legal_entity_id`（精确到「空串 OR 法人列」，不会误伤 `access_scope_sql.go` 等合法失败关闭谓词，也不会误伤 approval_status / 币种等非法律谓词）。`go test ./internal/repository/ -run TestNoLegalEntityEscapeHatch` 即可，无 TEST_DATABASE_URL 也能跑（纯静态扫描）。

### B4. 发现的「本就缺少法人过滤」之处

无「本就缺少法人过滤」的新发现（§3.4 第 5 条场景未触发；表征测试改动前即证明隔离成立）。过程中发现以下**预存缺陷**（均未自行修改，仅记录）：

1. **`repository/fpna_governance.go` `UpdateDataQualityStatus` 恒失败**：`SET status=$3 … CASE WHEN $3 IN ('resolved','accepted')` 中 `$3` 被推导为 varchar 与 text 两种类型，pgx 扩展协议下必报 SQLSTATE 42P08（已在 psql `PREPARE` 复现）。Go 调用方 100% 失败。表征测试按「两侧均报错」断言，重构未使其更糟。
2. **`repository/fpna_governance.go` `CreatePlanLine` 恒失败**：`RETURNING created_at` 而 `fpna_plan_lines` 表当前 schema 无 `created_at` 列。
3. **`repository/operating_facts.go` `CreateBatch` 无幂等键时恒失败**：RETURNING 的 `idempotency_key` 未 COALESCE，NULL 扫描报错；生产 handler 恰好总是带上。
4. **范围外残留逃生舱**：`repository/ai_chat_runtime.go:236` `($2 = '' OR COALESCE(legal_entity_id::text, '') = $2)` 是 COALESCE 变体的法人逃生舱，不在本票 5 文件范围内（§3.5.6 红线），防回归测试的精确签名不命中它；建议并入后续「法人值类型」任务收尾。
5. **payload 信任**：`CreateAction`/`CreateMemo`/`CreateScenarioAction` 的幂等查询与 INSERT 使用 payload 的 `legal_entity_id`（`entityFilterForOptional` 保持原语义：nil→Global 无过滤）。跨法人 payload 注入的防护依赖 handler 层校验，未在本票扩大范围。
