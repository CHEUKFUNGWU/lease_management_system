## 1. 一个必须理解对的前提

ADR §Context「What the measurement actually shows」已经量过：

- 回归容差 `1` **不是 float64 造成的**（浮点误差量级 `1e-9`，小九个数量级）；
- **148 条断言的实际差异全部是 `0.00`** —— 代码已经和 Golden 值精确到分相符。

所以现状是**潜在风险，不是当前算错**。

**因此以下说法都是错的，写进报告即退回：**

- ❌「迁移到 decimal 修正了金额计算」——当前没有算错的数
- ❌「迁移让容差得以降低」——容差在 MONEY-001 就降到 0 了，与迁移无关
- ✅ 正确表述：**迁移消除的是逐期递推与聚合场景下的潜在漂移**，并让对账可以精确比较

# 票一：MONEY-001 —— 把回归容差收紧到 0

## 2.1 为什么先做这个

148 条断言实际差异已全是 `0.00`，容差 `1` 是防御性留白。**先降到 0，它就成了后两张票的安全网**——迁移一旦引入任何偏差，立刻失败，而不是藏进 ±1 元的带子里。

## 2.2 必须实现

1. `core-service/internal/services/ifrs16/testdata/ifrs16_regression_cases.json` 顶层 `tolerance` 改为 `0`；
2. 若断言比较逻辑对 `tolerance: 0` 有浮点相等的隐患（`math.Abs(delta) > 0` 在浮点下可能因 `-0.0` 之类边界出问题），一并处理，**但不要改成"约等于"**；
3. 重新生成回归报告（`make ifrs16-regression`），确认仍是 `PASS 22/0`。

## 2.3 明确不做

1. 不改任何计量逻辑；
2. 不改 Golden 期望值；
3. **不动 `review_status: pending_third_party_review`** —— 精确相符不等于第三方背书。

## 2.4 验收

| # | 检查 | 期望 |
|---|---|---|
| T1 | `tolerance` | `0` |
| T2 | `make ifrs16-regression` | **PASS，22 通过 / 0 失败，148 断言** |
| T3 | 报告中「容忍差异」 | `0.00` |
| T4 | 故意把某个 Golden 值改动 `0.01` | 回归**失败**；改回 → 通过。**贴两次输出** |
| T5 | `review_status` | 未改动 |

**T4 是本票的意义所在**：证明这张网真的会兜住东西。

# 票二：MONEY-002 —— 金额接缝

## 3.1 必须实现

按 ADR §Decision 1–6 建立 `core-service/internal/money`：

1. 金额类型，`shopspring/decimal` 为引擎；
2. **舍入策略集中在一处**：half-up、正负对称（`0.005→0.01`，`-0.005→-0.01`）。不要散落成第二个 `round2`；
3. 币种小数位表：默认 2，显式列出 JPY(0)、KWD/BHD/OMR(3)；**精度超出币种允许即报错，不静默舍入**；
4. `sql.Scanner` / `driver.Valuer`，与 `DECIMAL(18,2)/(18,4)/(18,8)` 往返无损；
5. `MarshalJSON` **输出不带引号的 JSON number**（ADR §Decision 6——前端金额字段全是 TS `number`，默认的字符串序列化会静默坏掉前端）；
6. 分摊使用**最大余数法**，保证各部分之和精确等于总额。

## 3.2 守卫：防止未迁移部分恶化

加一条 CI 可执行检查：**新增的金额字段不得是 `float64`**。

沿用 `web/scripts/enforce-design.mjs` 已验证有效的**计数法 + 行级新增**思路（它在上一批的大 diff 下零误报），作用于 Go 侧。字段名词表（`Amount|Balance|Liability|Revenue|Rent|Cost|Interest|Depreciation|Payment|Price|Fee` 一类）**写在一处并可扩展**。

**若词表在既有代码上大量误报，说明词表太宽——收敛词表，不要加豁免名单。**

## 3.3 明确不做

1. 不迁移任何既有字段（那是 MONEY-003）；
2. 不改 schema、不动前端；
3. 不动其余 137 处 `round2` 调用。

## 3.4 验收

| # | 检查 | 期望 |
|---|---|---|
| M1 | 往返精度 | 三种 `DECIMAL` 精度写入→读出**逐位相等**，真实 PostgreSQL |
| M2 | 舍入 | `.5` 边界，**正负各有断言** |
| M3 | JSON | 序列化为不带引号的 number；与现有格式**逐字节一致**（贴对照） |
| M4 | 分摊守恒 | 各部分之和 == 总额，含无法整除情形 |
| M5 | 币种精度超限 | **报错**，不静默舍入 |
| M6 | 守卫生效 | 新增 `float64` 金额字段 → 失败；改成金额类型 → 通过。**贴两次输出** |
| M7 | 守卫不误报 | 当前 main 上通过 |
| M8 | 全量 Go + vet | 通过 |

# 票三：MONEY-003 —— 迁移审计链

4. **逐期递推路径**（`services/ifrs16/calculation.go:222` 一带）必须有测试证明 36 期以上累计无漂移。

## 4.3 验收
