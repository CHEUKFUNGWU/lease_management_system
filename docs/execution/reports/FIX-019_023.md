## 1. FIX-019 全站 Modal 标题栏高 809px（P0）

### 1.1 根因与修复

## 6. SANKEY-001 利润流向桑基图一期（P1）

### 6.1 后端

`GET /api/v1/retail/stores/{store_id}/pl-flow`（`core-service`，permission `reports.read`，与 diagnostics 同查询契约：as_of / window_days / classification / dataset_version / source_system）。

响应（`PlFlowResult`）：
```json
{ "nodes": [{key,label}], "links": [{from,to,value}],
  "currency", "basis": "Working · …", "residual", "status",
  "formula_version": "retail-pl-flow-v1", "missing": [], "reason": "" }
```

**口径**：
- 节点：营业额（单一，不分品类）→ 人工成本 / 租金（fixed+variable 合并）/ 非租赁成本 / 其他可控成本 / 门店贡献
- 门店贡献 = 营业额 − 四项费用（金额是一手 `DECIMAL(18,2)` 字段，**无比率乘回**）
- `status = complete | partial | unavailable`；费用字段在窗口内**任一天缺失** → partial + `missing` 列表（流值只含观测天数，缺失不补零）
- `residual = revenue − Σ(links)`：四项费用整体不可观测（无贡献流）时 = 未归因金额（如全缺 = 整个 revenue）；部分缺失时贡献流按观测费用补平、缺失由 status/missing 表达——**左右不平永不悄悄抹平**
- 多币种冲突 → partial + `reason: currency_conflict`（复用 retail-kpi-v1 语义）

**二/三期注释**（§6.4 三段原文）写入 `pl_flow.go` 接口定义处文件头：二期是数据模型问题（唯一键无品类列、需新事实表 + 新导入链路、POS 按品类出数是商务问题；大类映射复用 mapping_status 三态、未匹配销售额显示为独立流）；三期警告（分摊是判断、与「不作解释性判断」声明冲突、规则须可配置可标注可切回）。

**测试**（`pl_flow_test.go`，3 条）：全字段完整 → complete + 贡献 1400 + residual 0；labor 缺 3 天 → partial + missing=[labor_cost] + 观测值 1200；费用全缺 → 无贡献流 + residual = revenue。

### 6.2 前端

- `api.ts`：`RetailPlFlowResponse` 类型 + `retailAnalyticsApi.plFlow()`（同 storeDiagnostics 校验）
- `store-360/ProfitFlowPanel.tsx`：recharts `Sankey` 渲染（默认节点/链接，token 色），meta 行显示 status / residual（fmtMoney）/ missing / formula；unavailable 与未选门店走 Empty
- store-360 页：独立 `plFlow` effect（与 diagnostics 并行加载），面板置于 BridgePanel 之下
- i18n：`store360.pl_flow.*` 三语

## 7. HELP-001 页面使用教程面板（P2）

### 7.1 流程图选型（任务书要求先说明理由）

**手写 SVG 组件**（`HelpFlowDiagram.tsx`，零依赖）。理由：样板流程是固定线性步骤（3-5 节点），mermaid 的「文本即图」维护优势在此不成立；mermaid 会引入 ~500KB 运行时依赖 + 独立样式面（与 DESIGN token 隔离）。内联 SVG 的节点填充/描边/文本直接走 `var(--...)` token，步骤标签来自 i18n，三语零额外产物。若后续某页教程需要分支/循环，届时再评估 mermaid。

### 7.2 结构

| 件 | 说明 |
|---|---|
| `PageHeader.help` 槽位 | 单开槽位（`page-header-actions` 内独立 `page-header-help` 容器），**不混入** primaryAction/secondaryAction；静默感叹号按钮 |
| `HelpDrawer.tsx` | `HelpTrigger`（按钮 + Drawer）；Drawer 非 Modal（可边看教程边操作，同 RetailAIDrawer 模式） |
| `HelpFlowDiagram.tsx` | 零依赖 SVG 线性流程图（节点 + 箭头，token 色） |
| `help-content.ts` | 独立结构化内容（`pulseHelpContent` / `scenarioHelpContent`），与页面代码分离；文本全走 t() |
| 样板页 | 经营脉搏 + 租金谈判测算（任务书推荐的两页） |

**红线遵守**：合规口径（门店 360 与租金谈判测算的 meta 句）**未收进教程**，保持常驻页面——本票未触碰任何 `meta` 内容。

**浏览器实测**：经营脉搏页 help 按钮 1 个 → 点击 Drawer 打开、SVG 流程图 4 节点、3 个内容段落渲染 ✓。
