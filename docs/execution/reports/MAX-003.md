## 1. 用户可见结果

- `GET /api/v1/retail/kpis/definitions` 返回 KPI 中文名称、英文名称、公式、单位、必需字段、空值规则、零分母规则和 `retail-kpi-v1`。
- `GET /api/v1/retail/kpis/store-days` 按 `total|region|brand|store` 返回日事实聚合。查询必须提供日期、`data_classification=production|simulated`；模拟数据必须提供 `simulation_dataset_version`（同时兼容查询参数 `dataset_version`），生产数据携带模拟版本直接 400。
- 结果只读 `retail_store_day_facts`，按租户及现有 store/region/brand scope 过滤，按 `store_id + business_date + source_system` 取最高事实版本；未指定来源而同一 store-day 有多来源时返回 409 数据质量冲突。
- 总览按 `dimension + currency` 分行，绝不跨币种相加；门店行返回 store id/code/name、brand、region。响应含 `basis=Working`、分类、模拟版本、最高 `as_of`、事实版本范围、来源信封、覆盖率、`multi_currency`、`total_rows` 和定义链接。
- `occupancy_cash_cost = fixed_rent + variable_rent + non_lease_cost` 明确是经营现金占用成本，不读取或写入 IFRS16 折旧、利息、ROU、租赁负债、分录或 Official 表。

## 2. 语义与数据字典

实现位置：`core-service/internal/services/retailkpi/retail_kpi.go`。Golden 定义位置：`core-service/internal/services/retailkpi/testdata/retail_kpi_v1_golden.json`。

加总指标：`revenue`、`gross_profit`、`footfall`、`transactions`、`labor_cost`、`fixed_rent`、`variable_rent`、`non_lease_cost`、`other_controllable_cost`、`occupancy_cash_cost`、`store_contribution`。

比率/效率指标：`gross_margin_rate`、`conversion_rate`、`average_transaction_value`、`labor_cost_rate`、`rent_to_sales_rate`、`occupancy_cash_cost_rate`、`store_contribution_margin`、`sales_per_sqm`、`revenue_per_store_day`，并以诊断字段返回 `average_daily_area_sqm` 和 `distinct_business_days`。

所有 KPI 都返回 `value`、`unit`、`status`、`formula_version`、`required_fields`、`available_fact_count`、`fact_count`。必需字段不完整时正式 value 为 null、status 为 `partial`；零分母为 null、status 为 `unavailable`、reason=`zero_denominator`；空事实集为稳定空信封，不伪造 0。

面积口径为 `SUM(store_day.area_sqm) / distinct_business_days`：每日所有选中门店面积先求和，再按不同经营日平均，禁止把跨日面积直接求和或取任意一行。覆盖率口径为：`expected_store_days = 请求日期天数 × 当前租户/数据分类/模拟版本下的 active 门店数`；`coverage_rate = observed_store_days / expected_store_days × 100`，expected 门店群体由数据库确定，无法确定时保持 null。覆盖响应同时列出 requested/observed dates、observed/expected store-days 和缺失字段。
