## 2. 实现与边界

- `core-service/internal/services/retailpulse/retail_pulse.go` 是独立编排层。它只调用 MAX-003 `RetailKPIRepository.QueryFacts` 一次取得 comparison+current 范围，再在内存调用公开的 `retailkpi.AggregateFacts`；没有复制 KPI 公式。
- `core-service/internal/handlers/retail_pulse.go` 只负责参数校验、租户上下文和错误信封。路由复用 JWT、TenantMiddleware、`reports:read`。
- current 为 `as_of-window_days+1...as_of`，comparison 为前一段紧邻等长日期，二者不重叠；daily trend 只覆盖 current，每个自然日都返回，缺事实日使用 `gap=true`，不补 0。
- `occupancy_cash_cost`、`occupancy_cash_cost_rate` 继续使用经营现金口径；不读取或写入 IFRS16 计量、租赁负债、ROU、月结分录或 Official 表。
- production 禁止 dataset version，simulated 必须绑定 dataset version；响应携带 classification、dataset versions、source systems、最高 `as_of`、`retail-pulse-v1` 和 `retail-kpi-v1`。

## 3. 规则、评分与响应语义

八个固定信号：

| signal_code | 触发条件 | threshold/unit |
|---|---|---|
| `revenue_decline` | current/comparison revenue ≤ -15% | -15 / percent |
| `footfall_decline` | footfall ≤ -15% | -15 / percent |
| `conversion_drop` | conversion rate ≤ -3 pp | -3 / percentage_point |
| `average_ticket_drop` | average ticket ≤ -15% | -15 / percent |
| `gross_margin_compression` | gross margin ≤ -5 pp | -5 / percentage_point |
| `labor_cost_rate_spike` | labor cost rate ≥ +5 pp | +5 / percentage_point |
| `occupancy_cost_rate_spike` | occupancy cash cost rate ≥ +5 pp | +5 / percentage_point |
| `contribution_turns_negative` | comparison contribution ≥ 0 且 current < 0 | 0 / currency |

金额、数量、客单、坪效使用 `(current/comparison-1)*100`；比率使用 `current-comparison`（pp）；comparison 为 0 时 `change_value=null`、reason=`zero_comparison`，不产生无穷大。`store_contribution` 同时返回金额百分比变化及 `change_margin_pp`，没有混淆单位。

每个固定信号贡献 `min(abs(observed/threshold),3)`，权重均为 1；但 `contribution_turns_negative` 是明确的评分例外，命中时固定贡献 +1（不套用阈值相除公式）。总分保留两位，按 score 降序、store code 升序稳定排序。severity 固定为 score ≥6 `critical`、≥3 `high`、≥1 `medium`、其余 `low`（运行时边界断言覆盖 score=1/3/6）。invalid、partial、unavailable 或任一期间覆盖不足的门店不进入排名，而进入 `suppressed_attention`。

## 4. 覆盖率、空事实和多币种

MAX-003 Repository 现在返回 active authorized `StorePopulation`（id/code/name/brand/region），而不只返回数量。Pulse 以该 population 计算 expected store-days；因此 14–56 天请求范围（例如 window=28 的 current+comparison）内整段没有事实的授权门店不会从 facts map 消失：它们会进入 `suppressed_attention`，reason=`no_facts_in_requested_range`，并带 current/comparison expected/observed coverage。若存在事实但期间不完整，reason=`incomplete_store_day_coverage`；无事实的分区仍返回明确 coverage 和 `decision_ready=false`。为兼容只返回 `ExpectedStoreCount` 的旧 reader，服务还保留 `currency_status=unknown` 的 partition-level suppression（不把 `unobserved` 冒充货币，也不伪造门店身份）；零授权门店只返回空 suppression 的稳定 coverage/gap envelope，并有单元测试覆盖。

不同 currency 从不汇总到同一个 summary。每种币种独立返回 `Partition`；当一个门店群体包含无事实授权门店时，suppressed population 会合并到唯一事实币种分区并将该分区降级；多个事实币种则保留各自分区及 `multi_currency=true`。source 未指定且同一 store-day 存在多个来源时，Repository 返回 `ErrRetailKPISourceConflict`，Handler 返回 HTTP 409，不静默选择。
