## 2. 用户能看到什么、完成什么任务

用户在首屏看到经营数据可信条、六项核心 KPI、趋势、辅助指标、优先门店和折叠的数据不足门店。用户可以选择日期/窗口/模式/来源，识别六类固定异常，从 attention 行进入带 `store_id` 的同口径门店脉搏，查看 code/name/brand/region 后返回全部门店；正式数据无事实时得到导入行动空状态，而不是六张伪造的 0 卡片。

## 3. 实现范围与关键证据

### Latest dataset

- `GET /api/v1/retail/simulations/store-days/latest` 已接入 protected route，Repository 按当前 `legal_entity_id`、`status='completed'` 和 `completed_at DESC, created_at DESC, id DESC` 查询；无数据为 HTTP 200、固定 envelope、`data: null`，空法人为 400。
- Handler 单测覆盖空 envelope、数据 envelope、空法人；Repository PostgreSQL 集成 fixture 覆盖法人 A/B、最新 completed 选择和清理。
- 该 GET 只读，不写模拟数据、审计、合同、计量、分录或 Official 表。

### 页面状态修复

- latest discovery 与 Pulse fetch 分离；直接进入 simulated URL 仍加载 latest 以恢复场景选择；latest 失败后刷新会重试 discovery。
- 新 query 发起时清空旧 response，旧响应不能与新筛选同屏；较早请求不会覆盖较新请求。
- 非法 `window_days` 显示可恢复错误，7/14/28 控件可以自救；production 缺少 `as_of` 时规范化为当天。
- anomaly 最晚日期只从 manifest 求 max，空 manifest 才回退 dataset `date_to`；旧 dataset 或 production 不展示不匹配的 generator/anomaly metadata。
- `gap=true` 的趋势值强制为 null、断线并在 tooltip 显示“数据缺口”；箭头按 change 正负显示，rate 指标使用 percent 单位。
- KPI 状态同时检查 current/comparison status/reason；partial/unavailable 显示“部分/缺失”和原因，null 显示 `—`。
- source conflict 409 可通过页面 `source_system` 输入框写入 URL 后重试；生产零事实显示导入行动空状态。
- scoped response 新增 `requested_stores` 元数据合同；即使该店没有 attention，也显示门店 code/name/brand/region，不伪造空白门店。

### 测试覆盖

- 固定六类异常由既有 Pulse service Golden/固定 seed 测试逐项断言 signal、rank、severity、coverage；前端补齐六类 manifest type 的中文映射、URL repeated store scope、7/14/28 round-trip、multi-currency partition、gap 强制 null。
- Attention 变化列展示全部 observed signals 的 observed change、threshold、unit，并以 tooltip 保留 current/comparison；suppressed 仍独立折叠展示。
- `web/app/page.tsx` 与 `web/app/performance/page.tsx` 无 diff；Next build 路由清单保留所有原路由并新增 `/operating-pulse`。
