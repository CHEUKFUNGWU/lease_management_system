## 架构接线与 Tool 合同

```text
retail_operations@v1
  -> 独立 retail runbook / deterministic fallback
  -> Agent Tool Runtime（ExecutionContext tenant + dimension scope + reports:read）
  -> 三个只读 adapter（最多 pulse -> diagnostics -> scenario）
  -> RetailKPIRepository -> retailpulse / retailstore360 / retailscenario
  -> 结构化回答 + 同站 Source + retail_action_proposal Artifact（不写业务表）
```

| Tool | 输入重点 | 权限/级别 | 输出与副作用 |
|---|---|---|---|
| `retail.operating_pulse.read@v1` | `data_classification`、`dataset_version?`、`as_of`、`window_days`、`source_system?`、`store_ids?` | `reports:read` / Read | 已验收 Pulse envelope、coverage/attention/source；`numeric_authority=deterministic_service`、`side_effects=false` |
| `retail.store_diagnostics.read@v1` | 公共上下文 + `store_id` | `reports:read` / Read | 已验收 Store360 target/peer/bridge/evidence；不生成根因；无副作用 |
| `retail.store.scenario.evaluate@v1` | 公共上下文 + `store_id`、`horizon_months`、七项 assumptions | `reports:read` / Read | 服务端重建 Baseline/Plan；`formal_execution=false`、`side_effects=false`；不保存行动 |

四个意图为 `pulse_summary`、`store_diagnostics`、`scenario_evaluate`、`action_draft`。缺少上下文、来源冲突、越权、覆盖不足或不支持的操作均返回稳定 `needs_input`/证据限制，不调用旧 Scenario 或写入业务表。
