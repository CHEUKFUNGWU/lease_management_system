# 票二：MONEY-002 —— 金额接缝 + 守卫（commit `3d41ea9`）

## 实现

- `core-service/internal/money`：`Amount` 以 shopspring/decimal 为引擎；零值不是合法金额（`ErrInvalidAmount`）；
- 舍入策略集中一处：half-up、正负对称（`0.005→0.01`，`-0.005→-0.01`），`Round(currency)` / `RoundTo(scale)`；
- 币种小数位表：默认 2，显式 JPY(0)、KWD/BHD/OMR(3)；`ValidatePrecision` 超限**报错**不静默舍入；
- `sql.Scanner` / `driver.Valuer`：与 `DECIMAL(18,2)/(18,4)/(18,8)` 往返无损（含 pgx 经 `pgtype.Numeric` 送达的扫描路径，见 §共同节-发现 4）；
- `MarshalJSON` 输出不带引号的 JSON number；`UnmarshalJSON` 同时接受数字与带引号字符串；
- `Allocate` 最大余数法分摊，各部分之和精确等于总额；
- 守卫 `core-service/scripts/enforce-money.mjs`：复用 enforce-design 已验证的**计数法 + 行级新增**思路，词表写在脚本一处（`Amount|Balance|Liability|Revenue|Rent|Cost|Interest|Depreciation|Payment|Price|Fee`），只拦截变更行里新增的 float64 金额字段。

## 发现（迁移过程中暴露/修正的问题）

1. **`monthend/fx.go` 符号反转（已修）**：迁移初稿把 `math.Abs(difference)` 写成了 `difference.Neg()`，正差异（汇兑损失）会产出负金额分录——线上格式与语义都会变。给 money 补了 `Abs()`，并还原为 `difference.Abs()`；材料性阈值比较同时简化为一次 `Cmp`。
2. **`principal_repayment` 休眠列**：旧代码从不计算 `PrincipalRepayment`，float64 零值静默写入 0；迁移后未设置的 `money.Amount` 按设计拒绝持久化（`ErrInvalidAmount`），集成测试当场暴露。为保持「表示法迁移不改变业务结果」，显式写 `money.NewFromInt64(0)` 保留旧行为；正确计算（`TotalPayment − InterestExpense`，eventaccounting 路径已有此公式）属于行为票，不在本批。
3. **月度汇总输出随机序**：`aggregateMonthly` 按 map 迭代序返回，每次运行线上字节都不同（旧代码也无法自洽复现）。已改为按年月排序——这是 C6 逐字节对比成立的前提，也让 API 响应与回归报告确定性输出。
4. **pgx 扫描路径**：真实 PostgreSQL 下 pgx 把 `NUMERIC` 以 `pgtype.Numeric` 交给 `Scan`，迁移中补上了「可自渲染为十进制字符串即接受」的路径（M1/C7 的实测依据）。
5. **float64 聚合噪音的线上形态**：月度汇总的 `InterestExpense` 等聚合字段旧输出带 `40.200000000000024` 这类噪音尾数；迁移后为 `40.2`。这是消除潜在漂移的直接证据（C6 量化：35 对，分值全部相等）。
