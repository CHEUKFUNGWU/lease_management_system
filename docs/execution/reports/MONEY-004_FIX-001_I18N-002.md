## B. 会话历史置信度持久化

`ai-chat` 消息的 confidence 此前只在内存（`repository/ai_chat_runtime.go` 0 处引用）。本次：

- `ai_chat_messages` 新增 `confidence DOUBLE PRECISION`、`confidence_reason TEXT`（`db/init/01_init.sql` + 增量迁移 `041_ai_chat_message_confidence.sql`，已应用到运行库）；

# 票三：I18N-002 —— 清理死 i18n key

## 顺序：先让失败变响亮，再删任何东西

### 第一步：保护网（K1/K2）

新增 `web/app/lib/i18n-keys.test.ts`：扫描全部源码，按**四条引用规则**断言每个被引用的 key 都在字典中：

1. `t("字面量")` 与 `t(...)` 内回退字面量（仅限 key 形状，`{ total: "__TOTAL__" }` 这类替换值不算）；
2. **常量表值**：`*_KEYS` / Record map / 字面量数组 / 函数内联 map 的值（`LEASE_SCOPE_KEYS`、`ASSET_TYPE_KEYS`、`REASON_KEYS`、`CRITICAL_DATE_KEYS`、`SCENARIO_LABEL_KEYS`、`KPI_LABEL_KEYS`、`SIGNAL_LABEL_KEYS`、`criticalDateKeys`、`causeKeys`、`labels` 等）——朴素 grep 找不到的间接引用；
3. **模板拼接前缀**（`reports.asset_type_${x}` 保护所有以该前缀开头的 key）；
4. **纯文本出现**（三元表达式等其余形态）。

K1 实测输出（故意加 `t("no.such.key", ...)` 到 `format.ts`）：

