## A. SEC-004（补上逃生舱最后两个口子）

### NULL 法人行在 scoped / global 下的判断与依据

`ai_chat_sessions.legal_entity_id` 可为 NULL。转换后：

- **scoped（非管理员）**：`legal_entity_id::text = $N` 排除 NULL 行——NULL 法人会话没有可归属的 Legal Entity Access，非管理员不可见。与旧 COALESCE 谓词行为一致（`COALESCE(NULL,'') = LE` 恒假）。
- **global（管理员）**：不产出法人子句，NULL 行包含在内——管理员看全部。与旧 `$2=''` 短路行为一致。
- COALESCE 只是为了让 `''` 能与 NULL 行比较，值类型化后「全部」由「无子句」表达，COALESCE 整体消失。S4 集成测试（`TestAIChatSessionTenantFilterNullLegalEntity`）把这两个方向都钉住。

顺带处理：handler 里 `?legal_entity_id=` 查询参数可覆盖租户（web 端从不传，已核实），是用户可控的租户边界输入，值类型下不可表达，移除——filter 一律从请求 scope 构造。

### 放宽后的守卫模式

`''\s*OR\s+[^)]*legal_entity_id`（原为 `''\s*OR\s+legal_entity_id`，漏别名与 COALESCE 形态）。四形态断言：


### 门店搜索的选择与理由

**复用 `masterDataApi.listStores`**（`GET /api/v1/master-data/stores`）。理由：`retailAnalyticsApi.storeOptions` 强制 `data_classification`（production/simulated）语义，对全局导航面板不自然——面板是导航工具不是分析工具，不该把门店搜索绑定到数据分类；master-data stores 服务端按权限 scope 过滤（含空法人失败关闭），返回 code/name/brand/region，天然适合搜索。门店结果跳 `/store-360?store_id=…`。

新增 `web/app/lib/palette.ts` 注册表：`canViewGroup` 镜像 `AppLayout.tsx` useMenuItems（L71-79）的角色规则（daily 全员；analysis = admin/readonly/auditor；accounting = admin/auditor/editor/reviewer/approver；system = admin/auditor，settings 与 admin/users 仅 admin），注释标明「那里是导航的权威实现，这里是面板的镜像」，U2 测试锁住两组语义。21 条业务路由全部登记，`nav.upload` 为新增 key（三语言）。
