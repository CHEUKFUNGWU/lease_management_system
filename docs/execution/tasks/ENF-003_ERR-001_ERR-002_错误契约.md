# 票一：ENF-003 —— 守卫判定改计数法

## 1.1 问题

`enforce-design.mjs` 现在的判定是：

```js
isNewViolation = pattern.test(line) && !pattern.test(oldText)
```

**违规只有在「旧行里没有」时才成立**，于是已经违规的行可以随意加码。评审人实测：

| 注入 | 现状 |
|---|---|
| 往已有 `!important` 的行再加一个 | ❌ 放行 |
| 把既有内联样式从 2 个属性扩写到 5 个 | ❌ 放行 |
| 全新一行加违规 | ✅ 拦截 |

语义从「不得新增违规」漂成了「不得新增违规行」。

**方向本身是对的**——若改到 906 处内联样式所在的行就报错，那些文件无法维护。问题在于判定用了「有 / 无」而不是「多少」。

## 1.2 必须实现

改成**计数比较**：该行违规出现次数比旧行增加即失败。

```js
const count = (s, re) => (s.match(new RegExp(re.source, re.flags + "g")) || []).length;
// 新行次数 > 旧行次数 → 失败
```

内联样式按**静态属性个数**比，不是按 `style={{` 出现次数。

## 1.3 验收

| # | 检查 | 期望 |
|---|---|---|
| N1 | 往已有 `!important` 的行再加一个 | **拦截** |
| N2 | 既有内联样式从 2 属性扩到 5 属性 | **拦截** |
| N3 | 仅**触碰**含存量违规的行（不增加数量，例如改颜色值） | **放行**（不得误报） |
| N4 | 全新一行加违规 | 拦截 |
| N5 | 当前 main 上跑 | 通过 |

**N3 是本票的关键**——如果改成计数后触碰存量行开始误报，就把上一批好不容易解决的问题又带回来了。**五条都要贴输出。**

# 票二：ERR-001 —— 后端错误契约

## 2.1 问题（架构改善方案候选 01）

HTTP 接缝**没有错误接口**：`core-service/internal/handlers/` 有 **824 处** `gin.H{"error": "自由文本"}`，而 Web 层期望的是 code。

前端 `web/app/lib/api.ts` 的 `ApiError.userMessage` 分支在这五个 code 上：

```
invalid_token · unauthorized · forbidden · not_found · network_error
```

**后端一个都不发。** 结果是所有具体原因在接缝处被丢掉，一律退化成通用文案。

**最要命的一条**：`scope_denied`（权限拒绝）到了界面上变成通用「没有权限」甚至「暂无数据」——而 AGENTS.md 明令 `scope_denied` 不得被软化。这条规则目前**没有任何东西在保证**。

## 2.2 关键设计约束：不要发明第三套词汇

模块**已经存在**，在 Agent 接缝上：`core-service/internal/agenttools/errors.go` 的 `ToolError`，带 13 个稳定 code：

```
invalid_arguments · unauthenticated · permission_denied · scope_denied
review_required · capability_denied · business_failure · system_failure
timeout · cancelled · not_found · conflict · data_unavailable
```

**这套词汇就是标准答案。** 把它抬升为共享模块，HTTP 与 Agent Tool 变成**同一套 code 之上的两个适配器**。

⚠️ **前端现有的五个 code 名（`invalid_token` / `unauthorized` / `forbidden` / …）与这套不一致。以 Agent 那套为准，前端在 ERR-002 里适配。** 不要为了迁就前端造第三套名字，也不要在两套之间做映射表——那等于保留了两套词汇。

## 2.3 范围严格限定：只做零售这条纵向

824 处全改不是一张票能做的事，**本票只转换三个零售页实际调用的 handler**：

| 文件 | 错误站点 |
|---|---|
| `retail_pulse.go` | 12 |
| `retail_store_diagnostics.go` | 13 |
| `retail_scenarios.go` | 25 |
| `retail_kpis.go` | 12 |
| `retail_store_day_facts.go` | 17 |
| `retail_simulations.go` | 10 |
| **小计** | **89** |

其余 735 处**本票不动**。选这一组是因为它们构成一条完整纵向：ERR-002 正好消费它们，能端到端验证契约真的贯通。

## 2.4 必须实现

1. 把 `ToolError` 的 code 词汇抬升为共享错误模块（放在 `internal/` 下合适位置，不要留在 `agenttools` 里被 HTTP 反向依赖）；
2. 该模块拥有：code 词汇、`retryable`、`details`、**内部细节脱敏**（不得把 SQL、堆栈、内部路径透给客户端）；
3. HTTP 适配器：把错误编码成 `{"code": "...", "error": "...", "details": {...}}`，并保持既有 HTTP 状态码不变；
4. Agent Tool 适配器：行为不变（它已经在用这套）；
5. 转换上表 89 处；
6. **`scope_denied` 必须端到端存活**——从仓储/服务一路到 HTTP 响应体，不得被降级成 `not_found` 或 `data_unavailable`。为此单独写测试。

## 2.5 明确不做

1. 其余 735 处错误站点；
2. 不改任何 HTTP 状态码（本票只加 code，不动状态码语义）；
3. 不动 `agenttools` 的对外行为；
4. 不动 `web/`（那是 ERR-002）。

## 2.6 验收

| # | 检查 | 期望 |
|---|---|---|
| R1 | 全量 `go test ./...`（带 `TEST_DATABASE_URL`）+ `vet` | 通过 |
| R2 | 89 处已转换 | `grep -c 'gin.H{"error"' core-service/internal/handlers/retail_*.go` = **0** |
| R3 | 其余站点未动 | 全仓计数 = **824 − 89 = 735** |
| R4 | `scope_denied` 端到端 | 构造越权请求，**响应体 `code` 为 `scope_denied`**；贴实际响应 |
| R5 | 状态码未变 | 转换前后同一请求的 HTTP 状态码一致，抽 5 例对照 |
| R6 | 脱敏 | 构造一个数据库错误，响应体**不含** SQL 片段或内部路径；贴响应 |
