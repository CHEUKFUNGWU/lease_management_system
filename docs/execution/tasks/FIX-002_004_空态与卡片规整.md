# 票一：FIX-002 —— 折现率缺失不该报「服务暂时不可用」

## 1.1 现象

打开 `/portfolio` 弹出两个 toast：「请求未成功，请重试。」「服务暂时不可用，请稍后重试。」页面所有指标为 0。

实际接口返回：

```
GET /api/v1/reports/portfolio-summary → HTTP 500
{"error":"contract aaaaaaaa-…: discount rate requires policy matching or human confirmation"}
GET /api/v1/reports/unit-price       → HTTP 500（同一错误）
```

## 1.2 引擎行为是对的，呈现是错的

`services/contracts/discount_rate.go:10` 的 `ErrDiscountRateRequired` **完全符合** AGENTS.md：「AI 不得猜测折现率，缺失时必须触发 human-in-the-loop」。

库中两份合同 `CT-LE001` / `CT-LE002` 的 `discount_rate_policy_id` 与 `discount_rate_confirmed_at` 均为 NULL —— 无政策匹配、无人工确认，引擎拒绝计算是**正确**的。

**错的是它被当成服务器故障：**

| 现状 | 应改为 |
|---|---|
| HTTP **500** | **422**（数据条件不满足，不是服务故障） |
| 「服务暂时不可用，请稍后重试。」 | 指明哪份合同缺折现率，并说明要做什么 |

**500 +「请稍后重试」让用户去重试一个永远不会成功的操作。** 真正该做的是补合同的折现率。

## 1.3 必须实现

1. `ErrDiscountRateRequired` 在 HTTP 层映射为 **422**，带 ERR-001 的错误 code（从既有 13 个里选，**不要新增**；语义上 `business_failure` 或 `data_unavailable` 更贴切，选哪个在报告里说明理由）；
2. 错误 `details` 带上**是哪些合同**（合同编号，不是裸 UUID）；
3. 前端据此显示可行动文案：缺折现率的合同、以及去哪里补。文案走 `t()`，三语齐全；
4. `ErrDiscountRateRequired` 全仓有 **5 条调用路径**，一并检查是否都落在同样的 500 上。

## 1.4 明确不做

1. **不要给合同填一个折现率把问题绕过去** —— 那正是 AGENTS.md 禁止的猜测；
2. 不改 `ErrDiscountRateRequired` 的触发条件；
3. 不转换 `/reports` 其余错误站点。

## 1.5 验收

| # | 检查 | 期望 |
|---|---|---|
| A1 | 折现率缺失时两个端点 | **422** + code + `details`，贴实际响应 |
| A2 | `details` 内容 | 含合同编号（`CT-LE001` 这类），不是裸 UUID |
| A3 | 前端文案 | 说明缺什么、去哪补；**不含「请稍后重试」** |
| A4 | 5 条调用路径 | 逐条说明现状与处理 |
| A5 | 折现率齐全时 | 行为不变 |
| A6 | 全量 Go + vet + web 验证 | 通过 |

# 票二：FIX-003 —— 卡片固定尺寸与数值排版

## 2.1 现象

`/operating-pulse` 六张 KPI 卡高度参差：「销售额 49,669.45 CNY」数值加币种换行成两行把卡撑高，「毛利率 31.51%」一行放得下就矮一截。

当前样式只有：

```css
.pulse-kpi-card { min-height: 156px; }
```

只约束最小高度，**没有固定高度、没有数值排版规则**。

## 2.2 必须实现

1. **同一行卡片高度一致**，不因数值长短或换行而参差；
2. **数值与币种排版规则**：主数值与币种不得因换行造成高度跳变（币种缩小同行、或独立一行但高度恒定 —— 选一种并统一）；
3. 数值一律 `tabular-nums`（DESIGN.md §4.3），金额走统一 formatter；
4. 极长数值有明确降级（缩写或截断 + tooltip），**不允许撑破卡片**；
5. 规则同时适用于 `pulse-kpi-card` 与 `store-360-kpi-card`（共 3 处使用点）。

## 2.3 验收

| # | 检查 | 期望 |
|---|---|---|
| B1 | 六张 KPI 卡高度 | 相等（渲染高度断言或可验的 CSS 契约） |
| B2 | 超长数值 | 不撑破卡片，有降级 |
| B3 | `tabular-nums` | 所有数值位生效 |
| B4 | 无新增内联样式 | `enforce-design` 通过 |
| B5 | web 全套验证 | 通过 |

# 票三：FIX-004 —— 空态不产生幽灵滚动条

## 3.1 现象

`/portfolio` 的「每平米月租对比」在无数据时，表格下方仍有一条横向滚动条，宽度随容器伸缩。

原因：

```tsx
scroll={{ x: 900 }}    // portfolio/page.tsx:248
scroll={{ x: 1120 }}   // portfolio/page.tsx:305
```

写死了横向滚动宽度，**接口失败或无数据时表格是空的，那个 900px 虚拟宽度仍在**。

## 3.2 必须实现

1. `scroll` 只在**确实有数据行**时生效；空态不产生滚动区域；
2. 空态使用统一空状态呈现，说明为什么没有数据（现有的「暂无可比数据：请先为合同填写租赁面积」保留，并让它成为空态主体，而不是躲在滚动条上方）；
3. 全仓 `scroll={{ x` 共 **22 处、8 个文件**。本票**只修 `/portfolio` 的 2 处**，其余记入报告供后续统一处理 —— 不要顺手全改。

## 3.3 验收

| # | 检查 | 期望 |
|---|---|---|
| C1 | 空数据时 | 无横向滚动条，测试断言 |
| C2 | 有数据时 | 滚动行为不变 |
| C3 | 空态文案 | 说明原因，可读 |
| C4 | 未越界 | 其余 20 处 `scroll={{ x` 未改动，报告列出清单 |
| C5 | web 全套验证 | 通过 |
