## 1. 三条必须先理解对的设计约束

### 1.1 中间栏首屏**不是**空的输入框

用户提出参照 Codex / Claude Code 的布局，Planner 采纳了三栏骨架但**明确否决了空 prompt 首页**（UIUX 方案 §8.1），两条理由：

- **任务性质不同。** 编码任务每次都不一样，所以空输入框合理；经营晨检每天问的是同一个问题（「昨天哪儿出问题了」）。让分析师每天重复打同一句话，比现在的仪表盘更低效。
- **会承诺后端给不了的能力。** `retail_operations@v1` 只有**三个只读 tool**，action proposal 明确不落业务表。空 chat 首页会诱导用户下达执行类指令，而系统只能回建议。

**中间栏首屏是 Agent 自动跑出来的「今日经营简报」**，底部常驻 composer 支持追问。

### 1.2 角色决定中间栏放什么

`AppLayout.tsx:78` 的既有规则：

```
canViewAnalysis  = admin || readonly || auditor
canViewAccounting = admin || auditor || editor || reviewer || approver
```

**`editor` / `reviewer` / `approver` —— 每天做合同与月结的财务角色 —— 没有经营分析权限。** 若首页一律渲染经营简报，他们会得到一个自己点不进去的页面。

因此中间栏必须**角色感知**：

| 角色 | 中间栏首屏 |
|---|---|
| 有经营分析权限 | 今日经营简报（Agent 自动生成） |
| 仅会计权限（editor/reviewer/approver） | 以其工作队列为主的内容，**不是空简报也不是权限错误** |

右栏对所有角色一致。

### 1.3 增量叠加：现有首页内容一张不能少

现有 `/` 的四类内容（待复核合同 / 待过账分录 / 临近关键日期 / 月结就绪度 / 总租赁负债 / 本月租赁费用）**全部迁入右栏，不得删减**。

复用既有组件，**不要重写**：`components/dashboard/DashboardCards.tsx`（`DashboardHeader`、`MoneyKPICard`）、`DashboardLists.tsx`（`UpcomingDatesCard`、`WorkQueueSummaryCard`）。

# 票二：HOME-002 —— 今日经营简报

## 3.1 必须实现

1. **页面加载即由 Agent 跑一次经营晨检**，输出带引用编号的卡片流；
2. **复用已有组件，一个都不要重建**：

   | 用途 | 组件 |
   |---|---|
   | 可信度 | `<DataTrustBar>` |
   | 工具调用 | `<ToolChip>` |
   | 推理轨迹 | `<ThinkingTrace>` |
   | 引用来源 | `<SourceCitation>` |
   | 置信度 | `<ConfidenceBadge>` |
   | 严重度 | `<SeverityDot>` |

3. **角色感知**（§1.2）：会计角色渲染其工作队列视图，不渲染简报、不报权限错误；
4. 底部常驻 composer，追问复用既有 AI 路径（`RetailAIDrawer` 已验证的调用方式）；
5. **三态必须都有**：无数据（正式数据无事实）、非 decision-ready、权限不足。`scope_denied` 按 AGENTS.md **如实显示**，不得软化成「暂无数据」。

## 3.2 自动执行的代价要控制

首屏自动跑一次 pulse 是**每次打开首页都会发生的真实查询**。

- 同一会话内重复进入首页**不应重复跑**（复用既有缓存/请求门控思路，如 `operating-pulse/requestGate.ts`）；
- 加载中要有明确状态，不得白屏。

|---|---|---|
| B1 | 首屏自动产出简报 | 无需用户输入 |
| B2 | 复用组件 | 无重复实现（grep 确认无第二套可信度/引用/置信度渲染） |
| B3 | 角色感知 | admin / readonly / auditor / editor / reviewer / approver 六种角色各有断言 |
| B4 | 三态 | 无数据 / 非 decision-ready / `scope_denied` 各有测试，`scope_denied` 文案不含「暂无数据」 |
