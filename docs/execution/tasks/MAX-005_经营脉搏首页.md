## 1. 用户与页面唯一任务

目标用户是负责多门店晨检的零售经营负责人。页面唯一任务是：在两分钟内确认数据是否可信、整体经营发生了什么、应先看哪家门店，并进入该门店的同口径脉搏。

### 用户能看到什么

- 新增 `/operating-pulse` 模块首页：当前期与前一等长周期、核心 KPI、每日趋势、异常门店优先级、被数据质量抑制的门店及完整来源状态；
- production/simulated、Working、数据集版本、来源系统、公式版本、覆盖率和 decision-ready 始终可见；
- 模拟环境下可选择固定异常场景，清楚显示“模拟数据，不进入 Official”；
- 原有 `/`、`/performance`、合同、IFRS 16、月结、报表、Agent 等所有页面和入口继续存在。

### 用户能完成什么经营任务

- 选择截至日期和 7/14/28 天窗口，完成一次“整体表现—趋势—异常门店”的经营晨检；
- 从异常榜点击门店，在同一页面按该 `store_id` 重新查询并查看单店脉搏，再一键返回全部门店；
- 在没有真实客户数据时，由有权限的用户明确点击生成固定 seed 演示数据，并稳定复演六类异常；
- 识别数据缺口、来源冲突、零分母和 coverage 不足，不把缺失值误读为 0 或正常。

## 3. 最小支撑 API：最新模拟数据集发现

为避免刷新后丢失 dataset version，新增只读接口：

```text
GET /api/v1/retail/simulations/store-days/latest
```

- 权限：`reports:read`，沿用 JWT、TenantMiddleware；空法人返回 400；
- 只查询当前法人最新 `completed` 数据集，排序必须确定（`completed_at DESC, created_at DESC, id DESC`）；
- 有数据时返回 `basis=Working`、`data_classification=simulated`、`source_system=retail_simulator`，以及 `dataset_version`、`generator_version`、seed、date_from/date_to、store_count、fact_count、status、anomaly_manifest、completed_at；
- 无数据时返回 HTTP 200 和同一稳定信封，`data=null`；不得用 404 制造错误页；
- 不返回其他法人记录，不修改生成器，不新增 migration，不写审计；
- 为 Repository 和 Handler 补真实或可验证的法人 A/B、无数据、稳定排序、空法人测试。

保留原 POST 生成接口。前端只有在“无模拟数据集”空状态中，才对具备 admin 角色的用户显示“生成固定演示数据”按钮；必须由用户点击，禁止页面加载时自动写入。调用默认空 payload，并使用稳定 `Idempotency-Key=max-005-retail-sim-v1-default`；成功后使用响应中的 dataset version 加载 Pulse。非 admin 显示联系管理员的行动说明。

## 4. 前端 API 合同与状态

在 `web/app/lib/api.ts` 增加类型化 `retailAnalyticsApi`（名称可等价但必须聚合本模块）：

- `latestSimulationDataset(token)`；
- `generateDefaultSimulation(token)`；
- `operatingPulse(params, token)`；
- 查询参数必须用 `URLSearchParams`，多个 `store_id` 用 repeated keys，不手工拼接；
- 为 dataset、coverage、KPI value、summary metric、daily trend、signal、attention、suppressed attention、partition、pulse response 定义 TypeScript 类型；业务组件禁止以 `any` 代替响应合同。

页面 URL 是可复现状态源，至少支持：

```text
data_classification
dataset_version
as_of
window_days
store_id（可重复）
```

- 默认无 URL 参数：优先查最新模拟数据集；有数据时显式进入 simulated，默认场景选择 anomaly manifest 中结束日期最晚的一项，而不是服务器当前日期；无数据时进入引导空状态；
- simulated 必须携带 dataset version；production 禁止携带；
- production 模式由用户明确切换，as_of 默认当天且允许手工选择；无生产事实展示可行动空状态；
- 窗口只允许 7/14/28；切换筛选更新 URL 并重新请求；刷新后恢复相同视图；
- 请求竞态必须防护，较早响应不得覆盖较新筛选；保留上一次有效结果或明确 skeleton，禁止闪出全 0；
- 409 source conflict、403、5xx、网络错误分别给出可行动提示；禁止吞错。

## 5. 页面信息架构

沿用 `PageHeader`，标题“经营脉搏”。推荐结构如下，不得改成全屏 Hero：

```text
PageHeader                                      [刷新]
[数据模式] [模拟场景/截至日期] [7|14|28天] [全部门店/单店]
[经营数据可信条：模拟/正式 | Working | coverage | source | formula]
[销售额] [毛利额] [毛利率] [客流] [转化率] [门店贡献]
[趋势：指标切换，占 2/3]          [辅助指标，占 1/3]
[优先关注门店表：rank/severity/store/signals/change/score/source/action]
[数据不足而被抑制的门店（折叠，含明确 reason）]
```

### 5.1 KPI 与格式

- 第一行固定六项：revenue、gross_profit、gross_margin_rate、footfall、conversion_rate、store_contribution；
- 辅助指标：average_transaction_value、labor_cost_rate、occupancy_cash_cost_rate、store_contribution_margin、sales_per_sqm；
- 每项显示 current、comparison 变化、正确单位和 status；percent change 显示 `%`，percentage-point 显示 `pp`，二者不得混用；
- money/客单/坪效带当前 partition currency；多币种用币种 Tabs/Segmented 切换，禁止跨币种求和；
- `value=null` 显示 `—` 和 reason/status，不得转成 0；partial/unavailable 不能使用“正常”视觉；
- 正负变化颜色必须结合经营方向：收入、毛利、客流、转化、客单、贡献下降为不利；人工/占用成本率上升为不利。颜色之外同时显示箭头/文字，不能只靠颜色。

### 5.2 趋势

- 使用现有 Recharts；默认展示销售额，可切换本票 API 提供的趋势指标；
- gap 必须断线或空点并在 Tooltip 标为“数据缺口”，禁止补 0；
- 图表标题、轴、Tooltip、单位与当前币种/指标一致；移动端可横向适配但不得溢出页面；
- 不发起额外 KPI 请求，所有内容只消费一次 Pulse 响应。

### 5.3 Attention 与轻量单店下钻

- 按 API rank 原序展示，不在前端重算 score、severity 或排序；
- signal 用中文业务标签，同时保留 code 在 tooltip/详情中；显示 observed change、threshold、unit；
- 行操作“查看门店脉搏”把该行 `store_id` 写入当前页面 URL 并重新请求 Pulse；页面显式显示门店 code/name/brand/region 和“返回全部门店”；
- 这只是同口径 scoped pulse，不实现同群对比、根因拆解或完整门店 360（留给 MAX-006）；
- suppressed attention 默认折叠，展开后必须显示门店和全部 reason；不得把 suppressed 行混入正常榜单；
- attention 为空时写“当前筛选下未触发固定经营信号”，不能写“经营正常”。

### 5.4 数据可信条和状态

- simulated 使用 `StatusTag`/Alert 明确“模拟数据 · 不进入 Official”；production 也明确来源；
- 展示 current/comparison 日期、两段 observed/expected store-days、coverage rate、decision-ready、source systems、dataset/generator version、pulse/formula version、fact version min/max、highest_as_of；
- decision-ready=false 时置于内容之前警示，并说明 KPI 可用于查看但不可作为完整判断；
- `basis=Working` 必须可见，禁止出现 Official 暗示。

## 6. 模拟用户验收脚本

没有设计伙伴，使用以下固定脚本代替访谈；Executor 必须逐项执行并在报告记录 actual：

1. **首次进入（无数据）**：当前法人无 dataset 时，用户理解缺什么；admin 可点击生成，非 admin 获得明确下一步；无自动写入。
2. **固定异常晨检**：生成默认 60×181 数据后，无额外配置进入 simulated；选择六个 anomaly manifest 场景，分别可看到 002–007 对应关注信号。
3. **可信度判断**：用户在首屏能辨认 simulated、Working、current/comparison、coverage、source、formula；没有任何 Official/IFRS 16 数字混入。
4. **异常下钻**：从榜单进入门店后 URL 含 store_id，summary/trend/attention 都只来自该店；返回全部门店恢复原视图。
5. **异常数据状态**：无 facts、coverage 不足、partial/unavailable、zero comparison、409 source conflict 均不显示假 0 或“正常”。
6. **兼容性**：通过新首个分析导航进入页面；原 `/`、`/performance` 及全部旧导航仍可访问且内容未改。
