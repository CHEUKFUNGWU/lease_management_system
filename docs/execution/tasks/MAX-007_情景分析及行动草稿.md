## 4. 确定性情景数据合同

新增零售纵向 API；允许复用 `retailstore360.Service`、`RetailKPIRepository`、既有 action repository，但不得修改旧 API 的行为。

### 4.1 Evaluate API

```text
POST /api/v1/retail/stores/:store_id/scenarios/evaluate
  ?data_classification=production|simulated
  &dataset_version=...
  &as_of=YYYY-MM-DD
  &window_days=7|14|28
  &source_system=...
```

权限：`reports:read` + JWT + TenantMiddleware + region/brand/store scope。

请求：

```json
{
  "horizon_months": 12,
  "scenarios": [
    {
      "key": "baseline",
      "name": "Baseline",
      "assumptions": {
        "revenue_change_pct": 0,
        "gross_margin_rate_change_pp": 0,
        "labor_cost_change_pct": 0,
        "fixed_rent_change_pct": 0,
        "variable_rent_rate_change_pp": 0,
        "non_lease_cost_change_pct": 0,
        "other_controllable_cost_change_pct": 0
      }
    },
    {
      "key": "plan",
      "name": "Plan",
      "assumptions": {}
    }
  ]
}
```

冻结规则：

- 必须恰有一个只读 `baseline`，且所有 delta 为 0；至少有一个非 baseline Plan；最多 4 个情景；key 唯一、顺序稳定；
- `horizon_months` 仅允许 3、6、12；MVP 默认 12；
- pct 输入范围 `[-100, 300]`；pp 输入范围 `[-100, 100]`；计算后的 gross margin rate 和 variable rent rate 必须在 `[0,100]`，超出直接 422，不静默 clamp；
- 所有输入必须是有限数；NaN/Inf、未知字段、重复 key、缺 baseline 均拒绝；
- 仅当目标门店 current period `decision_ready=true`、单币种且所需 KPI complete 时可运行；partial/no facts/zero denominator/currency conflict 返回 422 稳定 reason 和 evidence，不补 0；source conflict 为 409；参数错误 400；越权/不存在门店 404；Repository 失败 500。

### 4.2 Baseline 口径

从 MAX-006 同一 current window 的正式 KPI 生成 30 日 run-rate，不接受客户端上传“基准事实”：

```text
factor = 30 / current_observed_store_days
monthly_revenue = current revenue × factor
monthly_gross_profit = current gross_profit × factor
gross_margin_rate = current gross_margin_rate
monthly_labor_cost = current labor_cost × factor
monthly_fixed_rent = current fixed_rent × factor
variable_rent_rate = current variable_rent / current revenue × 100
monthly_variable_rent = current variable_rent × factor
monthly_non_lease_cost = current non_lease_cost × factor
monthly_other_controllable_cost = current other_controllable_cost × factor
monthly_occupancy_cash_cost = fixed + variable + non-lease
monthly_store_contribution = gross_profit - labor - occupancy - other
store_contribution_margin = contribution / revenue × 100
```

- `current_observed_store_days` 必须等于 expected，且只允许 7/14/28；
- 30 日 run-rate 必须在 API 和 UI 明示，不冒充自然月 Actual 或 Forecast；
- 经营占用现金成本继续与 IFRS 16 折旧、利息、ROU、负债分列。

### 4.3 Plan 计算公式

```text
revenue' = base_revenue × (1 + revenue_change_pct/100)
gross_margin_rate' = base_gross_margin_rate + gross_margin_rate_change_pp
gross_profit' = revenue' × gross_margin_rate'/100
labor' = base_labor × (1 + labor_cost_change_pct/100)
fixed_rent' = base_fixed_rent × (1 + fixed_rent_change_pct/100)
variable_rent_rate' = base_variable_rent_rate + variable_rent_rate_change_pp
variable_rent' = revenue' × variable_rent_rate'/100
non_lease' = base_non_lease × (1 + non_lease_cost_change_pct/100)
other' = base_other × (1 + other_controllable_cost_change_pct/100)
occupancy' = fixed_rent' + variable_rent' + non_lease'
contribution' = gross_profit' - labor' - occupancy' - other'
contribution_margin' = contribution' / revenue' × 100
monthly_contribution_change = contribution' - baseline contribution
horizon_contribution_change = monthly_contribution_change × horizon_months
```

- 金额在最终输出 round half away from zero 到 2 位；中间计算不得逐步 round；百分比输出 4 位；
- revenue'=0 时 contribution margin 为 null + `zero_denominator`，不得为 0；
- 每个结果返回 baseline/result/delta、单位、status/reason；
- 返回贡献变化桥，固定项与符号：gross profit `+Δ`、labor `-Δ`、fixed rent `-Δ`、variable rent `-Δ`、non-lease `-Δ`、other `-Δ`；合计与 monthly contribution change 守恒至 0.01，残差单列；
- 不输出 NPV、市场租金、IFRS 16 影响或“最优方案”。旧 store decision engine 继续保留，但本页不得混用其 relocation/landlord/market assumptions。

### 4.4 Evaluate 响应

稳定信封至少含：

- `basis=Scenario`、`scenario_version=retail-store-scenario-v1`、`formula_version=retail-kpi-v1`、`diagnostics_version`；
- `side_effects=false`、`review_required=true`、`official_impact=false`、`ifrs16_impact=false`；
- store identity、classification/dataset/current window/currency；
- baseline、scenario results、bridge、horizon；
- evidence：source systems、dataset、fact min/max、highest_as_of、coverage、required fields、KPI drilldown URL、request assumptions；
- 排序与输入一致；同一事实和输入返回相同数值，`generated_at` 除外。

Evaluate 只读，整个请求只允许一次 `QueryFacts`，不得 N+1，不得写任何表。

## 5. 行动保存

### 5.1 API

新增：

```text
POST /api/v1/retail/stores/:store_id/scenario-action-drafts
```

查询参数与 evaluate 相同；权限 `fpna_actions:write`。请求至少含：

```json
{
  "horizon_months": 12,
  "selected_scenario": { "key": "plan", "name": "Plan", "assumptions": {} },
  "title": "Store 006 人工排班改善行动",
  "planned_action": "复核高峰时段排班并形成调整建议",
  "owner_name": "",
  "due_date": null,
  "verification_period": "2026-07"
}
```

- 必须提供 `Idempotency-Key`；同法人同 key 重放返回同一 action，payload 不一致必须 409，不得静默接受；
- 服务端必须重新读取同一事实并重算 selected scenario，不信任客户端 result/expected benefit；
- 写入仅限现有 `fpna_action_items`，不新增 migration；status 固定 `open`，category 固定 `retail_store_scenario`，verification status `not_due`；
- Owner、Due Date 可空，系统不得自动分派；title/planned_action 必填且长度受限；
- `baseline_amount=baseline monthly contribution`、`target_amount=plan monthly contribution`、`expected_benefit=horizon contribution change`（允许负数，不伪装为收益）；currency 使用目标门店币种；
- evidence 保存 store、classification、dataset/source、current window、fact/metric/scenario version、baseline、assumptions、server result、bridge、KPI drilldown URL、`formal_execution=false`；
- source table/record 指向 `retail_store_day_facts` 和目标 store；不得伪造 contract/event reference；
- 成功返回 `basis=Scenario`、`formal_execution=false`、`review_required=true`、`data` 和 `idempotent_replay`；
- 只允许该 action 表新增一行；不得写 scenario 到 Official/Budget/Forecast，不得创建租赁 event、改变合同或调用 Agent。

### 5.2 UI 行为

- 未运行成功情景前不能保存行动；
- 默认仅展示本地草稿预览；用户显式点击“保存到行动清单”并二次确认后才调用 API；
- 保存成功显示 action ID、status=open、Owner/Due Date，并提供“前往经营工作台查看”链接；
- 重试复用同一 idempotency key；修改任一 action/scenario 字段后生成新 key；双击/网络重试不得重复创建；
- 不提供“立即执行、自动排班、自动改价、通知房东、创建租赁事件、过账”等按钮。
