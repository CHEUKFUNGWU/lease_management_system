# 票一：SEC-002 —— 首个管理员引导路径

## 2.1 问题

仓库中**不存在任何种子用户创建路径**：

```
admin_user / testuser / user_le001 / user_le002
  → db/init/01_init.sql:  0 处
  → db/migrations/:       0 处
  → scripts/:             0 处
grep 'password123'（排除 _test.go） → 无结果
```

叠加两个事实：

- `handlers/auth.go` 的 `Register()` **无条件返回 403**（公开注册已关闭）；
- `AdminCreateUser` 需要一个**已认证的管理员**。

**结论：执行 `make reset-db` 或 `docker compose down -v` 后，数据库没有任何用户，且没有任何路径能创建第一个用户——系统进入不可登录、不可引导的状态。** 这也是为什么 SEC-001 评审阶段禁止重置环境。

## 2.2 必须实现

新增 `core-service/cmd/bootstrap-admin/`，与既有 `cmd/` 下的五个入口同构。

行为要求：

1. **凭据只从环境变量读取**，至少 `BOOTSTRAP_ADMIN_USERNAME`、`BOOTSTRAP_ADMIN_EMAIL`、`BOOTSTRAP_ADMIN_PASSWORD`。任一缺失即退出并说明。
2. **仓库中不得出现任何默认密码或示例密码**。`.env.example` 只放空值占位与注释。
3. **仅在系统中不存在任何用户时才执行**；已存在用户时必须拒绝并以非零码退出，错误信息说明系统已引导过。这条保证命令可安全重复执行，不会被拿来提权。
4. 创建的用户：`is_active = true`，关联 `admin` 角色（role id `11111111-…`），`legal_entity_id` 留空（管理员的正规形态）。
5. `user_roles.assigned_by` 可为 NULL —— 首个管理员没有指派人，直接留空，不要自引用。
6. 密码哈希**必须复用** `handlers/auth.go` 现有的哈希方式，不要另写一套。
7. 退出码：成功 0；参数缺失、系统已引导、数据库错误各用不同的非零码，并在 README 中列出。

# 票二：SEC-003 —— 法人过滤的值类型化

## 3.1 目标

把「查询忘记加法人过滤」从**运行期静默泄漏**变成**编译期错误**。

当前 38 处查询使用 `($N='' OR legal_entity_id::text=$N)`，空串即不过滤。SEC-001 已在入口挡住空串，但这只是运行期约定；本票要让这个写法**写不出来**。

分布（已核实，集中在 5 个文件）：

| 文件 | 逃生舱数 | 现有测试 |
|---|---:|---|
| `repository/fpna_governance.go` | 15 | **0** |
| `repository/operating_facts.go` | 14 | **0** |
| `repository/retail_store_day_facts.go` | 4 | 1 |
| `repository/budget.go` | 3 | **0** |
| `repository/renewal_decisions.go` | 2 | **0** |

## 3.2 关键设计约束（写错这里会锁死管理员，或把哨兵换个马甲请回来）

**值类型必须是两态的，不能只是「非空字符串」。**

管理员（Global）合法地需要"不加法人过滤"。如果值类型只表达"一个非空法人 ID"，你会被迫在某处重新引入一个特殊值来表示"全部"——那就是把 `''` 哨兵换了个名字。

正确形状是一个封闭的两态类型，示意（具体命名与实现自定，但语义必须是这两态）：

```go
// access 包内
type EntityFilter struct {
    global bool
    id     string
}

func GlobalEntityFilter() EntityFilter                  // 管理员：不加法人子句
func EntityFilterFor(id string) (EntityFilter, error)   // 普通用户：拒绝空串与空白串
func FromScope(s Scope) (EntityFilter, error)           // 由既有 access.Scope 构造
```

配套一个 SQL 片段构造器：Global 时**不产出任何法人子句**，非 Global 时产出 `legal_entity_id = $N`（不再有 `OR` 分支）。

**零值必须是安全的。** `var f EntityFilter` 若被误用，应导致拒绝或明确错误，绝不能退化成"不过滤"。请在报告中说明你如何保证这一点，并为此写一个测试。

**术语**：CONTEXT.md 已定义 `Legal Entity Access` 与 `Data Scope`。命名请贴合，不要引入 `tenant permission`、`default scope` 这类 `_Avoid_` 词。

## 3.3 顺序要求（这条是硬的）

**4 个文件零测试。在无测试代码上直接做 38 处重构不可接受。**

必须分两步，且体现为两个 commit：

1. **先写表征测试（characterization tests）**：针对 5 个文件中现有的法人过滤行为，补真实 PostgreSQL 集成测试，证明「A 法人读不到 B 法人数据」在**改动前**就已成立。参照 `repository/retail_store_day_facts_postgres_integration_test.go` 的既有写法与清理约定。
2. **再做值类型替换**：替换后同一批测试必须继续通过，不得修改测试断言来迁就实现。

Reviewer 会检查这两个 commit 的先后顺序与测试 diff。**若第二个 commit 改动了第一个 commit 里的断言，本票直接退回。**

## 3.4 必须实现

1. 在 `internal/access/` 新增值类型与 SQL 片段构造器（§3.2）；
2. 5 个文件的 38 处逃生舱全部替换；相关 repository 方法签名由 `legalEntityID string` 改为值类型；
3. 调用方（handlers）改为从 `access.Scope` 构造该值类型，不再直接传 `middleware.GetTenantID(c)` 的裸字符串；
4. 加一条 CI 可执行的防回归检查（脚本或测试均可）：`internal/repository/` 下再次出现 `= '' OR` 形状即失败。这是编译期约束之外的实际兜底；
5. 若替换过程中发现某处查询**本就缺少法人过滤**（不是逃生舱，是根本没有），**停下来在报告里单列**，不要顺手补 —— 那是新的安全发现，需要 Reviewer 判断影响面。

2. 不动 `middleware.RequireTenant()`（SEC-001 的成果，保持不变）；
