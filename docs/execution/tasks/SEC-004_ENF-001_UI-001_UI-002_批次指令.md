# 票一：SEC-004 —— 补上逃生舱的最后两个口子

## 1.1 背景

SEC-003 消除了 38 处 `($N='' OR legal_entity_id::text=$N)` 并加了防回归守卫。评审复核发现两处未闭合，**两者合起来才构成「逃生舱不可重现」的完整闭环**。

## 1.2 必须实现

### A. 第 39 处逃生舱

`core-service/internal/repository/ai_chat_runtime.go:236`

```sql
AND ($2 = '' OR COALESCE(legal_entity_id::text, '') = $2)
```

这是真实的法人逃生舱，`COALESCE(` 卡在 `OR` 与字段名之间，所以 SEC-003 的清单漏掉了它。危害略高于普通形状：`COALESCE(legal_entity_id::text, '')` 使 `legal_entity_id IS NULL` 的行在 `$2=''` 时**同样命中**，两个方向都漏。

改用 SEC-003 已建立的 `access.EntityFilter`，与其他 38 处同样处理。**注意这张表的 `legal_entity_id` 可为 NULL**，替换时必须想清楚 NULL 行在 scoped 与 global 两种过滤下各应如何表现，并在报告里说明你的判断依据。

### B. 守卫的盲点

`core-service/internal/repository/legal_entity_escape_hatch_regression_test.go` 现在的模式是：

```go
regexp.MustCompile(`''\s*OR\s+legal_entity_id`)
```

Reviewer 实测四种形态：

| 形态 | 现状 |
|---|---|
| `($2='' OR legal_entity_id::text=$2)` | ✅ 捕获 |
| `($2='' OR v.legal_entity_id::text=$2)` | ❌ 漏 |
| `($2='' OR l.legal_entity_id::text=$2)` | ❌ 漏 |
| `($2 = '' OR COALESCE(legal_entity_id::text, '') = $2)` | ❌ 漏 |

别名形态不是假想——被 SEC-003 替换掉的原代码里就存在 `v.` / `l.` / `s.` 前缀。放宽模式（例如 `''\s*OR\s+[^)]*legal_entity_id`），并**为上表四种形态各写一个断言**，证明放宽后全部捕获。

## 1.3 明确不做

1. 不动 SEC-003 已完成的 38 处替换；
2. 不改 `access.EntityFilter` 的公开接口；
3. 不动 `web/`；
4. 不改 schema；
5. 交付报告里 B4 列出的 5 处预存缺陷（`UpdateDataQualityStatus` 42P08 等）**本票不修**，它们另有票。

## 1.4 验收

| # | 检查 | 期望 |
|---|---|---|
| S1 | `go test ./... && go vet ./...`（带 `TEST_DATABASE_URL`） | 通过 |
| S2 | 守卫对四种形态的断言 | 四条全部存在且通过 |
| S3 | 逐一注入四种形态 | 守卫**每一种都失败**；移除后恢复。**贴四次失败 + 一次恢复的输出** |
| S4 | `ai_chat_runtime.go` 的 NULL 法人行为 | 有测试覆盖 scoped 与 global 两种过滤 |
| S5 | 真实库 `-count=2` | 两轮通过，零残留 |
