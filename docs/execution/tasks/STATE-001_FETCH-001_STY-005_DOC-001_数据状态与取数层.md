## 1. 背景：一个晚上撞到四次的同一个形状

用户在一次走查里报了六个问题，其中四个是**同一个病**：

| 用户看到的 | 真相 |
|---|---|
| 「没有找到桑基图」 | 接口 404（后端镜像未含新路由），被 `.catch(() => setPlFlow(null))` 静默吞成空白面板 |
| 「请求的数据不存在或已被移除」（门店 360 切正式数据） | 库里正式数据本来就是 0 条，simulated 10,860 条 |
| 「加载标签数据失败」（设置页） | 待复现，但该页两块政策阈值都还空着 |
| 「请求未成功（/calculate）」（合同详情） | 该合同付款计划 0 条，IFRS 16 无从算起 |

**四个都是「没有数据」被呈现成「出错了」，或反过来「出错了」被藏成「什么都没有」。**

UIUX 方案阶段二做了 `<StateBlock />` 的空/载/错三态，但那是**呈现层**。缺的是**判定层**：谁来决定这一次到底是空、是错、还是「需要你先去做某件事」。上面四处的正确答案全是第三种。

## 2. STATE-001 数据状态的判定与表达（**P0**）

### 2.1 建立三分法

定义一个共享的判定结果，页面不再各自 `if (error) ... else if (!data) ...`：

| 状态 | 含义 | 呈现 |
|---|---|---|
| `empty` | 请求成功，事实为空 | 空态 + 说明为什么空 |
| `actionable` | 请求成功或失败，但**用户能自己解决** | 空态 + **明确的下一步动作（带入口）** |
| `failed` | 真异常，用户无能为力 | 错误态 + 原因 + 重试 |

判定放在一个纯函数里（跟 `classifyHomeBrief` 同一个套路，那是仓库里已有的先例），**不要放进组件**。

### 2.2 先落到这四处

| 位置 | 现在 | 应该 |
|---|---|---|
| 门店 360 · 正式数据无事实 | 红色「请求的数据不存在或已被移除」 | `actionable`：「正式数据下没有该门店的经营事实。切换到模拟数据，或先导入正式数据。」+ 切换按钮 |
| 合同详情 · 无付款计划时算 IFRS 16 | 「请求未成功（/calculate）」 | `actionable`：「该合同还没有付款计划，无法计量。去添加付款计划」+ 跳到付款计划页签 |
| 设置页 · 标签数据加载失败 | 红色 toast | **先复现取证**（贴 URL / status / code / body），再按三分法归类 |
| store-360 · pl-flow 失败 | 已在 FIX-024 修好，作为**参考实现** | — |

### 2.3 ⚠️ 拦坑

- **不要为了「不报错」而把异常 catch 掉显示空白**。那是把可信度问题藏起来，直接退回。`failed` 必须仍然显眼。
- `scope_denied` **不得**并入 `empty` 或 `actionable`，它永远是权限拒绝，保持原因（AGENTS.md 既有红线）。
- 判定函数必须能区分「后端说没有」和「请求没打通」——这两个在今晚被混为一谈了整整一小时。

### 2.4 验收

```
web: npm test -- state
```
纯函数单测覆盖三种状态 × （成功空 / 404 / 422 / 500 / 网络失败）矩阵；四处落点各有一条断言。报告里贴设置页那处的复现取证表。

## 8. 提前拦坑（本批通用）

1. **`next dev` 与 `next build` 共用 `.next`**：跑完 build 会覆写正在运行的 dev server 的 chunk，页面卡「加载中…」且 chunk 404。**这不是代码 bug**，重启 dev server 即可。顺序是「先 build 后重启 dev」。
2. **改了后端就必须重建镜像**。今晚「没有桑基图」的真相就是路由在代码里、不在运行的二进制里（`strings ./api | grep pl-flow` 得 0）。前端 dev server 热更新会让人误以为整个栈都是新的。
3. **容器端口必须与前端 dev 默认值一致**：`api.ts` 默认 core `http://localhost:8080`、AI `http://localhost:8081`。带 `.env` 起容器会把 core 顶到 18080，dev 模式下前端直连后端、代理不参与，于是全站「网络连接失败」。要保端口又要保密钥就用 `CORE_PORT=8080 AI_PORT=8081 docker compose --env-file <path> up -d`（shell env 优先级高于 --env-file）。
4. **`JWT_SECRET` 变了要重新登录**，那不是 bug。
5. **不要用 `!important` 解决级联**，见 STY-005。
6. **测试断言不许是恒真的全文正则**。FIX-021 的教训：`expect(css).toMatch(/\.selector[\s\S]*?property/)` 会跨 69 行命中无关规则。用精确取规则体的辅助函数。自检句：**把修复改回去，这条测试会不会红？不会红就是没写对。**
7. 全批次：**不得删除或隐藏任何既有页面、路由、API 与 IFRS 16 能力**（转型执行看板规则 11/12）。
