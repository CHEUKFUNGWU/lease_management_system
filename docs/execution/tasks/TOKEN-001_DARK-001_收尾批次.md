## 2. TOKEN-001 颜色 token 化（**P0，DARK-001 的硬前置**）

### 2.1 为什么暗色不能直接做

实测：

```
:root 里的颜色变量      16
globals.css 硬编码 hex  27
tsx 里硬编码 hex        14
tokens.ts 里的 hex      37
```

**颜色还没有完全 token 化。** 直接做暗色，等于要在 78 处散落的硬编码上再叠一套值 —— 那不是「加一个主题」，那是把同一个问题复制一遍。阶段一刚证明了这种债会怎么发作。

### 2.2 要求

1. **语义命名，不是色值命名**：`--bg-page` / `--fg-primary` / `--border-default` 这类（仓库已有一部分），不要 `--gray-100`。暗色主题要能换掉的是语义槽位，不是色阶表。
2. `tokens.ts` 的 37 处 hex 是**唯一真源**，`globals.css` 的变量从它派生；`tsx` 里 14 处直接写 hex 的一律改成变量。
3. **图表颜色单独成组**（`--chart-*` 已有先例），因为暗色下图表配色不是简单反转。
4. 本票**不改任何视觉**：迁移前后每个元素的 computed color 必须逐一相等。

### 2.3 ⚠️ 拦坑

- **并 token 不改值**（FIX-034 的教训，阶段一批次里重演过一次）。值不同就分开写，哪怕看起来「差不多」。
- AntD 的颜色要通过 `theme.ts` 的 token 走，不要在 CSS 里去覆盖它 —— STY-007 刚把 114 处这种覆盖清掉。

### 2.4 验收

```
web: npm test
web: node scripts/enforce-design.mjs
```

外加：**硬编码 hex 计数归零**（三处各自的计数改动前后对照），以及**至少 10 个代表性元素的 computed color 迁移前后逐一相等**的实测表。这一条是本票的成败判据 —— 它是纯重构，任何视觉变化都是缺陷。

## 6. DARK-001 暗色模式（P1，**依赖 TOKEN-001**）

方案阶段四的验收原文：**暗色下对比度全部 ≥ 4.5:1**。

**要求**：

1. `ThemeProvider` 目前只是 `ConfigProvider` + `antdTheme`。加暗色：CSS 变量的暗色一套 + AntD 的 `theme.darkAlgorithm`。

3. **图表配色单独处理**，不要指望反转能work。

**⚠️ 拦坑**：

- 状态色（成功/警告/错误）在暗色下不能简单调暗，要重新取值保对比度。
