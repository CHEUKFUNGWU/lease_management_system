## P0 — 合并阻塞（9 项）

### P0-1 finmodel definition 跨法人校验缺失（底线 1）

- **位置**：`core-service/internal/handlers/finmodel.go` 的 run 执行路径（约 :512 `GetModelDefinition` 后无 `defRow.LegalEntityID != tenant` 校验；对比同文件 :709-726 `scopedRun` 有校验，是正确先例）
- **问题**：A 法人用户拿到 B 法人 definition id 即可执行 run，并以 B 的 entity 落 run 行
- **要做**：所有按 definition id 进入的 handler（run / read / export / publish）统一走带法人校验的 scoped 读取，仿 `scopedRun`；拒绝时保持 `scope_denied` 原因原文
- **验收**：跨法人访问的正反测试（A 法人 token 请求 B 法人 definition → 403/404 且原因不软化）

### P0-2 单店 P&L 的 lease/occupancy 端口无法人过滤（底线 1）

- **位置**：`repository/monthly_closing.go` `ListMeasurementResultsByStorePeriod`、`repository/payment_schedule.go` `ListOccupancySchedulesByStore` 只按 `store_id` 查；`handlers/store_pnl_adapters.go`（约 :298/:339）接口收不到 legalEntityID；`handlers/store_pnl.go`（约 :152）Projection 不校验门店归属
- **问题**：知道对方门店 id 就能读到跨法人门店的 IFRS 16 区块金额与占用成本合同拆分
- **要做**：两个端口加 legalEntityID 参数并下推到 SQL；Projection 入口校验门店 ∈ 请求者法人及 Data Scope
- **验收**：跨法人门店 id 请求被拒绝的测试；既有法人内功能回归绿

### P0-3 出厂模板 Actual 区毛利来自假设而非事实（规格 S2-3 / 附录 C7）⚠️ 埋雷级

- **位置**：`core-service/internal/finmodel/template/defaults.go:53` —— `gp` 行公式 `rows.rev * rows.gross_margin_rate` **全期间生效**
- **问题**：规格要求 Actual 区只读自事实层（`retail-kpi-v1` 聚合）。现状下真实数据的 Actual 期毛利 = 收入 × 假设毛利率 ≠ 事实毛利，T13 勾稽在 Actual 期几乎必失败 → **任何真实数据跑出来的 run 都永远无法通过发布门禁**
- **要做**：link 行与公式行的求值做期间切换——Actual 冻结线左侧从 FactReader 取事实值，右侧才应用驱动公式。检查出厂模板**全部** Actual 相关行（rev/gp/labor/fixed_rent/variable_rent/non_lease/other），不止 gp 一行
- **验收**：Golden 测试加一组「Actual 期事实值 ≠ 假设推导值」的输入，断言 Actual 期输出等于事实值；T13 在 Actual 期对真实事实聚合通过

### P0-4 勾稽恒真与桩：T2 / T4 / T11 重设计 + 反向测试补齐（规格 §9、S2 验收）

- **位置**：`core-service/internal/finmodel/tieouts.go`
- **问题三条**：
  - **T2 恒真**：BS `cash` 行是 `cf.ending_cash` 的别名（`template/defaults.go` 的 `resolveCfAliases` 机制），T2 拿别名比自己，永远相等
  - **T4 恒真**：`cfo` 公式即 `net_income + dna + delta_nwc` 定义式，T4 倒减必等
  - **T11 是桩**（:227-237）：所有路径都返回 `not_applicable`；且最后一个分支用 `total_assets` 上期 vs 本期互比——这既不是期初连续性检查，逻辑上也比错了对象。T11 的语义是「Opening BS_t = Closing BS_{t-1}，逐行，容差 0」
- **要做**：勾稽存在的意义是「两条独立路径算出来的数必须相等」。逐条重设计：T2 改为「CF 内部计算的期末现金」 vs 「BS 资产端独立求和路径中的现金构成」对照，或按 D-S5 的构造语义重新定义检查对象（现金由 CF 回填是构造保证，则 T2 应断言构造本身的输入一致，而不是断言别名相等）；T4 同理，比较 IS 的净利润行与 CF 起点行是否**同一行源**（行源引用断言）而非数值倒推；T11 实现逐 BS 行的 opening_t = closing_{t-1} 真实比较。**如果某条勾稽按构造必然成立，就改规格把它表述为构造断言**（PRD 附录 B 同步修订），不要留一个假装在检查的恒真检查
- **验收**：T1–T16 **十六条每条至少一个反向测试**（当前缺 T2/T4/T6/T8/T11/T15）；每个反向测试先证红、修复后证绿；PRD 附录 B 若有表述修订，随同一 PR 提交

### P0-5 期初闸失败处理方向反了（规格 S2-3）

- **位置**：`core-service/internal/finmodel/engine.go:210-227` —— 闸失败被降级为 `openingMissing`（追加 Gap，run 继续）
- **问题**：规格明确区分两种情形——「未提供期初」→ BS/CF 降级不可判定（run 继续）；「提供了期初但闸不通过」→ **阻止运行**（期初带病，后面每期都是错的）。代码把后者也当成了前者
- **要做**：run 入口区分 `openingAbsent`（未提供，降级路径）与 `openingRejected`（闸失败，Run 返回错误、不落库）；三道闸各自的失败都要走阻止路径
- **验收**：闸失败时 run 不存在、handler 返回具名错误；`opening/` 包三道闸的反向测试（d05f65d 已有，需扩展到引擎入口语义）

### P0-6 T9 利息列报政策开关是惰性的（规格附录 B T9）

- **位置**：`core-service/internal/finmodel/engine.go:91` 开关只校验非空并进快照；`template/defaults.go:106` CF 公式固定 `cfe = borrowings_delta − lease_principal − dividends`，租赁利息永远隐含在 CFO 的净利润里
- **问题**：开关取 operating / financing 不改变任何数字——政策参数是假的
- **要做**：实现两个分类的真实分支：financing（CAS 实务）时利息从 CFO 剔除（加回净利润后单列或经 ΔWC 调整）并计入 CFE「分配股利、利润或偿付利息支付的现金」；operating（IAS 7 选项）保持现状。注意 T2 现金守恒在两分支下都必须成立
- **验收**：同一输入分别在两个政策下跑 run，CFO/CFE 金额不同且 T1/T2 全过；缺开关值时 run 拒绝启动（已有，保持）

### P0-7 模拟标识未贯穿导出 + publish 不闸 classification（底线 2）

- **位置**：`core-service/internal/storepnl/xlsx.go` `RenderXLSX` 全文无 classification 标记（`StorePnl.Classification` 字段可用未用）；`web/app/store-pnl/page.tsx:293` 前端 CSV 无标识；`handlers/finmodel_export.go:55` 有模拟标红（正确先例，自相矛盾）；publish 路径不闸 `data_classification`——simulated run 可发布为 plan version 草稿且谱系里不带标识

- **验收**：导出文件含标识的测试；simulated run publish 被拒的测试

### P0-8 AI 工具生产接线被 nil 注册挡住（SM7 / commit 1d67dd6 声明落空）

- **位置**：`core-service/internal/aiagent/agent.go:103-112` **无条件**注册三个 nil 端口工具（`NewStatementModelReadDefinition(nil)` 等）；:123-138 的 else 分支再注册真实 adapter 时，`registry.Register` 重名报错，被 `if err == nil` 吞掉 → 生产环境永远是「unavailable」版。:101-102 的注释（「生产接线随工作台落地」）是上一 commit 的陈旧注释

### P0-9 假设草稿幂等是假的（底线 4 / SM5）
