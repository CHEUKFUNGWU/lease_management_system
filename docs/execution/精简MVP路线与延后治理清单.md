# 线下零售经营分析工作站：精简 MVP 路线与延后治理清单

状态：待确认  
Owner：Planner / Reviewer  
Executor：Max  
日期：2026-08-12

## 1. 执行原则

- 产品功能优先，资源按 **70% 用户可见功能、20% 数据与测试、10% 安全审计** 分配；
- Audit 在 MVP 只保留不妨碍经营产品开发的最小控制；
- 纯治理工作只有在阻断数据正确性或租户隔离时，才允许进入当前关键路径；
- 每票必须说明用户能看到什么、能完成什么经营任务，并提供可重复验收证据；
- IFRS 16 保留为隔离的正式台账与占用成本数据域，不再作为经营工作站的信息架构中心。
- 转型以原产品为底座做增量扩展；既有合同、租赁计量、月结、报表、页面、API 和 Agent 能力全部保留。专项 UI 任务可将经营分析页面放到导航与工作入口前排，但保留原入口且沿用整体 UI 架构和排版。

## 2. 不能降低的五条底线

1. **跨法人隔离**：写入、查询、批次引用和 Agent 工具调用均不得跨法人泄露或污染；
2. **模拟/正式数据区分**：数据库、API、导出和 UI 必须明确标识，混合数据必须显示 `mixed`；
3. **来源追溯**：事实至少可追溯到来源系统、来源记录、导入批次、数据集版本和生成时间；
4. **重复导入保护**：同一业务键或请求幂等键重试不得产生重复事实，冲突载荷必须被识别；
5. **IFRS 16 正式台账隔离**：模拟经营事实和 Agent 建议不得进入 Official 报表、会计计量、过账或锁账路径。

## 3. 精简 MVP 主路径

### M0 — MAX-001：Store-day 日事实底座收尾

- 用户能看到：production/simulated/mixed 来源信封、数据集版本、来源和法人范围内事实；
- 用户能完成：安全导入、重试和读取门店日经营事实；
- 通过条件：代码可编译；增量迁移和空库初始化安全；法人隔离；模拟标识；基础幂等；来源追溯；IFRS 16 路径无回归；自动测试通过。

### M1 — MAX-002：固定 seed 的模拟数据生成器

- 用户能看到：可选择 seed、日期范围和门店数量的一键生成结果，固定 seed 重跑得到相同数据；
- 用户能完成：在没有设计伙伴和真实客户数据时，创建可复演的正常、季节性和异常经营场景；
- 通过条件：默认 60 店；固定日历和数据集版本；至少包含销售、毛利、交易、客流、面积、人工和占用成本；预埋可解释异常；重复生成受幂等保护；全量标记 simulated；不得触达 IFRS 16 正式台账。

### M2 — MAX-003：核心经营 KPI 与 Golden 对数

- 用户能看到：销售额、毛利额/率、客流、交易数、转化率、客单价、坪效、人工成本率、占用成本率、门店贡献等统一指标；
- 用户能完成：按集团、区域、品牌、门店和时间比较经营表现，并理解指标口径；
- 通过条件：每个 KPI 有公式、粒度、空值/零分母规则和数据来源；生产与模拟口径一致；Golden 数据集有确定预期值；自动对数测试通过。

### M3 — MAX-004 / MAX-005：经营脉搏 API 与首页

- 用户能看到：KPI 卡、趋势、异常门店榜、数据新鲜度和数据分类状态；
- 用户能完成：完成一次每日经营晨检，识别优先调查的指标和门店并进入下钻；
- 通过条件：默认视图无需配置即可用；筛选条件一致；所有图表可追溯到 KPI 口径和事实范围；空状态、模拟状态和混合状态清楚；固定数据集结果可重复。

### M4 — MAX-006：门店 360 与异常下钻

- 用户能看到：单店趋势、同群对比、销售驱动拆解、人工与占用成本、异常证据链；
- 用户能完成：回答“哪家店异常、何时开始、与谁相比、最可能由什么驱动”；
- 通过条件：从首页一跳进入门店；至少支持客流×转化×客单价拆解和毛利/人工/占用成本解释；同群定义透明；所有数字可回到来源事实。

### M5 — MAX-007：情景分析及行动草稿

- 用户能看到：假设参数、基线、情景结果差异、敏感项和待审批行动草稿；
- 用户能完成：评估客流、转化、客单、毛利率、排班人工和占用成本变化，并形成可编辑的行动建议；
- 通过条件：假设与正式事实分层存储；结果可重复；不把相关性描述成因果；行动只生成草稿，不自主回写外部系统或正式台账。

### M6 — MAX-008：AI 经营分析 Agent

- 用户能看到：带指标口径、数据范围、引用、模拟标识、置信度和下一步建议的回答；
- 用户能完成：用自然语言完成“发现异常—下钻解释—运行情景—生成行动草稿”；
- 通过条件：只调用受权限和法人范围约束的工具；数字由确定性 KPI 服务计算；回答引用可打开；低证据时明确不确定性；MVP 只读调查和草稿生成，不自动执行高影响动作。

### M7 — MAX-009：端到端演示与发布验收

- 用户能看到：从固定 seed 数据集到行动草稿的一条完整演示路径；
- 用户能完成：独立完成一次经营晨检、异常下钻、情景比较和行动草拟；
- 通过条件：Golden 场景端到端通过；关键页面可在干净环境启动；五条底线有自动化证据；已知限制明确展示。

## 4. MVP 最小安全与审计控制

- JWT、现有权限和法人过滤继续生效；
- 写入保留最小操作留痕：操作者、时间、对象、动作、来源/批次；
- 导入使用业务键和请求幂等键保护；
- 模拟、生产及混合状态贯穿数据库、API、UI 和导出；
- Agent 默认 Assist Mode，仅调查、解释、模拟和生成行动草稿；
- 用 Golden 测试保护核心 KPI，用跨法人正反测试保护租户隔离。

这些控制是 MVP 门槛；不要求当前阶段达到财务审计级回放或证据包完整性。

## 5. Hardening Backlog（不阻塞当前 MVP）

| ID | 延后项 | 何时重新进入关键路径 |
|---|---|---|
| HARD-001 | 经营事实与审计事件强原子事务、更新前后值完整 diff | 外部审计/合规要求，或出现事实落库但留痕失败的实际风险 |
| HARD-002 | 门店/区域/品牌级细粒度审计查询权限 | 开放更多区域角色或将审计页面交付客户前 |
| HARD-003 | 完整审计回放、不可变 checkpoint 与证据包 | 客户要求可复演决策/模型过程或进入受监管场景前 |
| HARD-004 | 审计保留期、归档、WORM/防篡改和哈希链 | 正式合规合同明确保留及不可篡改要求时 |
| HARD-005 | 高影响行动的多级审批、外部系统回写和补偿事务 | Agent 从行动草稿升级到执行模式前 |
| HARD-006 | Agent 红队、提示注入专项、漂移监控和模型变更审批 | 接入真实客户数据或开放客户自定义工具前 |
| HARD-007 | 大规模审计检索、导出性能、冷热分层与长期容量治理 | 实际数据规模或 SLA 证明需要时 |
| HARD-008 | 审计专用细粒度资源权限重构 | 最小现有权限不能满足客户组织分工时 |
| HARD-009 | 将 Retail KPI/Pulse 多个位置参数收敛为类型化查询对象 | 参数继续增加、调用方超过两个或出现错位缺陷时 |
| HARD-010 | 将 requested scope 与 drilldown 响应收敛为共享类型化 DTO | MAX-006/Agent 需要复用同一范围合同或前后端发生漂移时 |
| HARD-011 | 将 Pulse 指标公式、变化类型和显示元数据集中注册 | 指标集扩展或规则版本升级前 |
| HARD-012 | AI Chat 响应式测试由 helper/常量自证升级为真实渲染 DOM、hover/focus、Drawer 关闭回焦契约 | 下一次改动 AI Chat 会话布局或引入组件级测试基础设施时 |

## 6. 当前明确不做

- 不把经营工作站扩展为地产投资、招商或物业资产管理系统；
- 不以 IFRS 16 计量页面作为新产品首页；
- 不在 MVP 接入真实 POS、ERP、WFM、客流硬件或支付系统；
- 不让模拟数据进入 Official/过账链路；
- 不让 Agent 自动改正式事实、IFRS 16 台账或外部业务系统；
- 不为追求审计级完备性延迟经营脉搏、门店 360、情景分析和 Agent 的用户验证。
- 不清理、下线、重命名或隐藏原有功能与页面；只有独立 UI 任务可以重排导航优先级或新增入口，并且不得改变整体 AppLayout、设计语言和页面排版体系。

## 7. Planner 放行规则

- 当前只允许一张执行票处于 `IN_PROGRESS`；
- 每票先验证用户任务，再验证数据正确性和底线控制，最后检查非阻断治理项；
- 非阻断治理缺口记录到本文件 Hardening Backlog，不得以 `CHANGES_REQUESTED` 阻塞产品票；
- 只有数据错误、跨法人风险、模拟/正式混淆、重复导入、来源丢失或 IFRS 16 隔离破坏，才可阻断当前主路径；
- MAX-001 接受后立即放行 MAX-002，之后依次沿 M1—M7 交付。
