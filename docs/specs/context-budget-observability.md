# 工单：上下文预算的可观测面（OBS1）

> 编制：2026-08-25 · 状态：`ready-for-agent`
> 来源：C1 spec 契约变更清单里已承诺但未交付的一项
> 相关：[母 spec C1](agent-runtime-overhaul-c1.md) D-C2 / User Story 2、6 · [AR3 整改 AF1](agent-runtime-c1-review-fixes.md)

## 为什么是这一单

C1 spec 的契约变更清单写着：

> | 新增可观测指标 | **token 用量与上下文预算占用** |

User Story 6 讲了它存在的理由：

> 我想有一个可观测的 token 用量指标，**以便「观察到真实溢出」这个条件真的可被观察**

**实测：这条没做。** 装配器今天只有事件面（`run_events` 的 `context_compacted`、消息行的 `measured_tokens`），`ops/prometheus/` 下没有任何 token 或预算占用指标。

这件事的形状值得说清楚：ADR-0022 当初把压缩推迟到「观察到真实溢出」，而 C1 立项的核心论证正是**「没有计数就没有可观测量，那个条件永远不会被满足」**。现在计数建好了、预算建好了、压缩建好了、AF1 四项缺陷也修好验过了——**可观测量仍然没有**。同一个死结换了个位置继续存在。

连带后果：装配器至今**没有在生产流量上跑过一次**。没有指标就不敢开，不开就永远拿不到真实数据。

Story 2（「上下文接近上限时收到提示」）同样是空的：唯一的事件 `context_compacted` 在**压缩发生之后**才发，撞墙前没有任何信号。

## 要做的

### 1. 指标本体

沿用既有形状：`agenttools.RuntimeMetrics` 的累积 + `Prometheus(now)` 文本渲染 + `GET /agent/metrics/prometheus` 暴露（权限门照旧）。新指标是并列的一组，不要另起一套暴露机制。

至少要能回答三个问题：

- 一次回合的上下文**占用了预算的多少**
- 其中**多少是实测、多少是估算**
- 压缩**发没发生**、发生时丢了多少

### 2. 核心验收：实测与估算必须分开，不得合并成一个数

`Prompt` 已经同时带 `Tokens` 与 `EstimatedTokens`。指标**必须把这两者分开暴露**。

理由是 AF1-a 的教训：那次就是「类型上是 token 数、语义上是猜测」的值混进了计算，而且单测因为输入语义与生产不一致而照不出来。一个把实测与估算加总成单一数字的仪表盘，会让人以为自己在看测量结果——**这比没有仪表盘更糟，因为它会被用来做决策**。

### 3. 标签纪律（这条是硬约束）

**禁止把 `legal_entity_id` / `user_id` / `session_id` 放进指标标签。** 两个理由，任一独立成立：

- 基数爆炸
- `agentcontext.ContextKey` 特意不实现 `String()`，就是为了防止租户与用户标识被 `%v` 撒进日志（见 `key.go` D-C11 注释）。指标标签是同一类出口，同一条纪律。

按 `model` 打标签是合理的（预算几何本来就是按模型配置的）。其余维度动手前说明理由。

### 4. Story 2：撞墙前的信号

占用率越过阈值时要有信号，且**必须发生在压缩之前**。阈值是配置还是常量、信号走事件还是指标还是两者，由你提案。

**不要做成把 `context_compacted` 改个名**——那个事件是事后记录，本条要的是事前预警，两者都要存在。

### 5. 建议的形状：计数与压缩解耦（先提案再做）

现在 `CONTEXT_ASSEMBLER_ENABLED` 是一个开关管两件事：算不算，和压不压。

**建议拆成两级**：可以「只计数、只上报，不压缩」。这样能先在生产流量上收集真实占用数据，再拿数据决定压缩阈值与何时启用压缩——而不是像现在这样，必须先承担行为变更才能拿到第一个数据点。

这正是 Story 6 那句「以便条件真的可被观察」的直接兑现。**但这改变了现有开关语义，动手前把方案抛回来**：两级怎么表达、默认值是什么、与 AF1-c 的启动期模型校验怎么配合（只计数模式是否仍要求预算几何——我的看法是要，因为占用率需要分母，但你可以反驳）。

### 6. 告警规则

`ops/prometheus/lease-agent.rules.yml` 补对应规则，形状照既有的 `LeaseAgentTool*` 两条。至少一条：占用率持续高位。阈值给出理由，不要拍脑袋。

## 验收

- 指标出现在 `GET /agent/metrics/prometheus`，实测与估算分开，权限门与既有指标一致
- **反向测试**：把实测与估算合并成一个数，测试必须变红
- **标签纪律测试**：断言渲染输出里不含法人 / 用户 / 会话标识——删掉纪律必须变红
- 撞墙前信号有测试证明它在压缩**之前**发生
- 若采纳两级开关：只计数模式下断言 prompt 内容**逐字节不变**（没有任何压缩发生）
- 全量 `go test ./...` + `go vet` 绿；`make test-integration` 实跑非 SKIP

## 不在本单范围

- **不要打开装配器开关**。本单交付可观测面；开不开、什么时候开，是拿到指标之后的运营决策，不由这一单决定。
- 不动 AF1 已验证的计数语义（基线 + 尾部估算）。本单是把已有的数暴露出来，不是重算。
