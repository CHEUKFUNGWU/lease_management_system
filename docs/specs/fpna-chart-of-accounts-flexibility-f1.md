## 先决：引擎已经支持，界面不支持

**引擎侧做到了科目级。** 行类型 `RowInput`（自填）/ `RowLink`（挂系统事实）/ `RowFormula`（推导）/ `RowSubtotal` / `RowCheck`，外加 `ActualSource` 让同一行在 Actual 冻结线左侧读事实、右侧跑驱动公式。可挂的来源有五族：`fact.*`（10 个已知，如 `fact.revenue` / `fact.labor_cost` / `fact.fixed_rent`）、`assumption.*`、`cf.*`、`contract.*`、`sched.*`。

蓝图 §四 写的「三类即插即用模式」（纯手工 / Excel 导入 / 系统挂载）是**模型级**描述，比引擎实际能力粗一档。

**界面侧没有对应物。** `FormulaEditor.tsx` 只把一条公式送后端校验，它构造临时模板时把所有行写成 `kind:"input"` 仅为让那条公式可解析，不是科目树编辑器。`page.tsx` 的 `addRow` 只接受 `"leaseRef" | "engine"` 两个固定分区。用户建不了自定义科目，也选不了某科目的取数来源。

R1 批次曾判「缺的是可视化编辑器，不是引擎」，看来只交付了公式校验那一半。

### 两个会咬人的结构约束

**一、16 个保留键是勾稽的读取点。** `finmodel/tieouts.go` 直接读 `s.at("total_assets", period)`、`s.at("cash", period)`；`fold.go` 的 `foldStockKeys` 白名单列出全部：`cash` / `ar` / `inventory` / `ppe` / `rou_asset` / `total_assets` / `ap` / `lease_liability` / `borrowings` / `total_liabilities` / `share_capital` / `retained_earnings` / `total_equity` / `nwc` / `borrowings_opening` / `ending_cash`。

删掉或改键其中任何一个，T1–T16 直接跑不了。所以「预置科目不可删」不是产品偏好，是机械后果。

**二、自定义科目默认按流量折叠。** `fold.go` 注释：「Custom templates default to flow semantics」。用户新建一个「预付账款」，年度视图会把 12 个月**加起来**，而不是取年末余额。这个错误安静发生，数字看着像模像样。

## Problem Statement

站在 FP&A、财务 BP 与跨行业客户的位置上，三件事今天做不到。

**第一，科目表是别人的，不是自己的。** 系统预置的科目树按零售连锁设计。一家 SaaS 公司要「订阅收入」「云服务成本」「研发期权薪酬」，一家出海电商要「跨境物流关税」，都加不进去。他们能做的只有把不适用的科目留在那里显示 0，然后在心里忽略——但报表交出去的时候那些行还在。

**第二，取数来源不可选。** 引擎支持某个科目从系统事实取数、另一个科目手工填，但用户无从表达这个选择。一家已经有完整总账的客户想让「营业收入」挂系统数、「明年的新店数量」自己填，只能改代码。

**第三，AI 生成科目表这件事完全没有。** 蓝图 §四.1 点名的 `fpna.coa.suggest_template`（输入行业类型，AI 生成专属科目树与驱动假设）全仓零实现。就算实现了，没有编辑器的话用户也改不了 AI 生成的结果——那是一次性生成后锁死。

三件加起来的效果是：这个三表引擎只服务一种客户，就是它预置科目表所描述的那种零售连锁。

## Solution

一个科目树编辑器，加一个 AI 生成工具，两者合起来交付。

**编辑器**让用户在预置科目树上做三件事：新增自定义科目（挂在某个小计之下）、为每个科目选择取数来源（自填 / 挂系统事实 / 公式推导）、把不适用的预置科目置为零。预置科目不可删、不可改键，因为勾稽读它们。

**AI 生成**（`fpna.coa.suggest_template`）接收行业类型，产出一份**科目树草稿**，落在模板的 draft 状态等人确认。它生成的是编辑器能编辑的东西，不是一个黑箱结果。

**两者缺一不可**：只做编辑器是全手工，跨行业客户要从零搭一棵树；只做 AI 生成是一次性产出后用户改不了。

## User Stories

### 自定义科目

1. 作为 SaaS 公司的 FP&A，我想新增「订阅收入」「云服务成本」这类科目，以便这份模型描述的是我的业务而不是零售连锁
2. 作为跨行业客户，我想把新增科目挂在某个既有小计之下，以便它自动进入合计并让报表继续配平
3. 作为 FP&A，我想在新增资产负债表科目时声明它是存量还是流量，以便年度视图取期末余额而不是把 12 个月加起来
4. 作为 FP&A，我想让不适用的预置科目显示为零而不是空白，以便读报表的人知道这是「确认为零」而不是「没算出来」
5. 作为审计人员，我想让「用户主张的零」与「取不到数」在数据和呈现上都能区分，以便不会把一个未知当成一个事实
6. 作为 FP&A，我想在新增科目前被提示「这个诉求也许该用维度表达」，以便不会为「华东的订阅收入」建第二个科目

### 逐科目取数来源

7. 作为已有完整总账的客户，我想指定某个科目从系统事实取数，以便不必手工录入已经在系统里的数
8. 作为 FP&A，我想指定某个科目由我自己填，以便计划性的输入不被系统数覆盖
9. 作为 FP&A，我想指定某个科目由公式推导，并看到公式引用的行是否存在，以便不会写出悬空引用
10. 作为 FP&A，我想在选择「挂系统事实」时看到可挂的来源清单，以便不必记住 `fact.revenue` 这类字符串
11. 作为 FP&A，我想让同一个科目在 Actual 冻结线左侧读事实、右侧跑公式，以便历史期是实际数、预测期是驱动结果
12. 作为 FP&A，我想在挂载的来源不可得时看到具名 Gap，以便知道是哪一项没接上，而不是看到一个 0

### 预置科目的边界

13. 作为使用者，我想让预置科目不可删除，以便我不会在不知情的情况下弄坏资产负债表勾稽
14. 作为使用者，我想在尝试删除预置科目时看到原因，以便知道这是结构约束不是权限问题
15. 作为使用者，我想让预置科目的键不可修改，以便勾稽仍然找得到它们

### 导出时的科目取舍

16. 作为 FP&A，我想在导出报表时勾掉不需要的科目，以便交出去的报表只含相关行
17. 作为审计人员，我想让隐藏行之后的报表**仍然配平**，以便小计等于它可见子项之和这条不被破坏
18. 作为 FP&A，我想让隐藏一个非零科目时它被并入「其他」而不是凭空消失，以便报表不会因为隐藏而不平

### AI 生成科目树

19. 作为跨行业客户，我想输入行业类型让 AI 生成一份科目树草稿，以便不必从零搭
20. 作为 FP&A，我想让 AI 生成的结果落在 draft 状态等我确认，以便它不会直接成为正式模板
21. 作为 FP&A，我想让 AI 生成的科目树是编辑器能编辑的，以便我可以在它基础上改而不是全盘接受或拒绝
22. 作为 FP&A，我想让 AI 生成时保留全部 16 个保留键，以便生成的模板一定能跑勾稽
23. 作为 FP&A，我想在 AI 重新生成时不丢失我已经做过的改动，以便重新生成不是覆盖

## Implementation Decisions

### D-F1：预置科目不可删、不可改键，原因写给用户看

16 个保留键是 `finmodel/tieouts.go` 的读取点。删除或改键让 T1–T16 无法运行，而勾稽是这个引擎存在的理由。

**拒绝时要说机械原因，不要说「无权限」**：「`total_assets` 是资产负债表勾稽的读取点，删除后 T1–T16 无法运行」。说成权限问题会让用户去找管理员要权限，而那条路走不通。

### D-F2：用户主张的零 ≠ 缺失

这是本批次最容易做错的一条，因为它和仓库既有的「不用 0 填补缺失」表面冲突，实际不冲突。

| | 含义 | provenance | 渲染 |
|---|---|---|---|
| **用户主张的零** | 「我的业务没有这一项」 | `HumanInput`（含确认人与时间） | `0`，可选标注「已确认为零」 |
| **缺失** | 「取不到数」 | 具名 Gap | 「—」加原因，**不是 0** |

两者在数据层必须是不同的值，不能都存成 `0`。一个未知被渲染成零，就是编造数据点；一个确认为零被渲染成「—」，则是把已知说成未知。

既有的 `Cell Provenance` 已经区分 `Certified` / `SystemFact` / `HumanInput` / `Exploratory`，用户主张的零走 `HumanInput` 这条，不新建概念。

### D-F3：自定义科目必须挂在某个小计之下

模板结构里只有 `RowSubtotal` 可以声明 `Children`（`template.go:283`）。一个不挂在任何小计下的自定义科目不会进入任何合计，于是它显示了一个数但那个数不影响任何结论——比不显示更糟。

编辑器新增科目时**必须选父小计**，没有「先建了再说」。

### D-F4：自定义科目必须声明存量或流量

`fold.go` 的默认是流量（跨期求和）。一个自建的资产负债表科目若不声明，年度视图会把 12 个月加起来，得出一个看起来合理的错数。

新增科目时**存量/流量是必填**，不给默认值。给默认值就等于替用户选了一个大概率错的答案。

### D-F5：导出隐藏只能安全地隐藏

用户要「勾掉不需要的科目」，但**小计必须等于它可见子项之和**，否则报表不配平，这是会计意义上的错误而不是显示偏好。

因此分两种：

- **零值行**：直接隐藏。行不显示，小计不变（因为它贡献 0）
- **非零行**：不能凭空隐藏。并入同级「其他」行，或拒绝隐藏并说明原因

**默认只允许隐藏零值行。** 隐藏非零行要走「并入其他」这条明确的路径，不给一个会让报表不平的开关。

### D-F6：先问维度，再建科目

外部实践一致建议用维度而非增科目表达变体（[Cube](https://www.cubesoftware.com/blog/chart-of-accounts)、[Datarails](https://www.datarails.com/chart-of-accounts/)：「instead of multiplying accounts for every variation, use dimensions such as department, location, or product line」）。

本系统已有门店 / 区域 / 品牌维度。新增科目时若名称含已有维度值（「华东」「某某品牌」），提示用维度表达。**只提示不阻止**——判断是用户的，我们只负责让他知道有另一条路。

### D-F7：取数来源选择器列真实来源，不让用户记字符串

五族来源：`fact.*`（经营事实）、`assumption.*`（假设）、`cf.*`（现金流）、`contract.*`（合同）、`sched.*`（付款计划）。选择器按族分组，显示中文名与口径说明。

**中文名的唯一真相源是 `retailkpi`**，不得在编辑器里再建第二张 labels map。

来源不可得时返回具名 Gap，不返回 0（D-F2）。

### D-F8：编辑器不复刻后端的 DSL 解析器

公式校验一律走 `POST /api/v1/financial-model/templates/validate`，复用 `template.Compile` 同一条路径。**一次本地校验也不做**，包括括号配对这类「显然安全」的检查。开了本地校验的口子它会长大，然后与后端分叉。

这条是既有约束，此处重述因为编辑器是最容易违反它的地方。

### D-F9：AI 生成产出草稿，且必须含全部保留键

`fpna.coa.suggest_template` 是 `LevelDraft` 写类工具，落模板的 draft 状态，`source=ai_suggestion`，人确认后才成为可用模板。AI 无 approved 路径。

**生成结果必须包含全部 16 个保留键**，否则生成的模板跑不了勾稽。这一条在工具内校验，缺键即拒绝产出而不是产出一个残缺模板。

命名空间是 `fpna.*`（读写的是模板与假设，属 FP&A 域）。

### D-F10：重新生成不覆盖用户改动

AI 重新生成时，用户已改过的行保留，新增的行追加，冲突的行标出让用户选。

模板已有 review / approve 路由（`/financial-model/templates/:id/review`、`/approve`、`/copy`），版本机制存在，不需要新建。重新生成走「基于当前版本产生一个新 draft 版本」，不是原地覆盖。

### 契约变更清单

| 类型 | 变更 |
|---|---|
| 新增 Tool | `fpna.coa.suggest_template`（LevelDraft，写模板 draft） |
| 新增前端 | 科目树编辑器（`/financial-model` 内），含来源选择器与导出勾选 |
| 后端 | 复用既有模板 CRUD 与 validate 路由；可能需补「按父小计新增行」的校验 |
| 表结构 | 预期不改。`Cell Provenance` 与模板 JSON 已能承载 |
| 中文名 | 全部来自 `retailkpi`，不新建 labels map |

## Further Notes

**为什么外部资料帮不上最关键的那条。** 检索 FP&A 平台的科目表实践，通用原则（对齐报表、统一命名、用维度而非增科目、留编号空间）都能找到，但「预置系统科目不可编辑、用户只能扩展」这个模式没有公开资料覆盖——搜索结果明确指出这一点。所以 D-F1 的依据是本仓自己的代码事实（`tieouts.go` 按键读取），不是行业惯例。这也意味着这条约束**必须在界面上解释给用户**，因为他不会从别处的经验里预期到它。

**关于 `unvalidated`。** 本批次同样没有真实客户验证。跨行业科目树让引擎能服务更多行业类型，这不改变结论仍基于固定 seed / 构造数据这一事实。
