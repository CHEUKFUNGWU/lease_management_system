## 1. 立即处理：跨法人隔离可被绕过

**这是本次评审唯一需要在排期之外单独对待的一条。** 它触及五条底线的第 1 条。

### 1.1 完整调用链（✅ 已核实，逐环节复现）

| 环节 | 证据 |
|---|---|
| `users.legal_entity_id` 可为空 | `db/init/01_init.sql`：`legal_entity_id UUID`，无 `NOT NULL` |
| 建用户时不强制填 | `handlers/auth.go:108` `LegalEntityID *string`，**无 `binding:"required"`** |
| NULL 被转成空串写进 JWT | `handlers/auth.go` `buildTokens`：`if user.LegalEntityID != nil { legalEntityID = *user.LegalEntityID }` —— NULL 时保持 `""` |
| Handler 无守卫 | `handlers/fpna_governance.go`：26 处 `GetTenantID` 调用，**0 处空值检查** |
| 查询把空串当"不过滤" | 仓储层 **38 处** `($N='' OR legal_entity_id::text=$N)`，谓词短路为真 |
| 本该拦住的中间件是死代码 | `middleware/tenant.go:45` `RequireTenant()` —— **全仓 0 个调用点** |

结果：一个 `legal_entity_id IS NULL` 的普通用户调用 `GET /api/v1/performance/decision-memos`，谓词恒真，返回**所有法人**的决策备忘录。计划版本、映射、数据质量记录、报表工件、Agent 信号是同一形状。

### 1.2 修正报告的一处说法

报告称 `appendEquipmentScopePredicate` 是"第二个洞"。**这条只对了一半**：该函数确实从不发出法人子句，但它在 `access_scope_sql.go:81` 有 `if scope.LegalEntityID == "" { return query + " AND false" }` —— **空法人时是失败关闭的**，不会泄漏。真正的问题是它在法人非空时只加 plant/line/equipment 过滤，是否安全取决于调用方是否另外加了法人条件。**风险等级低于报告的描述，但仍需逐个调用方确认。**

### 1.3 严重度的诚实表述

**这是「潜在且触手可及」，不是「正在泄漏」。**

正确的семь缝其实已经存在：`access.Scope` 有显式的 `Global bool`（`middleware/rbac.go:85`，由 `*:*` 权限决定），`appendScopePredicate` 系列会正确失败关闭。问题是**38 条查询完全绕过了这个 seam**，用空串同时表达了两件事：「管理员，看全部」和「这个用户配错了」。

当前种子用户都带法人 ID，管理员本就该是 NULL，所以**今天观察到的行为可能与预期一致**。但：**一次不带 `legal_entity_id` 的建用户调用，就会静默产生一个跨法人读取者**，且没有守卫、没有测试、没有编译期保护。

### 1.4 建议

分两步，第一步今天就能做：

1. **止血（小改动）**：给建用户接口加 `binding:"required"`；在 38 处查询的入口加一个共用断言——空法人且非 Global 即拒绝；给 `RequireTenant()` 找回调用点或删掉它。
2. **根治（评审报告候选 04）**：引入不能持有空串的值类型，让忘记过滤变成**编译错误**而不是静默泄漏。

```go
type LegalEntityID struct{ v string }
func NewLegalEntityID(s string) (LegalEntityID, error) // 拒绝 ""
```

值类型穿透仓储接口后，`($N='' OR …)` 这个写法本身变得写不出来。

**需要一份新 ADR** 记录「值类型即执行边界」。这不与 ADR-0001 冲突——ADR-0001 定义策略**是什么**，这条定义策略**在哪里执行**。

### 2.2 候选 03 的核实结果（✅ 已复现两条关键证据）

**捏造分母**：`services/operating/fourwall.go:79/91/92` 使用 `max(f.Revenue, 1)`。零营收门店会被凭空给一个分母，算出一个看似正常的比率——**这正是零售线建来杜绝的「不用 0 填补缺失」**。而 `retailkpi` 对零分母返回 `null`。同一个指标名，两个引擎，两种答案。

**Fact Coverage 谓词五份拷贝、一份写错**：`retailstore360/store360.go:242` 和 `:252` 用 `!=`，而 `retailpulse/retail_pulse.go:606` 与 `retailkpi/retail_kpi.go:179` 用 `ExpectedStoreDays > 0 && Observed < Expected`。**超额覆盖（observed > expected）在门店 360 会触发降级，在其他地方不会**，Peer Benchmark 被整片抹掉。

**注意增量叠加底线**：`/performance` 必须保留路由并继续可用。这是**换实现**不是删功能，但它是唯一触及转型前存量界面的候选，需要兼容性回归证据。

## 3. 对 DESIGN.md 的直接打击（✅ 已核实）

评审指出 DESIGN.md「没有执行机制」，这条完全成立，而且**我在 DESIGN.md §14 里低估了债务规模**：

| 项 | DESIGN.md 原记 | 实际 |
|---|---|---|
| 内联 `style={{}}` | 30 处（AppLayout） | **906 处**（全 `web/app`） |
| `fontWeight` 700/800 | 「页面标题、Logo」 | **13 处** |
| ESLint 配置 | 未提 | **不存在**——`package.json` 有 `"lint": "next lint"` 但无配置文件，CI 不跑 lint |
| §1 要求的 token 对齐测试 | 「阶段一完成」 | **从未写过** |

我写的是 AppLayout 的 30 处，那句话本身没错，但**放在「已知偏离」表里会让人以为全仓就这个量级**。已在 DESIGN.md 中更正。

**结论：DESIGN.md 目前是一份没有牙齿的文档。** 阶段一必须包含执行机制，否则 §13 止血条款只是自觉遵守——而 906 这个数字说明自觉遵守从来没有奏效过。

最小执行机制（成本低、当天可落）：

```
1. 加 ESLint 配置 + react/jsx-no-inline-styles（新增文件 error，存量 warn）
2. 加一条 CI 检查：新增 !important / fontWeight>600 / 硬编码 CJK 即失败
3. 写 tokens.ts ↔ globals.css 的对齐测试（DESIGN.md §1 已要求）
```

## 4. 修订后的整体排期

原 UIUX 方案是四阶段六周。纳入架构评审后：

| 阶段 | 内容 | 工期 | 关口 |
|---|---|---|---|
| **0a 止血** | 法人隔离止血（§1.4 第 1 步）+ DESIGN.md 执行机制（§3） | 2–3 天 | 不阻塞任何后续 |
| **0b** | 主线错配速修（UIUX §7：命令面板、品牌文案、AI Chat 开场白） | 2–3 天 | 与 0a 可并行 |
| **1** | 候选 04 法人隔离值类型 + 新 ADR | 1 周 | **建议先于一切重构**：它把底线 1 从约定变成编译期性质 |
| **2** | 候选 01 错误契约 | 1 周 | 前端 403/scope_denied 处理依赖它 |
| **3** | 候选 02 + 03（Source Envelope + 单一 KPI 引擎） | 2 周 | 两者是同一次重构的两面；03 需 `/performance` 兼容证据 |
| **4** | 样式系统收敛（UIUX 阶段一） | 1 周 | 依赖 0a 的执行机制 |
| **5** | 候选 05 fetch 模块 + UIUX 阶段二、三（组件层） | 3 周 | |
| **6** | 三栏 Agent 首页 + 双语回归 + 暗色模式 | 3 周 | |

**顺序上的一条硬约束**：候选 04 应先于候选 02/03。后两者要动仓储读取路径，在法人隔离还是「38 处自觉遵守」的状态下重构，等于在没有安全网的情况下改承重墙。

## 5. 需要产品决策的两件事

这两条我不替你定：

1. **i18n 的去留**（候选 10）：6879 行字典里 zh-HK 和 en 完全不可达，278 个 key（834 条译文）零引用。**要么补完零售页把语言开关打开，要么砍到单语言回收约 4500 行。** 代码怎么走取决于这个答案。
2. **金额是否迁出 `float64`**：对已过账分录和锁定期余额，这需要一份 ADR 明确表态，而不是默认继续。
